# 백엔드 판단 기준

- MUST NOT: 조건별 하드코딩 분기로 동적 필터를 우회하지 않는다. 이 프로젝트의 핵심 난제는 런타임에 조합되는 필터 조건을 쿼리로 변환하는 것이다. 분기로 우회하면 당장은 동작하지만, 지표가 추가될 때마다 분기가 늘어나 확장 구조가 무너진다. 조건을 데이터로 다루고 쿼리를 조립하는 방향을 유지한다.

- MUST: 프리셋 전략과 커스텀 필터는 하나의 조건 모델을 공유한다. 프리셋은 가중치 점수로 순위를 매기고 커스텀 필터는 충족/불충족으로 걸러내지만, 판정 방식만 다를 뿐이다. 두 체계를 따로 만들면 지표를 하나 추가할 때 양쪽을 모두 고쳐야 하고, 시간이 지날수록 두 구현이 어긋난다.

- MUST NOT: 조건 목록을 트리 구조로 확장할 수 없는 형태로 못박지 않는다. 향후 조건 그룹 간 OR 결합이 도입될 때 지금의 구조가 그 최상위 계층으로 흡수될 수 있어야 한다. 지금 트리를 구현하지는 않는다.

- MUST: 지표 저장은 스키마 변경 없이 새 지표를 추가할 수 있는 구조로 만든다. 지표는 계속 추가된다.

- MUST NOT: 기능마다 로깅 코드를 손으로 넣는 방식으로 인터랙션 기록을 구현하지 않는다. 그 방식은 반드시 누락이 생긴다. 기록 대상 행위를 코드 상에서 선언적으로 표시하고, 수집은 공통 계층이 담당하게 한다.

- MUST NOT: 관리자 기능을 별도 애플리케이션으로 분리하지 않는다. 인증·배포를 이중으로 관리하는 비용이 이 프로젝트 규모에 맞지 않는다. 같은 애플리케이션 안에서 권한으로 분리한다.

- MUST: 배치 실패는 나중에 실패 단위를 식별할 수 있는 형태로 남긴다. 관리자가 실패한 부분만 골라 재실행하는 기능이 여기에 의존한다.

- MUST: enum에 값을 더하거나 `@Size`·공개 상수를 바꾸면 `src/test/resources/contract/wire-contract.json`에도 함께 적는다(ADR-0020). 프론트가 그 값을 손으로 거울 삼아 들고 있고, 거울은 어긋나도 화면 어디에서도 티가 나지 않는다 — 실제로 `IndicatorCategory`에 값이 하나 늘면 그 분류의 지표 전체가 조건 빌더에서 **선택 불가능해진다.** `WireContractTest`가 잡아 주지만, 잡히는 시점이 커밋 뒤가 아니라 지금이어야 한다.

- MUST: 컨트롤러는 도메인별 `…/web`에 두고, 최상위 `web`은 HTTP 인프라 전용으로 유지한다. `pipeline` 하위 패키지 이름은 `.claude/rules/data-pipeline.md`의 glob에 **의도적으로 맞춘 것**이므로 바꾸면 그 규칙이 로드되지 않는다 — 로드되지 않았다는 사실은 드러나지 않는다.

## 실측된 함정

위가 설계 원칙이라면 아래는 **실제로 겪은 것**이다(2026-08, `docs/progress.md`에서 옮겨 왔다 — 주입 상한을 넘겨 조건부 로드로 돌렸다).

- **Jackson은 3.x이고 패키지가 `tools.jackson.databind`다.** Boot 3 예제를 복사하면 컴파일이 안 된다.
- **CSRF 토큰의 지연 로딩을 껐다**(`setCsrfRequestAttributeName(null)`). 켜두면 SPA의 첫 POST가 403이 되고 **인증 버그처럼 보인다.**
- **보안 매처의 마지막이 `permitAll`이다**(ADR-0018). 정적 셸을 익명에게 열어야 로그인 화면이 뜬다. **새 보호 대상은 반드시 그 앞에 명시해야 한다** — 뒤에 두면 조용히 열린다.
- **SPA 폴백은 `api/`·`actuator/`·`/assets/**`에 적용하지 않는다.** 적용하면 없는 경로가 404 대신 HTML 200을 주고 프론트가 JSON 파싱에서 죽는다.

**`application.yaml` 쪽 함정은 `.claude/rules/config.md`에 있다** — 배치·스케줄러 기본 꺼짐이 거기로 갔다. 트리거가 "Java를 고친다"가 아니라 "설정을 고친다"이기 때문이다.
