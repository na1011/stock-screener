# 브라우저로 이 앱을 몰 때

**이 문서는 따라야 할 순서가 아니라 알아야 할 사실이다.** 무엇을 볼지는 그때의 변경이
정하고, **무엇이 성립해야 하는지는 `docs/phase-criteria.md`가 답한다.**
여기에는 브라우저를 통해야만 드러나는 함정만 적는다.

## 지금 화면이 어느 빌드인가 — 틀리면 나머지 관찰이 전부 무효다

**`:8080`을 배포본이 잡고 있을 수 있다.** 그것은 `./gradlew build`로 바뀌지 않는다.
**방금 고친 코드를 그 화면으로 통과시키면 옛 코드를 통과시킨 것이고, 화면에는 아무
단서가 없다.** 먼저 `ops/status.sh`로 무엇이 도는지 확인한다.

코드를 고쳤으면 내리고 자기 빌드를 띄워 자기 것을 본다.

```bash
ops/stop.sh --app
./gradlew bootRun
```

**끝나면 되돌린다 — 아무것도 대신 띄워 주지 않는다**(ADR-0043). 안 되돌리면 사이트가
내려간 채로 세션이 끝나고, **평일 13시 30분 배치도 함께 빠진다**(배치는 앱 프로세스 안에 있다).
변경을 살릴 것이면 `ops/deploy.sh`, 아니면 `ops/start.sh --app`이다.

## 역할

- **사용자 몫은 Google 로그인 하나뿐이다.** 남의 계정 자격증명은 에이전트가 가질 수 없다.
  로그인된 뒤 읽고 조작하는 것은 전부 에이전트가 한다 — 되묻고 멈추지 않는다.
  - **MUST: 배포·재기동을 다 끝낸 뒤에 로그인을 부탁한다.** 세션이 앱 프로세스 안에 있어
    **재기동이 로그인을 무효로 만든다.** 그러면 화면은 캐시된 셸을 그리고 API만 401이 되어
    「로그인이 만료되었습니다」로 끊긴다 — 사용자를 두 번 로그인시킨 전례가 있다.
    화면을 보다가 고칠 것이 생기면 **고치고 배포한 뒤 한 번에 다시 부탁한다.**
- **브라우저 도구가 안 보이면 없는 게 아니라 그 세션에서 MCP 인증이 안 된 것이다**
  (`Claude_Code_Remote`). 비대화형 세션이 그렇다. 사용자에게 연결을 요청한다.

## 되돌릴 수 없는 조작

**허용목록 삭제 하나다.** 지우면 그 계정의 로그인 이력이 `app_user`에 남은 채 상태가
섞인다. 허용목록 밖 계정이 막히는 화면을 보려면 **등록된 계정을 지워서 만들지 말고 새
계정을 쓴다.**

나머지 조작은 되돌릴 수 있다. 네이티브 `confirm`·`alert`도 없어 다이얼로그로 세션이
굳지 않는다 — 삭제 버튼 앞에서 멈춰 설 이유가 없다.

## 쿼터를 태우는 버튼

**`/admin`의 일일 갱신 기동은 종목당 외부 API 1콜을 태운다 — 350종목이면 350콜**이고
data.go.kr 일일 한도 9,000의 4%다. 사용자가 이미 허락한 조작이라 확인을 다시 받지 않되,
**같은 날 여러 번 반복하지 않는다** — 멱등해서 결과는 같고 쿼터만 준다.

**이 기동이 `WatchlistAlertRunner`를 실데이터로 태우는 유일한 경로다**(`DailyUpdateJob`이
시세→지표→워치리스트 순으로 돈다). 판정이 돌았다는 증거는 이 한 줄이다:

```
워치리스트 판정을 마쳤다. asOf=…, 판정 N건, 새로 충족 N건, 통지 N명, 실패 화면 N개
```

`새로 충족 0건`은 **정상일 수 있다** — 엣지 트리거라 조건이 참으로 유지되는 동안은
침묵한다(ADR-0026). `알림 채널이 하나도 구성되지 않아…`도 정상이다(ADR-0025).

**초기 적재는 화면에 버튼이 없다**(DART 9,800콜을 한 번에 태운다, ADR-0029). 필요하면
`batch-load` skill을 쓴다.

## 브라우저 도구가 거짓 음성을 내는 자리

- **`javascript_tool`에서 던진 예외는 페이지 전역 핸들러를 타지 않는다.** 거기서 바로
  `setTimeout(() => { throw … })`을 하면 아무 일도 일어나지 않는다(실측). `<script>` 태그로
  주입해야 한다. 모르면 "전역 핸들러가 안 붙었다"로 오판한다.
- **`read_network_requests`는 도메인에 따라 권한 거부가 난다**(`sentry.io`에서 실측).
  전송 여부는 `performance.getEntriesByType('resource')`에서 센다.
- **모듈로 임포트한 SDK는 전역에 없다.** `window.Sentry`는 없고 캐리어에서 꺼낸다:

  ```js
  const carrier = window.__SENTRY__[window.__SENTRY__.version]
  carrier.defaultCurrentScope.getClient().getOptions().dsn  // 비면 initMonitoring이 건너뛴 것
  ```

## 서버가 거절한 뒤에 화면을 다시 읽는다

**서버가 거절하는가는 전부 테스트에 있다**(`SecurityConfigTest`·`Admin*ApiTest`). 브라우저로만
갈리는 것은 **거절을 받은 뒤 화면이 무엇을 말하고 있는가**다 — 낙관적 갱신을 되돌리지
않으면 실패한 조작이 성공한 것처럼 남고, 그 화면을 본 사람은 반대 방향으로 움직인다.
