# 관통 검증 (크롬 원격 제어)

**이 문서는 따라야 할 순서가 아니라 알아야 할 사실이다.** 무엇을 언제 볼지는 그때의 변경이
정한다 — 여기서는 **브라우저를 통해야만 드러나는 것**과 그 함정만 적는다.

## 전제

- **`./gradlew bootRun`은 에이전트가 띄운다.** 사용자 몫이 아니다. `localhost:8080`이 가장
  단순하다 — 도메인(`screener.na1011.net`)은 cloudflared까지 함께 살아 있어야 한다.
- **브라우저 도구가 안 보이면 없는 게 아니라 그 세션에서 MCP 인증이 안 된 것이다**
  (`Claude_Code_Remote`). 비대화형 세션이 그렇다. 사용자에게 연결을 요청한다.
- **사용자 몫은 Google 로그인 하나뿐이다.** 남의 계정 자격증명은 에이전트가 가질 수 없다.
  로그인된 뒤 화면을 읽고 조작하는 것은 전부 에이전트가 한다.

## 자동 테스트가 이미 덮은 것 — 여기서 다시 보지 않는다

`./gradlew build`가 도는 것을 브라우저로 또 확인하면 시간만 쓴다. **서버가 거절하는가**는
전부 테스트에 있다(`SecurityConfigTest`·`Admin*ApiTest`) — 비관리자의 403, 익명의 401,
마지막 관리자 잠금 거절, 중복 기동 409.

**브라우저로만 드러나는 것은 다르다:** 화면이 서버가 구분해 보낸 것을 접지 않는가, 항목이
**보이지 않는가**, 그리고 실데이터에서 값이 실제로 나오는가.

## Google 계정 하나로 두 가지를 본다 — 순서가 있다

허용목록 밖 차단과 비관리자 시야는 **같은 계정으로 연달아** 볼 수 있다. 순서를 뒤집으면
첫 번째를 못 본다.

1. 그 계정이 **허용목록에 없는 상태로** 로그인 → 막히되 `로그인할 수 없습니다. 접근 권한이
   있는 계정인지 확인해 주세요.`만 뜨고 **사유는 나오지 않아야** 한다(ADR-0004 — 허용목록의
   존재 자체가 운영 정보다).
2. 그 뒤 `/admin/accounts`에서 **비관리자로 추가** → 같은 계정으로 다시 로그인 → 들어가지되
   **사용자 메뉴에 `관리자` 항목이 아예 없어야** 한다. `/admin`을 주소창에 직접 쳐도 조용히
   스크리너로 돌아온다 — **403 화면이 뜨면 실패다**, 그 화면 자체가 "여기 무언가 있다"를 알린다.

먼저 추가해 버리면 1번을 보려고 다시 지워야 하고, 지우는 순간 그 계정의 로그인 이력이
`app_user`에 남은 상태와 섞인다.

## 관리자 화면에서 브라우저가 아니면 못 보는 것

- **자기 관리자 권한 회수 거부 뒤 스위치가 원래대로 돌아오는가.** 서버가 409를 주는 것은
  테스트가 확인한다. 화면이 그 실패를 받고도 스위치를 켠 채 두면 **관리자는 권한이 회수된
  줄 알고 나가고, 다음 로그인에서 아무도 못 들어온다.**
- **부분 실패가 실패와 다른 색인가.** 848종목 성공에 2종목 실패한 배치가 빨간불이면 매일
  빨간불이고, 곧 아무도 그 불을 보지 않는다.
- **재실행이 `#N 재실행`으로 원래 실행과 연결되어 보이는가.** 연결이 안 보이면 "재시도했는데
  또 실패"를 읽을 수 없다.
- **성공한 실패가 요약의 "미해결 실패"에서 빠지는가.**

## 쿼터를 태우는 조작

**`/admin`의 일일 갱신 기동은 외부 API를 종목당 1콜 태운다 — 350종목이면 350콜**이고
data.go.kr 일일 한도 9,000의 4%다. 사용자가 이미 허락한 조작이므로 확인을 다시 받지 않는다.
다만 **같은 날 여러 번 반복하지 않는다** — 멱등해서 결과는 같고 쿼터만 준다.

**이 기동이 `WatchlistAlertRunner`를 실데이터로 태우는 유일한 경로다.** `DailyUpdateJob`이
시세→지표→워치리스트 판정 순으로 돌기 때문이다. `삼성전자`가 `저평가 가치주`를 알림 조건으로
담겨 있다. **판정이 실제로 돌았다는 증거는 이 한 줄이다**(`WatchlistAlertRunner`):

```
워치리스트 판정을 마쳤다. asOf=…, 판정 N건, 새로 충족 N건, 통지 N명, 실패 화면 N개
```

`판정 0건`이면 워치리스트 행이 없거나 알림 조건이 안 걸린 것이고, `새로 충족 0건`은
**정상일 수 있다** — 엣지 트리거라 조건이 참으로 유지되는 동안은 침묵한다(ADR-0026).
`알림 채널이 하나도 구성되지 않아…`도 정상이다(ADR-0025) — 자격증명이 없어 로그로 떨어진다.

**초기 적재는 화면에 버튼이 없다.** DART 9,800콜을 한 번에 태우기 때문이다(ADR-0029).
필요하면 `batch-load` skill의 `--job=initial-load`를 쓴다.

## 프론트 Sentry — 번들에 문자열이 있는 것과 도는 것은 다르다

`window.Sentry`는 없다(모듈 임포트라 전역에 안 붙는다). 클라이언트는 캐리어에서 꺼낸다:

```js
const carrier = window.__SENTRY__[window.__SENTRY__.version]
const client = carrier.defaultCurrentScope.getClient()
client.getOptions().dsn          // 비어 있으면 initMonitoring이 건너뛴 것이다
```

전송 여부는 `performance.getEntriesByType('resource')`에서 `sentry.io`를 세면 된다 —
**`read_network_requests`는 이 도메인에서 권한 거부가 난다.** 실측 확인(2026-08-09):
명시 호출과 잡히지 않은 오류 양쪽 다 `envelope/`로 200이 나갔다.

**MUST: 잡히지 않은 오류는 `<script>` 태그로 넣어 던진다.** `javascript_tool`에서 바로
`setTimeout(() => { throw … })`을 하면 **전송이 일어나지 않는다**(실측). 그것을 보고
"전역 핸들러가 안 붙었다"로 오판하기 쉽다.

**소스맵이 올라간 뒤에는 그때 확인할 것이 하나 더 있다** — 이슈의 스택트레이스가
`index-a3f9.js:1:28471`이 아니라 `.vue`/`.ts` 줄을 가리키는가. 그것은 Sentry 대시보드를
봐야 갈리고, 지금은 슬러그가 없어 확인 대상이 아니다.
