# 주봉 일목 지표를 고칠 때

> **2026-08-14에 점수화 계층이 철회됐다**(ADR-0046 §2026-08-14 개정). Tier·9등급·값폭관측론
> leaf와 그 근거 코드(`IchimokuScoring`·`ValueWidth`)가 사라지고 **관측 지표 18개**만 남았다.
> 아래는 그 상태 기준으로 고쳐 적었다 — 점수 매트릭스를 다시 만들려는 것이 아니라면 원본
> Pine의 `score_*` 절은 읽을 필요가 없다.

**무엇을 하기로 했고 무엇을 원본과 다르게 옮기는가는 [ADR-0046](../../../docs/adr/ADR-0046-ichimoku-sp-screener-port.md)이,
완료 판정은 `docs/phase-criteria.md` §P12가, 원본은
[`docs/external/ichimoku_sp_screener_patched.txt`](../../../docs/external/ichimoku_sp_screener_patched.txt)가 정본이다.**
여기에는 **그 결정을 실행할 때만 걸리는 것**을 둔다.

## 착수 순서와 그 이유

`P9(수정주가+거래량) → 시장 지수 → 순수 계산 코어 → 계산기 18개 → 프리셋 → 백필`.

- **P9가 먼저인 이유는 정확도가 아니라 백필 횟수다.** P9는 `adj_close` 전 구간 재계산 + 지표 무효화를
  부르므로, 뒤에 두면 전량 백필을 두 번 돈다.
- **골든 픽스처는 순수 계산 코어를 짜기 *전에* 받는다.** 나중에 받으면 검증 기준 없이 800줄을 짠 뒤
  대조하게 되고, 어긋났을 때 어디가 틀렸는지 좁힐 수 없다.

## 시장 지수 — 구조적 단일 실패점이다

- 원자료는 `docs/api-spec/data-go-kr-market-index.md`가 정본이다. `idxNm`은 **`코스피`** 정확 일치이고
  **숫자 앞 공백**(`코스피 200`)과 `endBasDt`가 **미만**인 것이 거기 적혀 있다.
- **`readRawData`는 종목마다 불린다. 지수를 거기서 읽으면 356번 같은 쿼리를 던진다** — `asOf` 단위로
  한 번 읽어 넘긴다.
- **지수 한 줄이 없으면 전 종목이 함께 판정불가가 된다.** 실패 격리의 단위가 종목이라는 원칙이
  원리적으로 성립하지 않는 첫 입력이므로, **수집 실패와 0건이 반드시 알림으로 나가야 한다.**
  ADR-0042의 15일 창을 지수에도 건다(기간조회 1콜이라 창을 넓혀도 콜이 안 는다).
- **공개 지연과 휴장일 표현이 지수로는 미검증이다**(같은 문서 §미검증). 확정 휴장일로 한 번 물어 표에 올린다.
- `CollectionPhase`에 값을 더하는 것은 1줄이다 — `wire-contract.json`에 없고 `batch_execution_phase.phase`에
  CHECK도 없다. `ADJUSTMENT`는 P9용으로 이미 있다.

## 계산기 18개를 한 번의 분석으로 나누는 법

**`dependsOn`으로는 안 된다.** 그 채널이 나르는 것은 부모가 **자기 코드로 낸 스칼라 시계열 하나**다
(`IndicatorRunner`의 `computed.put(code, series)` → `dependencies.put(code, …)`). `ICHI_MOD_A`를 의존으로
받으면 Tier 값만 오고 거기서 수식자를 복원할 방법이 없다. `code()`도 단수이고 레지스트리가 중복 코드를
기동 시 던진다.

→ **`IndicatorContext`를 입력으로 받는 메모이저 빈을 둔다.** 러너가 한 종목의 계산기들을 연속으로
부르므로 **크기 1의 캐시로 충분하다.** 저장소를 조회하지 않으므로 컨텍스트 계약은 깨지지 않는다 —
깨지는 것은 "계산기끼리 중간 구조체를 공유하지 않는다"는 암묵 규약이고, 그것이 ADR을 남길 자리다.

**여기서 새면 값이 맞아도 백필이 실용 시간 안에 안 끝난다.** 30번 재계산은 시간 예산이 허락하지 않는다.

## 읽기 창 1,100 — 무엇이 조용히 바뀌는가

`IndicatorRunner.readRawData()`가 **전역 최대 하나**로 읽는다. 751 → 1,100.

- **읽기 창과 워밍업은 다르다.** 한 실행이 내는 포인트 수는 `읽기 창 − 그 지표의 워밍업 + 1`이다.
  창을 워밍업과 같게 잡으면 `SHARES_GROWTH_3Y`처럼 **1일자만 나온다.**
- **창은 종목을 배제하지 않는다.** `readPriceBars`가 `LIMIT`이라 짧은 종목은 있는 만큼 받는다.
  창 1,000~1,200에서 **207주 충족 종목이 320으로 동일**하다(실측). 창이 정하는 것은 ATR(26) 수렴뿐 —
  창 안 중앙 주봉 수가 1,000→215, 1,100→**236**, 1,200→258주이고, 잔차는 `(25/26)^(주봉수−129)`다.
- **`SHARES_GROWTH_3Y`의 산출 일자가 1 → 350으로 바뀐다.** 값은 같지만 쓰기 부피와 백필 특성이 달라진다.
  `SharesGrowth3yCalculator` javadoc과 `batch-load` skill의 **"실행당 1일치" 서술이 낡으므로 함께 고친다.**
  `TradingDays750Calculator`는 값도 산출 일자(1)도 불변이고, 거기서 낡는 것은 "현재 751"이라는 수치뿐이다.
- **`TRADING_DAYS_750`은 `min(size, 750)`으로 포화해 불변이다.** 창 확대가 U-05 게이트를 흔든다고 오해하지 않는다.
- **재귀 지표(`ATR_14`·`RSI_14`·`MACD`·`MACD_V`)의 저장값이 미세하게 바뀌는데 테스트가 못 잡는다** —
  픽스처가 창보다 짧아 값이 그대로다. **올리기 전에 최신 일자 값을 떠 두고 올린 뒤 대조한다.**

## 코드와 메타데이터

남은 것은 전부 **관측**이다. 조합은 프리셋의 조건 목록이 한다 — 지표 안에 판정을 접으면
사용자가 왜 걸렸는지 볼 수 없고, 그것이 점수화를 철회한 이유다.

| 쓰임 | 코드 |
|---|---|
| 구름 | `ICHI_MOD_A`(현재 색) `_B`(미래 색) `_C`(두께) `_K`(체류) `ICHI_PRICE_VS_KUMO`(가격 위치) |
| 선의 기울기 | `ICHI_MOD_F`(전환선) `_G`(기준선) `_L`(선행스팬 A) `_J`(선행스팬 B 평탄) |
| 선의 관계 | `ICHI_TK_CROSS`(전환>기준) `ICHI_MOD_H`(전환·기준과 구름, **센티널 −2**) |
| 시간·조망 | `ICHI_MOD_D`(후행스팬) `_E`(시간론, **센티널 −1**) `_M`(트위스트, **센티널 −1**) |
| 호전 | `ICHI_KAIZEN_W` `ICHI_KAIZEN_D` |
| 거래량 | `ICHI_OBV_T` `ICHI_DIVERGENCE` |
| 시장 대비 | `EXCESS_RETURN_26W` |

- `EXCESS_RETURN_26W`에 `ICHI_` 접두어를 붙이지 않는다 — **T-08(주간 베타)과 공유한다.**
  **`ICHI_*` 18개에 들지 않는 유일한 지표이며 시장 지수를 쓰는 것도 이것뿐이다.**
- **`ICHI_TK_CROSS`의 부등호를 다시 계산하지 않는다.** 정본은 `WeeklyAnalyzer`의 `tkAbove`
  하나이고 `drv_42`·`drv_44`가 그것을 공유한다. 나란히 적으면 갈리고, 전부 정수라 갈려도
  값이 그럴듯하다.
- **`valueType = COUNT` + `decimalScale = 0`으로 간다.** 새 enum 값을 만들면 enum + CHECK 마이그레이션 +
  `wire-contract.json` + 프론트 미러까지 번진다. **프론트는 `valueType`으로 포맷을 분기하지 않는다**
  (유일한 등장이 `frontend/src/api/types.ts`). "개수"가 아니라는 것은 `interpretation`이 말한다.
- **`bands`는 단조 순서형에만.** `ICHI_PRICE_VS_KUMO`(위/안/아래)가 그것이고,
  **명목형(`ICHI_DIVERGENCE`)과 센티널이 섞인 셋(`_E`·`_H`·`_M`)에는 `bands`도 `direction`도
  붙이지 않는다.** 센티널은 「해당 없음」이 유리한 쪽 극단에 앉아 조건의 좌변을 뒤집는다.
- **`PriceScaling`과 `MovingAverages.SCALE`이 package-private이다.** 하위 패키지는 접근하지 못하므로
  **둘을 `public`으로 올리거나 하위 패키지를 만들지 않는다.** 다시 구현하는 선택지는 없다.

## 프리셋과 컬럼

`ICHIMOKU_SP_KR`, FILTER 모드(`MOMENTUM_KR`이 선례). 조건 다섯 — `ICHI_TK_CROSS >= 1` ·
`ICHI_PRICE_VS_KUMO >= 1` · `ICHI_MOD_A >= 1` · `ICHI_MOD_B >= 1` · `ICHI_MOD_D >= 1`.

- **MUST NOT: 센티널이 섞인 셋(`_E`·`_H`·`_M`)을 좌변에 두지 않는다.** `IchimokuPresetTest`가
  문구가 아니라 **조건 자체를 훑어** 확인한다 — 설명에 「쓰지 말 것」을 적는 것으로는 다음
  사람이 쓰는 것을 막지 못한다.

- **프리셋 전용 컬럼은 `defaultColumn`으로 띄우지 않는다** — 그것은 전역이라 모든 화면이 시끄러워진다
  (지금 넷뿐이다). **어셈블러가 `source.codeIfPreset()`으로 `PresetCatalog.extraColumns`를 조회해 union한다.**
  `columns`는 이미 동적 목록이라 스키마도 wire-contract도 안 건드린다. **표현 계층 한정 예외다.**
  - `ScreenDefinition`에 필드를 더하는 길은 `screen` 마이그레이션 + `ScreenStore` 4메서드 + CUSTOM 저장 API +
    wire-contract까지 연다. 더미 조건(`ICHI_OBV_T >= -999`)은 조건 내역 화면에 무의미한 줄을 남긴다.
- **FILTER에는 서버 정렬이 없다**(`ScreeningRepository`가 SCORING만 `score DESC`). 걸러진 종목들
  사이의 우열은 `extraColumns`가 값으로 보여 줄 뿐이므로 **`description`에 결핍으로 적는다**
  (ADR-0039의 기준을 승계).
- **조건 지표를 `extraColumns`에 다시 넣지 않는다.** 어셈블러가 이미 union한다(`:75`).
- **`SWING_MIDTERM_KR`은 조건이 정확히 20개(상한)다.** 건드리지 않는다 — `PresetCatalogTest`가 단언한다.
- **주중에 값이 바뀌는 첫 프리셋이 된다.** 워치리스트가 이것을 참조하면 같은 주에 알림이 여러 번 울릴 수
  있다 — edge-trigger(ADR-0026)가 어디까지 접는지 착수 시 확인한다.

## 검증 — 대조 시점을 먼저 정한다

> **지금은 대조를 하지 않기로 했다**(ADR-0046 §승인된 예외, 2026-08-13). 아래는 **다시 하기로
> 할 때** 필요한 것이고, 그 전에는 이 절 때문에 픽스처를 요청하지 않는다.


- **주말에 뜨되 대조는 그 다음 영업일이다.** 원본은 실시간 봉에서 진행 중인 주를, 과거 봉에서
  마지막 확정 주를 준다. 주말이면 TradingView의 마지막 주봉이 확정된 월~금이고 우리
  `asOf = 금요일`과 같은 봉이 된다 — 두 의미론이 일치하는 유일한 시점이다.
  **그런데 토요일에 우리가 가진 최신 봉은 목요일치다** — 소스가 거래일 T의 종가를 T의 다음
  영업일 13시에 내기 때문이다(ADR-0042). 성립하는 조합은 하나다: **주말(또는 금요일 장 마감
  후)에 픽스처를 뜨고, 금요일 종가가 DB에 들어온 다음 영업일에 `asOf = 그 금요일`과 견준다.**
  픽스처는 스냅샷이라 대조는 나중에 해도 된다.
- 표본: 구름 위·안·아래가 각 1개 이상, 전환선이 기준선을 넘은 것과 못 넘은 것, **207주 미만
  밴드 1개**, **분할 이력 종목 1개**. 픽스처는 **최신 일자**로 뜬다(ATR 시드가 과거로 갈수록
  벌어진다). **점수 임계(5/15/8)는 더 묻지 않는다** — 그 계층이 없다.
- **테스트는 `market_index_daily`를 직접 시드한다.** 수집 어댑터는 `@ConditionalOnApiKey`라 키 없는
  환경에 없는데 계산기가 읽는 것은 테이블이다. 시드가 없으면 `EXCESS_RETURN_26W`가 비고 **에러는
  안 난다.** `ICHI_*` 18개는 2026-08-14부터 지수를 쓰지 않는다.

### 어긋나도 파면 안 되는 자리

- **OBV 시작점.** `ta.obv`는 첫 봉부터의 누적이라 TradingView와 절대 수준이 완전히 다르다. 그러나
  `drv_26`은 13점 OLS의 **t-통계량**이라 평행이동·배율에 불변이고 `drv_41`은 부호만 본다. **여기가 아니다.**
- **과거 일자가 TradingView 차트와 다른 것.** 우리는 진행 중인 주를 쓰고 차트의 과거 봉은 확정 주다.
  **Screener(마지막 봉)와는 같다.**
- ATR 시드 위치(우리 이력은 2020-01-02에서 시작한다), 수정주가 미보정(P9 전), 주 경계 휴장일 처리.

## 실측 기준선

착수 뒤 값이 이보다 크게 벗어나면 설계가 어긋난 것이다.

### 착수 전 (2026-08-11)

| 무엇 | 값 |
|---|---|
| 207 ISO주 이상 보유 종목 | **320 / 356** (130~206주 10 · 130주 미만 26) |
| 종목당 최대 ISO주 | 346 (소스가 2020-01-02에서 시작한다) |
| 일봉↔주봉 비율 | **4.69 일봉/주** |
| 종목 하나 1,621행 읽기 | 2.5ms (pkey Bitmap Index Scan) |
| 일일 갱신 전체 | 173초 |

### 착수 뒤 (2026-08-13, 창 1,100 · 지표 71코드)

| 무엇 | 값 |
|---|---|
| 지수 전 구간 적재 | 코스피·코스닥 각 **1,623행**, **지수당 1콜**, 3초 |
| **단일 거래일 백필** (350종목) | **91초** (1회차, 132만 행 신규) · **41초** (2회차, 0행) |
| 멱등 | 2회차 `written_row_count = 0` |
| `ICHI_*` 산출 | 29코드 × **42,000행** · 315종목 · 종목당 평균 **133.3일자**(최대 144 · 최소 27) |
| `EXCESS_RETURN_26W` | 347종목 × 180일자 = 61,655행 (207주 가드에 안 걸린다) |
| `indicator_value` | 2,329,738 → **3,650,442행**(+56.7%) · 41 → **71코드** |
| 인덱스 | 320 → **502MB**. **백만행당 137MB로 불변**(임계 250) |
| 전체 크기 | 1,160 → **1,342MB** (ADR-0046이 예상한 ≈1.8GB보다 작다) |
| `n_tup_upd` | **불변** — 두 백필이 전부 INSERT였다. 왕복은 되살아나지 않았다 |

**창 확대(751 → 1,100)로 값이 바뀐 기존 지표는 <b>하나도 없다.</b>** 재귀 지표 넷의 시드가
349봉 앞으로 갔지만 Wilder/EMA 잔차가 `(13/14)^349 ≈ 6e-12`라 **저장 자릿수(8)보다 작다.**
보존 창 180일자 전체에서 `updated_at`이 갱신된 행이 `SHARES_GROWTH_3Y`(일자 수 1 → 350)
말고는 0이다. ADR-0046이 예고한 "저장값이 미세하게 바뀐다"는 **방향은 맞았고 크기가 저장
정밀도 아래였다.**

**초기 백필은 단일 날짜 1회로 끝난다** — 위 표의 149일자가 그 한 번에서 나왔다.
"최근 20~30거래일"이라는 제약은 실재하지 않는다.
