# S1 스파이크 결과

환경: macOS · 시험용 Claude Code 2.1.301(격리 설치, 전역 2.1.292는 그대로) · Python 3.13.5. 판정은 hook 덤프 파일과 `--output-format json` 결과로 했다(모델의 자기 보고는 쓰지 않음).

## P4 — `onFailure` (2026-10-16)
| 조건 | 버전 | 결과 |
|---|---|---|
| UserPromptSubmit hook(정상) + `"onFailure":"block"` 키 | 2.1.292 | 오류 없이 기동, hook 실행됨, 답 정상 → **모르는 키는 조용히 무시**(settings 거부 아님) |
| 같은 설정, 키 없음(대조) | 2.1.292 | 동일 |
| hook이 예외(exit 1) + `onFailure: block` | 2.1.301 | **프롬프트 차단** (「UserPromptSubmit operation blocked by hook」) |
| hook이 예외(exit 1), 키 없음(대조) | 2.1.301 | 프롬프트 통과 (fail-open) |

→ 계약: 관문 hook에 `onFailure: block`을 쓰려면 최소 2.1.295. 그 미만에서는 키가 무시되어 **fail-open으로 떨어진다**(경고 없음) → 최소 버전 강제 장치가 필요(세션 시작 버전 확인).

## P6 — exec form · `${CLAUDE_PROJECT_DIR}` · 스크립트 부재 (2.1.301)
| 조건 | 결과 |
|---|---|
| `args: ["${CLAUDE_PROJECT_DIR}/dump.py"]`, 파일 있음 | 확장됨, hook 실행, 답 정상 |
| 같은 설정, 파일 없음 | **프롬프트 차단** (python이 exit 2) |
| `args: [<절대경로>/nope.py]`(없음) | **프롬프트 차단** — C3은 exec form에서도 재현 |
| `args: ["-c", <부트스트랩>, <경로>]`(없음) | 부트스트랩이 stderr + exit 1 → **프롬프트 통과** |

→ 계약: 모든 hook은 `-c` 부트스트랩으로 호출(파일 부재·인터프리터 내부 오류를 exit 1로 바꿈). 관문 hook은 부트스트랩 + `onFailure: block`으로 「실패 시 닫힘」을 명시적으로 고른다.

## P2 — 이벤트별 실제 hook 입력 (2.1.301, 헤드리스) — 원본 `spike/payloads/*.json`
| 이벤트 | 주요 필드 | 설계에 주는 것 |
|---|---|---|
| SessionStart | `source`(startup·resume·compact), resume·compact에는 `context_tokens` 등 추가 | 재개·압축 재주입 판정 |
| UserPromptSubmit | `prompt`, `prompt_id`, `permission_mode`, `transcript_path` | 입력 파싱·사람 턴 기록 |
| PreToolUse | `tool_name`, `tool_input`(Write: `file_path`·`content` / Edit: `old_string`·`new_string`·`replace_all` / Bash: `command`), `tool_use_id`, `prompt_id` | Edit은 조각만 옴 → 관문이 「적용 후 내용」을 직접 계산해야 함 |
| PostToolUse | 위 + `tool_response`(Write·Edit: `originalFile`·`structuredPatch`·`gitDiff` …) | 작성 즉시 알림 |
| **서브에이전트 안의 도구 호출** | **`agent_id`·`agent_type`이 붙음** | 메인/서브 구분 가능 (검증자 읽기 전용 강제, 세션 범위 판정) |
| SubagentStart | `agent_id`, `agent_type` | 서브에이전트 주입 |
| SubagentStop | `last_assistant_message`, `agent_transcript_path`, `agent_type`, `stop_hook_active` | 검증 판정은 `last_assistant_message`에서 추출 |
| **압축 시 SubagentStop** | **`agent_type`이 빈 값으로 발생** | 판정 기록 hook은 **검증자 유형만** 받아야 함(안 거르면 압축 요약을 판정으로 오인) |
| Stop | `stop_hook_active`, `last_assistant_message` | Stop 관문 |
| PreCompact / PostCompact | `trigger`, PostCompact는 `compact_summary` | — |
공통: 모든 이벤트에 `session_id`·`transcript_path`·`cwd`, 턴 단위 `prompt_id`. **대화형 세션의 payload는 아직 채집 전(P1).**

## P5 — 주입 상한의 단위 (2.1.301, 판정: 시작·끝 canary)
| 조건 | 결과 |
|---|---|
| 한글 8,500자 + `ensure_ascii=True`(원시 출력 약 5만 자) | 끝 canary까지 전부 전달, 파일 안내 없음 |
| 한글 8,500자 + `ensure_ascii=False` | 동일 |
| 한글 12,000자 + `ensure_ascii=False` | 「Output too large (11.8KB)」 안내 + 앞쪽 약 2KB 미리보기만, 끝 canary 미전달 |
→ **상한은 풀린 문자열의 글자 수 기준.** 출력을 ASCII 이스케이프로 내도(Windows 인코딩 회피) 손해 없음. 7,000/9,000자 임계는 글자 수로 유효.

## P8 — worktree × hook (2.1.301, 판정: gate 로그 + 파일 유무)
- 기능 worktree(`feat/x`)에서 연 세션: `cwd`·`CLAUDE_PROJECT_DIR` 모두 기능 worktree. 실행된 hook은 **세션을 연 worktree의 settings·스크립트**(대상 worktree의 것이 아님 → 업그레이드 판 불일치가 실제로 생김).
- 쓰기 대상 경로 기준으로 `git -C <대상 디렉토리> rev-parse --abbrev-ref HEAD` 판정: `kn/int-1` worktree 쓰기 **허용**, 기능 worktree의 `knowledge/` 쓰기 **거부** — 기대대로.
- 다른 worktree에 쓰려면 세션에 `--add-dir`(대화형은 권한 확인)이 필요 → 일상 사용에서는 「개발 중 빈칸은 `kn` worktree에서 **새 세션**을 연다」가 자연스러움(엔진 `kn start`가 안내).
- 진행 중 intake 읽기: `git fetch origin '+refs/heads/kn/*:refs/remotes/origin/kn/*'` 후 `for-each-ref`·`ls-tree`·`show`로 `state.json` 읽기 **동작**(로컬 bare 원격 0.06초 — 실제 원격의 네트워크 지연은 미측정).

## P7 — 브랜치 모델 한 바퀴 (로컬 bare 원격 + 클론 2개)
| 상황 | 결과 |
|---|---|
| 두 `kn/*` 브랜치가 같은 주제 문서의 **붙어 있는 두 줄**을 각각 수정 → 순서대로 병합 | 두 번째 병합 **충돌** |
| 같은 상황, 규칙 줄 사이에 **빈 줄** | **자동 병합 성공** — 단 병합 결과는 각 브랜치가 검증받은 초안과 다른 내용 |
| 두 브랜치가 문서 끝 「변경 이력」에 각자 한 줄 덧붙임 | **항상 충돌** |
→ 계약: ① 규칙 줄 사이 빈 줄(양식) ② 검증 결속은 「파일 전체 해시」가 아니라 **이번 입력이 바꾼 규칙 줄** 단위 ③ **변경 이력은 문서 안에 덧붙이지 않고 변경 1건 = 조각 파일 1개**(towncrier식)로 두고, 목록의 변경 횟수·문서 표시는 조각에서 계산 ④ 충돌을 사람이 풀면 해당 규칙 줄만 재검증(`complete → draft` 재개).

## P1 — 대화형 세션의 질문 도구 (2.1.301, Python pty로 터미널 구동, 판정: hook 덤프) — 원본 `spike/payloads/interactive/`
| 조건 | 결과 |
|---|---|
| AskUserQuestion 대화상자에서 선택지 고름 | `PostToolUse(AskUserQuestion)`의 `tool_response.answers` = `{질문 문장: 고른 라벨}` (`tool_input`에도 같은 값) |
| 같은 대화상자에서 「Other」로 자유 입력 | `answers` = `{질문 문장: 타이핑한 문장 그대로}` |
| 질문 문장에 `[Q-01]` 접두 | 접두가 그대로 키에 보존 → hook이 질문 ID로 결정적으로 짝지을 수 있음 |
| 대화상자 답 → `UserPromptSubmit` 발생? | **발생하지 않음** (대조: 직접 타이핑한 프롬프트는 발생) |
| 헤드리스 `-p` | AskUserQuestion 자체가 없음(앞서 실측) |
→ 계약: 질문 문장은 `[Q-xx]`로 시작해야 하고(PreToolUse가 형식 검사), 답 기록은 `PostToolUse(AskUserQuestion)`에서만. 일반 턴 답(UserPromptSubmit)은 `Q-xx:` 접두가 있을 때만 그 질문의 답으로 인정. AI가 hook 스크립트를 Bash로 직접 불러 가짜 답을 넣는 경로는 PreToolUse로 거부.

## S1 종합 — WP0 계약에 들어갈 것
1. **hook 호출:** 모든 hook은 `-c` 부트스트랩(P6). 관문 hook은 부트스트랩 + `onFailure: block`, 최소 버전 2.1.295 미만이면 키가 조용히 무시되므로(P4) **세션 시작에 버전 확인**.
2. **출력:** ASCII 이스케이프 JSON(P5), 주입 상한은 글자 수 기준 7,000 경고 / 9,000 절단(P5). deny·systemMessage·additionalContext·Stop block은 그대로 따라짐(P3).
3. **질의응답 결속:** `[Q-xx]` 질문 문장 + `PostToolUse(AskUserQuestion)`의 `answers`(P1). 대화상자 답은 UserPromptSubmit을 안 띄운다.
4. **검증 판정:** SubagentStop의 `last_assistant_message`에서, **검증자 `agent_type`만**(압축도 SubagentStop을 띄움, P2). 서브에이전트 도구 호출은 `agent_id`로 구분.
5. **브랜치 관문:** 쓰기 대상 경로 기준 `git -C` 판정(P8). 실행되는 hook은 세션을 연 worktree의 판 → `engine_version` 비교 필요. 개발 중 빈칸은 `kn` worktree에서 새 세션.
6. **진행 중 intake 읽기:** `refs/remotes/origin/kn/*`의 `state.json`(P8, 원격 지연은 Windows 키트에서 측정).
7. **팀 충돌(P7):** 규칙 줄 사이 빈 줄 · 검증 결속은 바뀐 규칙 줄 단위 · **변경 이력은 조각 파일**(문서 안 덧붙이기는 동시 작업 시 항상 충돌) · 충돌 해결 뒤 해당 줄만 재검증.
