# 하네스 범용 파일묶음 export 계획 (v4 — 핵심 기능 중심으로 재분류)

> v3까지는 반증 지적을 받을 때마다 장치를 더해 지나치게 커졌다(사본: `export-plan-v3.1-폐기.md`). v4는 사용자 판단기준(2026-10-17)으로 **핵심 / 핵심을 받치는 것 / 핵심 아님**을 갈라, 핵심만 구현해 export한다. 스파이크 결과(docs 11)는 그대로 쓴다.

## 판단기준 (사용자, 2026-10-17)
1. 사람이 회의록·요구사항 명세 등을 프롬프트로 입력한다.
2. AI는 자체 루프로 사람과 질의응답하며 문서를 구체화한다 — **강제**.
3. 기준 미달 문서는 도서관에 들어가면 안 된다 — **강제**.
4. 작성 중 문서는 도서관에 들어가면 안 된다 — **강제**. 단, 작성 중 문서는 로컬 세션에만 있고 push되지 않으므로 다른 개발자 세션에서 감지·회피하는 장치는 필요 없다.
- 팀 작업 방식: 변경마다 PR 리뷰 없음, **주 1회 main의 도서관을 함께 리뷰**. 사람의 push·커밋을 막는 관문 금지.

## 핵심 기능 (구현한다)

| # | 기능 | 판단기준 | 구현 |
|---|---|---|---|
| K1 | 도서관 구조 | 1 | `knowledge/topics/`(완성 문서) · `sources/`(입력 원문, 고치지 않음) · `vocabulary/`(정본 키워드, 키워드당 파일) · `checklists/` · `templates/` · `intake/`(작성 중, **`.gitignore`**) |
| K2 | 입력 감지 → 입력 절차 강제 연결 | 1·2 | UserPromptSubmit hook이 `키워드: …` 입력을 알아보고 원문 보관 + 입력 절차 skill·해당 점검표를 붙임 |
| K3 | 질의응답 루프 | 2 | 입력 절차 skill(분해 → 점검표로 빈칸 찾기 → 질문) + intake 상태 파일. 질문은 `[Q-xx]` 접두, 답은 PostToolUse(AskUserQuestion) hook이 상태 파일에 기록(일반 대화 답은 `Q-xx:` 접두일 때) |
| K4 | **입고 관문 하나** | 3·4 | PreToolUse hook: AI의 `topics/` 쓰기는 해당 intake가 완성일 때만 허용. 완성 = 점검표 전 항목이 「사람의 답」 또는 「사람이 확인한 해당 없음」 + 모든 규칙 줄에 원문 ID + [추론] 줄 0. 작성 중이면 미완성이므로 같은 관문에 걸림 |
| K5 | 개발 요청 시 관련 문서 연결 | (앞선 결정) | UserPromptSubmit hook: 「연계 키워드」 합집합 + 일치순 목록(상태·대체·사유 포함), 7,000자 경고(`systemMessage`)·9,000자 절단. SubagentStart·압축 뒤 재주입 |
| K6 | 이력 | (앞선 결정) | 바뀜·기각 상태는 `supersedes`에서 계산. 단순 변경 이력은 해당 규칙 줄 아래에 붙이고 규칙 줄 사이는 빈 줄(동시 작업 자동 병합 — 스파이크 P7) |
| K7 | 지어내기 금지(코드) | (앞선 결정) | CLAUDE.md IMPORTANT 한 줄 + 개발 요청 목록 머리말에 근거·미결 주석 형식 |
| K8 | 주간 리뷰 보고서 | 리뷰 방식 | 명령 하나: 이번 주 바뀐 문서 · 바뀐 줄의 원문·질의응답 근거 · 「해당 없음」 항목 · 원문 없는 줄 · 바뀜·기각 문서를 인용한 코드. 검증자(AI)는 이 보고서에 의심 항목을 채우는 용도로만(막지 않음) |
| K9 | 문서 | — | CLAUDE.md 템플릿 · 사용자 가이드(입력 형식·질의응답 기대치) · Windows 온보딩(Python 설치·Claude Code 버전) |

## 핵심을 받치는 것 (작게, 반드시)
- 모든 hook은 `-c` 부트스트랩으로 호출(스크립트가 없어도 프롬프트가 막히지 않게 — P6). 입고 관문만 `onFailure: block`(실패 시 닫힘). 세션 시작 hook이 Claude Code 버전을 확인해 2.1.295 미만이면 경고(P4).
- 인코딩: 읽기 `utf-8-sig`, 쓰기 `utf-8`·LF, hook 출력은 ASCII 이스케이프 JSON(P5). 경로는 `/`로 정규화, 저장소 루트는 `git rev-parse --show-toplevel`.
- 코어 라이브러리 하나를 hook·보고서가 함께 쓴다(판정이 갈리지 않게).
- 시험은 스파이크에서 채집한 실제 hook 입력을 픽스처로 쓴다.

| `kn/*` 브랜치·worktree·원격 브랜치 읽기 | 뺌 | 위와 같음. 도서관은 main에 바로 커밋 |

| Stop 관문 | 뺌 | 입고 관문(K4)이 3·4를 이미 지킴. 끊긴 intake는 세션 시작 알림으로 이어감 |
| 로컬 검증자 + 초안 해시 결속 + 재개 전이 | 뺌 | 검증은 주간 보고서(K8)로 |
| 이력 조각 파일 | 뺌 | 규칙 줄 단위 이력 + 빈 줄로 충분(P7 자동 병합 확인) |
| 소유자 잠금·repair·park·withdrawn·라운드 상한 | 뺌 | intake는 로컬(gitignore)이라 지우면 끝. 실패가 관측되면 그때 추가 |
| 버전·업그레이드 이행 규칙 | 최소화 | `bundle_version` 파일 하나 |

| 설계 정본(`design-*`) | 틀만 | 도서관이 쌓인 뒤의 일. 키워드 달린 skill 템플릿만 제공 |
