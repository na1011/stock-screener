# 05의 미확인 3건 실측

기준일 2026-10-15 · Claude Code 2.1.292 · 모델 `claude-opus-5-5` · `claude -p` 헤드리스 22회.
대상 설계: frontmatter 키워드(정본 어휘) → `UserPromptSubmit` hook이 **합집합 + 일치 개수 순**으로 문서 목록(경로·상태·대체 관계·사유)을 주입. hook 원문은 부록.

## 결과 요약

| 미확인 항목 | 결과 | 표본 |
|---|---|---|
| 1. 주입 목록 중 모델이 실제로 여는 비율 | 목록 56~69건 중 **3~16건(중앙값 약 7건)만** 열었다. 작업 관련 문서는 **12/12회 전부** 열었다. 고르는 방법은 목록 제목 + 내용 Grep 1~3회 | 200장 도서관, 12회 |
| 2. 이력 주입이 기각안 재시도를 줄이는가 | 이력 없음: **1/6회** 재시도(겐트리 적층 2단 상향 = 기각된 3단안). 이력 주입: **0/6회**. 이력이 있으면 기각 **사유**를 피해 가는 대안을 냈다 | 6 대 6 |
| 3. hook 주입이 subagent에 넘어가는가 | **안 넘어간다(0/2).** `SubagentStart` hook으로 같은 목록을 다시 넣으면 **넘어간다(2/2)** | 4회 |

## 1. 열람 범위

- 에이전트는 주입 목록을 **후보 집합**으로 쓰고 전부 읽지 않았다. 목록 제목을 보고 고른 뒤, 내용 Grep(`공팔레트|버퍼|적층` 등)으로 보강했다.
- 목록 **밖** 문서도 12회 중 11회 열었다(출고 컨베이어 협의 C01). 주입은 경계가 아니라 출발점이다.
- 문서가 7장뿐인 1차 시험에서는 목록과 무관하게 **폴더 전체**를 읽었다. 작은 도서관에서는 다 읽는 편이 싸기 때문으로 보인다.
- 목록 69건이 5,115자였다(건당 약 74자). 이 길이면 10,000자 상한까지 약 130건이 들어간다.

## 2. 기각 이력의 효과

과제: 공팔레트 목적지·적층 단수 구현 + 버퍼 만재 처리 + 회수 사이클 개선안(1차·2차 1개, 3차 3개).
비교 조건은 기각·대체 문서(A00 ASRS 랙 재입고, G00 겐트리 3단 적층) **파일 자체를 도서관에서 뺐다.** 목록에서만 빼면 에이전트가 폴더에서 찾아 읽었다(1차 시험).

| 조건 | 개선안 1개 요구 | 개선안 3개 요구 | 합 |
|---|---|---|---|
| 이력 없음 | 0/3 | **1/3** — 「겐트리 적층 단수를 2단에서 상향」 | 1/6 |
| 이력 주입 | 0/3 | 0/3 | 0/6 |

- 이력 주입 6회 모두 코드 주석에 「A00 철회·G00 기각이라 쓰지 않는다」를 남겼다.
- 한 회는 기각 사유(그리퍼 하중)를 피하는 대안을 냈다. 「적층은 하중 제한 없는 버퍼 측 고정 스태커가 맡는다」였다.
- 버퍼 만재 처리는 12회 모두 「발생 설비에서 대기」를 골랐다. 랙 재입고로 우회한 경우는 0건이다.

## 3. subagent 전달

- 검증 방식: hook 주입문에 확인용 토큰을 넣었다. 메인 에이전트에게는 그 토큰을 숨기고 subagent를 띄우게 했다. 도구 입력 기록으로 메인 에이전트가 토큰을 흘리지 않았음을 확인했다.
- `UserPromptSubmit`만 걸었을 때 subagent는 「NONE」을 답했다(2/2). 서브에이전트에게 개발을 맡기면 **협의 목록 없이 일한다.**
- `SubagentStart` hook이 마지막 주입 목록을 다시 넣게 하면 subagent가 토큰을 답했다(2/2). 부록의 9줄짜리 스크립트다.

## 하네스에 반영할 것

1. **`SubagentStart` hook은 필수다.** 없으면 subagent 작업에서 기준 3·4가 통째로 빠진다.
2. **문서 제목을 구체적으로 쓴다.** 에이전트가 목록에서 고르는 1차 근거가 제목이다. 작성 양식에 제목 규칙(설비·대상·논점)을 넣는다.
3. **목록에 상태·대체 관계·사유를 그대로 싣는다.** 이번 시험에서 재시도를 막은 것이 그 줄이다.

## 한계

- **도서관이 합성이다.** 작업 관련 문서 4장은 제목·내용이 과제와 뚜렷이 겹쳤다. 나머지 196장은 일반 문구였다. 실제 협의록처럼 비슷한 문서가 많으면 고르기가 어려워진다.
- **문서 이름의 영향이 섞였을 수 있다.** 관련 문서는 이름 규칙이 달라(A01·G01 대 D0001…) 눈에 띄었을 수 있다. 목록 밖 C01을 연 것도 이 영향일 수 있다.
- **표본이 조건당 3~6회라 방향만 보인다.** 2번의 1/6 대 0/6은 차이를 증명하지 못한다.
- 헤드리스 모드에서 python 실행은 승인되지 않아 에이전트가 시험을 돌리지 못했다. 열람·판단 측정에는 영향이 없다.

## 부록 — 시험에 쓴 hook

`UserPromptSubmit` (`.claude/hooks/inject.py`)

```python
#!/usr/bin/env python3
# UserPromptSubmit: 「연계설비:」 줄의 키워드(정본 어휘)로 협의 문서를 합집합 매칭하고 일치 개수 순으로 목록을 주입한다.
import json, os, re, sys, glob, time
root = os.environ.get("CLAUDE_PROJECT_DIR", ".")
data = json.load(sys.stdin)
prompt = data.get("prompt", "")
m = re.search(r"연계설비\s*:\s*(.+)", prompt)
if not m:
    sys.exit(0)
vocab = {w.strip() for w in open(os.path.join(root, "vocabulary.txt"), encoding="utf-8") if w.strip()}
query = [k.strip().lower() for k in re.split(r"[,\s]+", m.group(1)) if k.strip()]
unknown = [k for k in query if k not in vocab]
query = [k for k in query if k in vocab]
docs = []
for p in sorted(glob.glob(os.path.join(root, "agreements", "*.md"))):
    text = open(p, encoding="utf-8").read()
    fm = re.match(r"---\n(.*?)\n---", text, re.S).group(1)
    meta = dict(re.findall(r"^(\w+):\s*(.*)$", fm, re.M))
    kws = [k.strip() for k in meta.get("keywords", "").strip("[]").split(",")]
    hit = len(set(kws) & set(query))
    if hit:
        docs.append((hit, meta, os.path.relpath(p, root)))
docs.sort(key=lambda d: (-d[0], d[1].get("status") != "active", d[2]))
lines = []
for hit, meta, rel in docs:
    s = f"- {rel} · [{meta.get('status')}] · 일치 {hit}/{len(query)} · {meta.get('title')}"
    if meta.get("supersedes"): s += f" · 대체함: {meta['supersedes']}"
    if meta.get("superseded_by"): s += f" · 대체됨→{meta['superseded_by']}"
    if meta.get("reason"): s += f" · 사유: {meta['reason']}"
    lines.append(s)
head = f"요청 키워드({', '.join(query)})에 매핑된 협의 문서 목록이다. 작업 전에 관련 문서를 Read로 읽어라. superseded·rejected 항목은 다시 시도하지 않는다."
if unknown:
    head += f"\n정본 어휘에 없는 키워드: {', '.join(unknown)} — 정본 어휘로 다시 입력하라."
ctx = head + "\n" + "\n".join(lines)
with open(os.path.join(root, "logs", f"inject-{time.time_ns()}.txt"), "w", encoding="utf-8") as f:
    f.write(ctx)
print(json.dumps({"hookSpecificOutput": {"hookEventName": "UserPromptSubmit", "additionalContext": ctx}}, ensure_ascii=False))
```

`SubagentStart` (`.claude/hooks/sub.py`)

```python
#!/usr/bin/env python3
# SubagentStart: 메인 세션에 마지막으로 주입한 협의 목록을 서브에이전트에도 넣는다.
import json, os, glob, sys
root = os.environ.get("CLAUDE_PROJECT_DIR", ".")
json.load(sys.stdin)
logs = sorted(glob.glob(os.path.join(root, "logs", "inject-*.txt")))
if not logs: sys.exit(0)
ctx = open(logs[-1], encoding="utf-8").read()
print(json.dumps({"hookSpecificOutput": {"hookEventName": "SubagentStart", "additionalContext": ctx}}, ensure_ascii=False))
```

시험에서 조건을 가르던 분기(`KW_HIST` 이력 제외, `KW_CANARY` 확인 토큰)만 빼고 나머지는 시험에 쓴 그대로다. 시험용 시제품이다. 운영용으로 쓰려면 남은 일이 있다: 오류 처리, 동시 세션의 로그 구분(지금은 「마지막 로그」를 읽는다), frontmatter 파서 견고화, 10,000자 초과 처리.
