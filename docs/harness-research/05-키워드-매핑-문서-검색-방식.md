# 사람이 단 키워드는 hook이 결정적으로 대조한다

기준일 2026-10-14. 라벨: [1차] 공식 문서·논문·소스 · [2차] 재인용 · [벤더] 자사 서술·측정 · [일화] 개인 실험 · [미검증] 원문 미대조.

## 1. 한 줄 결론

**골격은 하나다. frontmatter의 매핑 키워드(정본 어휘)를 스크립트가 keyword→문서 색인으로 만들고, `UserPromptSubmit` hook이 요청 속 키워드를 그 색인과 정확 대조해 매칭 문서 목록(경로·status·대체 대상·사유 한 줄)을 강제 주입한다.** 사람이 단 키워드가 곧 정답 레이블이므로, 그것을 그대로 집합 연산하는 방식만 「전부 로드했다」를 기계로 증명할 수 있다. 단 **이 과제(키워드→문서 집합 회수)를 잰 공개 벤치마크는 없다.** 아래 순위는 기제에서 끌어낸 추론이다. hit율은 팀이 「질의 → 기대 문서 집합(이력 포함)」 평가셋을 만들어 직접 재야 한다.

## 2. 접근 방식 비교표 (위에서부터 기제 추론순)

| 방식 | 결정성(전부 로드 보장?) | 키워드 hit 근거 | 변경/폐기 이력 노출 | 토큰 비용 | Claude Code 연결 | 증거 수준 |
|---|---|---|---|---|---|---|
| **A. frontmatter 태그 + 생성 색인 + `UserPromptSubmit` hook 강제 주입** | **목록 주입까지는 보장한다.** hook은 이벤트마다 돌고 출력이 문맥에 들어간다. 본문 Read는 모델이 한다 | 문자열 정확 대조, 즉 집합 연산이다. 실패는 표기 변이와 태그 누락에서만 나고, 둘 다 작성 시점에 검사할 수 있다(추론) | 직접 설계한다. 색인이 `status`·`supersedes`·사유를 함께 출력 | 목록만 주입(문자열당 ≤10,000자). 본문은 연 것만 | 내장 hook ([Hooks](https://code.claude.com/docs/en/hooks), 조회 2026-10-14) [1차] | 기제 [1차] · **hit율 수치 없음** |
| B. skill `description` 자동 활성화 | 아니오. 모델의 의미 판단이고, description+when_to_use는 1,536자에서 잘린다 ([Skills](https://code.claude.com/docs/en/skills)) [1차] | 활성화 50–55%, forced-eval hook을 붙이면 100% ([Spence, 2026-02-08](https://scottspence.com/posts/measuring-claude-code-skill-activation-with-sandboxed-evals)) [일화] | 없음 | description은 상시, 본문은 호출 시 | 내장 | [1차] 기제 + [일화] |
| C. 모델 agentic grep (CLAUDE.md 지시) | 아니오. grep을 할지, 어떤 낱말로 할지를 모델이 정한다. 안 찾은 것은 로그에 안 남는다 | Claude Code+Opus 4.6: inline 전달 시 grep 76.7 vs vector 75.0, 파일 전달 시 68.1 vs 79.3 ([Sen et al., arXiv 2605.15184, 2026-05-14](https://arxiv.org/abs/2605.15184)) [1차]. 대화 기억 과제라 이 과제와 다르다 | 모델이 status를 읽을 때만 | 탐색 턴 수만큼 | 내장(Grep/Glob) | [1차], 과제 상이 |
| D. vector/embedding RAG (hybrid 포함) | 아니오. top-k·임계 절단이 원리상 있다 | top-20 실패율: embedding 단독 5.7%, BM25+rerank 추가 시 1.9% ([Anthropic, 2024-09-19](https://www.anthropic.com/news/contextual-retrieval)) [벤더]. 한·영 혼용(code-switched) 질의에서 다국어 IR은 불안정하다 ([arXiv 2409.00120](https://arxiv.org/abs/2409.00120v2), 2024) [1차] | 유사도로는 현행과 폐기를 구분하지 못한다 | 인덱스·임베딩 인프라가 추가된다 | MCP 또는 hook | [벤더]·[1차], 다른 코퍼스 |
| E. Basic Memory (태그 필터 MCP) | 필터는 결정적이지만 **필터를 부를지는 모델이 정한다** | `metadata_filters`는 대소문자 구분 정확 일치다. 다중 태그는 AND, OR는 `$in` ([Docs](https://docs.basicmemory.com/concepts/metadata-search), 조회 2026-10-14) [벤더] | 폐기·이동 처리는 문서에서 확인 못 함 | 검색 결과만 | MCP + 플러그인 | [벤더], 수치 없음 |
| F. Graphiti/Zep (시간축 KG) | 아니오. 색인 키를 LLM이 추출한다 | 사람이 단 키워드가 색인 키로 남는다는 보장이 없다 ([README](https://github.com/getzep/graphiti)) [벤더] | 무효 사실을 `valid_at`/`invalid_at` 기간과 함께 낸다. 「왜」 필드는 없다 ([Zep Facts v4](https://help.getzep.com/v4/facts.md)) [벤더] | 수집할 때마다 LLM 호출 | MCP | [벤더] |
| G. AWS AI-DLC DocumentKB | 아니오. 필터 동사가 없고 선택은 모델이 한다. 감사 요청은 아직 Open이다 ([#694](https://github.com/awslabs/aidlc-workflows/issues/694), 2026-08-01) [1차] | 태그를 「비신뢰 라벨」로 다룬다 ([08-knowledge.md](https://github.com/awslabs/aidlc-workflows/blob/main/docs/guide/08-knowledge.md)) [1차] | digest 바인딩과 tombstone은 있다. 문서 간 대체 관계 필드는 없다 [1차] | `list`/`show` 출력 | AI-DLC skill | [1차] |

E·F·G는 사람이 단 키워드를 모델 호출에 맡기거나(E), LLM으로 재해석하거나(F), 신뢰하지 않는다(G). 이 시나리오에서 가장 값진 신호를 결정적 단계에서 쓰는 것은 A뿐이다.

## 3. 이력 문서가 「맞게」 히트하려면

| 측정 | 수 | 함의 |
|---|---|---|
| 최신 문장이 이미 회수된 상태에서 낡은 경쟁 문장 하나를 섞음 | 정답률 Qwen2.5-7B 100%→44.6%, Qwen3-14B 100%→87.8% ([Poikarayil et al., NeurIPS 2026](https://neurips.cc/virtual/2026/169567)) [1차] | 폐기 문서를 **표지 없이** 현행 문서 옆에 주입하면 에이전트가 낡은 쪽을 따를 수 있다 |
| MemoryAgentBench FactConsolidation(262K, 단일 홉 갱신 추적) | HippoRAG-v2 54% · BM25 48% · Mem0 18% · Zep/Graphiti 7%. 판 순서를 프롬프트에 명시한 구조적 조립은 82%였지만 LongMemEval에서는 유의한 이점이 없었다 ([Reddy & Challaram, arXiv 2606.01435 v2, 2026-08-02](https://www.alphaxiv.org/abs/2606.01435.md)) [2차 재인용] | 시간축 그래프라는 구조만으로는 갱신을 따라가지 못한다. 판 메타데이터를 **명시**했을 때 올랐다 |

**함의(추론):** 이력은 숨기지 않는다. 대신 주입 텍스트 **자체**에 `status: rejected|superseded`, 대체 문서, 사유 한 줄을 박아 현행 문서와 구분되게 싣는다. 이력 주입 여부에 따라 기각안을 다시 시도하는 비율이 달라지는지 잰 측정은 없다.

**BMAD 고리 정정:** 앞선 조사에서 미확인으로 남겼던 「BMAD 구현 세션이 memlog의 기각 이력을 읽는가」는 부정으로 닫힌다. bmad-spec은 *"Do not list the memlog … process metadata that downstream consumers don't need"*, *"never read it back except to resume"*라고 적는다 ([bmad-spec SKILL.md, main 마지막 커밋 2026-09-29](https://github.com/bmad-code-org/BMAD-METHOD/blob/main/skills/bmad-spec/SKILL.md)) [1차]. 이 판정은 문서 문장에 근거한 것이고 실행해 확인하지는 않았다.

## 4. hit율을 깎는 요인

| 요인 | 근거 | A에서의 처리 |
|---|---|---|
| 표기 변이(겐트리/갠트리/gantry) | 정확 일치 필터는 표기 변이를 흡수하지 않는다(E) [벤더]. 동의어 확장은 recall을 올리고 정밀도 하락이 유의하지 않았다. 상위어 확장은 정밀도 하락이 유의했다 ([Greenberg, JASIST 2001](https://ideas.repec.org/a/bla/jamist/v52y2001i5p402-415.html)) [1차] | 정본 ID 하나에 동의어 목록을 둔다. 작성 시 검사하고 질의 시 정규화한다. 확장은 동의어까지만 |
| 태그 누락·과광역 태그(`outbound`) | 태그 매칭은 누락을 원리적으로 잡지 못한다. 과광역 태그는 precision을 떨어뜨린다(추론) | 누락은 평가셋으로만 드러난다. 과광역 태그는 OR/AND 선택으로 다룬다(질문 2) |
| 모델이 안 봄 | skill 50–55% vs forced hook 100%(22문항×2, Sonnet 4.5) [일화]. 같은 저자의 앞선 글은 20%/84%여서 서로 어긋난다 [미검증]. 공식 문서도 매번 지켜야 할 규칙은 hook으로 옮기라고 한다 ([Skills](https://code.claude.com/docs/en/skills)) [1차] | hook이 목록을 강제로 넣는다. 목록에서 실제 Read로 이어지는 비율은 아직 아무도 재지 않았다 |
| 10,000자 상한 | 넘으면 파일로 빠지고 앞 2,000자 미리보기만 들어간다. Claude에게 그 파일을 읽으라고 시키지 않으며 상한은 설정으로 못 올린다. 기본 30초 timeout에 걸리면 주입이 버려진다. 명령형 문구는 prompt-injection 방어에 걸릴 수 있다 ([Hooks](https://code.claude.com/docs/en/hooks)) [1차] | 본문이 아니라 목록만 넣고 사실형 문장으로 쓴다. `onFailure: "block"` |
| compaction | hook이 넣은 문맥은 요약에 녹는다. 다시 넣는 결정적 수단은 `SessionStart`의 `compact` matcher hook뿐이다 ([Context window](https://code.claude.com/docs/en/context-window)) [1차] | 다음 요청에 키워드가 없으면 다시 주입되지 않는다. compact hook이 직전 목록을 재주입한다 |

## 5. 남은 미확인

1. hook이 주입한 목록 가운데 모델이 실제로 Read하는 비율. 공개 측정이 없다. `PostToolUse`(Read) 로그와 주입 목록을 대조하면 팀이 잴 수 있다 [1차 기제].
2. 기각 이력 주입이 기각안 재시도를 줄이는지. 측정이 없고 근거는 §3의 인접 측정과 일화뿐이다.
3. `UserPromptSubmit` 주입이 `Agent`로 띄운 subagent에게 넘어가는지. 재지 않았다. subagent의 시작 문맥은 `SubagentStart` hook이 맡는다는 것만 확인했다.

## 6. 사용자 결정 질문

1. 매핑 키워드를 정본 어휘 목록(정본 ID + 동의어)에서만 고르도록 강제할 것인가? 자유 입력을 허용하면 A의 recall 상한이 표기 변이만큼 깎인다.
2. 다중 키워드 요청("asrs, gantry")을 합집합(놓침 최소)으로 볼 것인가, 교집합(무관 문서 최소)으로 볼 것인가?
3. 본문 grep이나 embedding을 A에 덧붙이려 한다면 먼저 답할 호환성 질문이 있다. 결정적 목록과 확률적 후보를 한 주입 안에서 구분해 표기할 수 있는가, 그리고 평가셋 hit율을 따로 잴 수 있는가?
