# 루프 절차는 상태 파일과 hook이 쥔다

조사일 2026-10-16 · 라벨 [1차] 공식 문서 · [벤더] 자기 운영 보고 · [일화] 개인 SNS · [연구] 논문 · 「추론:」은 내 합성

## 1. 한 줄 결론

**순서·출구·형식·상태는 코드가, 생성·판단은 LLM이, 승인은 사람이 쥔다. 경계는 지시문이 아니라 「쓰기·턴 종료·머지」라는 행동에 긋는다.** 근거: Anthropic *"a request, not a guarantee … A PreToolUse hook that blocks the edit is enforcement"*([features-overview](https://code.claude.com/docs/en/features-overview.md), 열람 2026-10-16 [1차]) · OpenAI *"we promote the rule into code"*([Harness engineering](https://web.archive.org/web/20261012001826id_/https://openai.com/index/harness-engineering/), 2026-02-11 [1차·벤더]) · Stripe *"putting LLMs into contained boxes"*([Minions Part 2](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2), 2026-02-19 [1차]) · AWS AI-DLC *"routing … lives in a tool, never in LLM prose"*([17-skill-system](https://github.com/awslabs/aidlc-workflows/blob/main/docs/reference/17-skill-system.md), 2026-10-16 [1차]).

**적용: intake마다 `state.json` 하나를 단일 정본으로 두고 엔진 스크립트만 그 파일을 고친다. command hook이 그 상태를 보고 `topics/` 쓰기와 턴 종료를 판정하며, pre-commit과 CI가 같은 판정을 한 번 더 돈다.**

## 3. 권장 강제 구조 (Claude Code 원시 기제만 쓴다)

**단일 정본** `knowledge/intake/INT-…/state.json`은 엔진 스크립트만 쓴다.

```
stage: decompose|scan|interview|draft|verify|complete|parked
items[]:     {id, status: open|answered|na, source_ids[], na_reason}
lines:       {stated, inferred, missing}
conflicts[]: {kn_id, status: open|resolved, source_id}
questions[]: {qid, asked_at, answer_turn}
human_turns[]: {ts, kind: prompt|ask_answer, sha256}
verifier:    {draft_sha256, unsupported, round}
```

얇은 `/intake` skill은 `intake-engine next`로 directive를 받아 실행하고 `report`로 넘긴다. hook은 전부 project `.claude/settings.json`에 command·exec form으로 두고 `"onFailure": "block"`(v2.1.295+)을 건다([hooks](https://code.claude.com/docs/en/hooks.md) [1차]).

| 단계 | 기제 | 보장 | 출처 |
|---|---|---|---|
| 진행 판정 | `next`는 멱등·상태 불변, `report`가 스키마 검사 후 전이 커밋 | 결정적 | AI-DLC에서 직접 |
| ① 원문 저장 | UserPromptSubmit과 PostToolUse(AskUserQuestion)가 `sources/SRC-…`를 쓰고 ID 반환. 기존 `sources/` 파일 쓰기는 PreToolUse(Write·Edit·Bash·PowerShell) deny | 결정적(로컬) | 추론: AI-DLC의 `HUMAN_TURN` 기록 기제를 변형 |
| ②③ 분해·점검 | skill이 실행, 엔진이 항목 형식·`inferred` 수 검사 | 형식 결정적 · 내용 모델 | AI-DLC + Anthropic 「enum 인터페이스」(2026-07-24) |
| ④ 인터뷰 | 메인 대화 AskUserQuestion. 질문 뒤 기록된 human turn이 있어야 answered. 답한 qid 재질문은 엔진이 거부. 라운드 상한 없음 | 질문은 모델 · 주체 결속 결정적 · 답은 사람 | AI-DLC에서 직접. 재질문 거부는 추론(#1122 보완) |
| 상태 보호 | 엔진 밖의 `state.json` 편집을 PreToolUse가 deny | 결정적(로컬) | AI-DLC state-transition-guard |
| 턴 종료 | Stop hook이 `next` 호출: AI 몫 미완(분해 미완, 검증 미실행)이면 block, 사람 답 대기·`parked`·`done`이면 허용. `stop_hook_active` 확인 | 결정적, 8회 상한에 안 기댐 | AI-DLC에서 직접(carve-out·park) |
| ⑤ 독립 검증 | 검증자 subagent(`tools: Read, Grep, Glob`, `omitClaudeMd`) 판정 → SubagentStop hook이 판정 JSON을 `draft_sha256`과 함께 기록. 3라운드 초과 시 사람에게 | 판정 모델 · 기록·결속 결정적 | 추론: Anthropic 생성자/평가자 분리 + 커밋 결속 + 3라운드 |
| `topics/` 쓰기 | PreToolUse는 stage=complete · 판정 해시=현재 초안 · unsupported 0 · inferred 0 · open conflict 0 · 전 item answered/na일 때만 허용 | 결정적(로컬) | Anthropic 문서 권고 + AI-DLC fingerprint |
| 세션 재개 | SessionStart(startup·resume·compact)가 미완 intake·남은 빈칸 수 주입 | 주입은 결정적 · 활용은 모델 | 기결정 |
| 최종 방어 | 같은 `intake-engine check`를 pre-commit·CI 필수 체크에서(`sources` 해시 불변, `topics` 파일마다 complete intake) | 결정적(서버) | Anthropic SDLC(하드 게이트는 CI) [벤더] |
| ⑥ 사람 승인 | branch protection + CODEOWNERS(`knowledge/topics/**`), 새 커밋 시 기존 승인 무효 | 사람 | Anthropic code review 「승인은 커밋에」 [벤더] |
| 코딩 루프 ID | CI가 `근거: KN-…`/`미결: INT-…` 실존 확인, superseded·rejected면 경고 | 결정적 | 추론: OpenAI KB lint 선례 |
| 표시 없는 결정 | 검증자 | 모델 | 위치 미정(§5) |

추론: hook·pre-commit·CI가 같은 엔진을 부르면 세 지점이 어긋날 수 없다.

## 4. 함정과 한계

- **Stop 연속 8회 상한**: 연속 8회 계속시킨 뒤의 block은 무시되고 턴이 끝난다. 사람 대기는 허용(park)으로 처리한다([hooks](https://code.claude.com/docs/en/hooks.md) [1차]).
- **hook은 기본 fail-open**: 실패·타임아웃이면 통과. `onFailure: "block"`은 v2.1.295+이고 prompt/agent hook 적용 여부는 문서에 없다(같은 문서).
- **agent hook은 실험적**: 2.1.300 전엔 모델 불가 시 허용으로 빠졌다([CHANGELOG](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md) [1차]). 판정은 subagent, hook은 기록만 검사.
- **skill frontmatter hook은 세션 끝까지 남는다**(스킬 실행 중만이 아님). `once: true`를 쓰거나 게이트는 settings에 둔다([hooks](https://code.claude.com/docs/en/hooks.md) [1차]).
- **인터뷰는 메인 대화에서만**: subagent는 AskUserQuestion 불가([sub-agents](https://code.claude.com/docs/en/sub-agents.md) [1차]), workflow는 *"No mid-run user input"*이다([workflows](https://code.claude.com/docs/en/workflows.md) [1차]).
- **Claude 5 모델은 Task 도구가 기본 꺼짐**: TaskCompleted 게이트엔 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` 필요([tools-reference](https://code.claude.com/docs/en/tools-reference.md) [1차]). 진척은 `state.json`에.
- **Windows는 sandbox 없음**: PowerShell·하위 프로세스 쓰기는 `Write|Edit` matcher를 안 지난다([sandboxing](https://code.claude.com/docs/en/sandboxing.md) · [hooks-guide](https://code.claude.com/docs/en/hooks-guide.md) [1차]). `Bash|PowerShell`을 더해도 최종 보장은 pre-commit·CI.
- **로컬 hook은 우회 가능**: `disableAllHooks`·`--safe-mode`, user mod가 비관리 hook과 (비관리 머신의) deny를 덮음([mods/events](https://code.claude.com/docs/en/plugins/mods/events.md) [1차]).
- **에이전트 간 검토는 수렴하지 않을 수 있다**: Anthropic 3라운드 상한(50라운드 초과 사례 [벤더]). 새 검증자는 섀도 모드로 먼저 돌려 사람 판정과 대조한다(SDLC 글).
- 추론: 불완전한 `state.json` 대조군으로 deny가 실제로 뜨는지 시험한다 — 필드 위치가 틀리면 오류 없이 무시된다([hooks-guide](https://code.claude.com/docs/en/hooks-guide.md) [1차]).

## 5. 남은 결정 질문

1. **「표시 없는 결정」 검증자를 어디에 둘까?** 로컬 Stop+subagent는 빠르나 우회 가능, PR CI는 우회 불가하나 늦다. Anthropic은 PR 전 subagent와 CI 하드 게이트를 둘 다 쓴다 [벤더].
2. **Agent SDK 바깥 루프를 쓸까, 세션 안 hook으로 갈까?** SDK는 순서를 원리적으로 강제하나 대화형 UX를 잃고 인터뷰 UI를 새로 만들어야 한다. 세션 안 hook은 AI-DLC의 운영 형태다.
3. **엔진 범위를 어디까지 잡을까?** AI-DLC식 전 단계 라우팅(복잡도 큼) 대 Intercom식 출구 게이트(`topics/` 쓰기·Stop)만.
