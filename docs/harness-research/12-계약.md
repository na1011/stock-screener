# 협의 도서관 하네스 — 계약

이 파일은 하네스의 **형식과 동작 규칙의 정본**이다. 코드·skill·문서는 이 계약을 따른다. 본문의 P1~P8은 Claude Code 2.1.301에서 실측한 결과다.

## 0. 원칙
- 목적은 **사람과의 질의응답으로 문서 작성·저장을 자동화**하는 것이다. AI는 입력의 **내용**에서 빠진 함의를 고정 항목(3.2)과 스스로의 판단(역질문)으로 찾아 최대한 묻는다. 문서의 종류(회의록·명세 등)는 묻지 않는다 — 도서관은 키워드별 정리본으로 묶인다.
- 규칙의 위치: **반드시 일어나야 하는 것**(고정 항목 싣기·질문 등록·모든 질문이 닫혀야 입고)은 hook과 엔진이 강제한다. **판단 기준**(빈칸 찾는 법·역질문·충돌 제기·지어내지 않기)은 입력 절차 skill에 두고, 기록 입력이 오면 hook이 강제로 붙인다. CLAUDE.md에는 코딩할 때 항상 걸려야 하는 한 줄(「협의에 없는 결정은 지어내지 않는다」)만 둔다.
- 관문은 **AI의 쓰기**만 본다. 사람의 git 작업(커밋·push·브랜치)과 편집기 수정은 막지 않고, 주 1회 팀 리뷰(7절 보고서)가 본다.

## 0-1. 전제
- 대상: Claude Code ≥ 2.1.295(입고 관문의 `onFailure`), Windows 11 / macOS / Linux. transcript 저장이 켜져 있어야 한다(실행 버전 확인, 6.0).
- 실행: Python ≥ 3.10, **표준 라이브러리만**. Windows는 `py -3`, 그 밖은 `python3`.
- 도서관은 main에 바로 커밋한다.
- 판: `.claude/harness/VERSION`.

## 1. 디렉토리

```

.gitignore                        # knowledge/intake/ · __pycache__/ · knowledge/**/.tmp-*
.gitattributes                    # 하네스 경로만 LF(knowledge/** · .claude/harness/** · docs/harness/**)

  sources/       SRC-*.md         # 입력 원문·질의응답 답변 그대로 (hook만 씀, 고치지 않음)
  vocabulary/    <키워드>.md       # 정본 키워드 (키워드 하나 = 파일 하나)
```

hook은 하네스 전용 폴더(`.claude/harness/hooks/`)에 둔다 — 프로젝트의 `.claude/hooks/`와 이름이 겹치지 않게.

## 2. ID
`<접두>-YYYYMMDD-XXXXXX` — XXXXXX는 무작위 6자(영대문자·숫자, 혼동 문자 0·O·1·I 제외). 접두: `KN`(주제 문서) · `SRC`(원문) · `INT`(작성 중). 파일 이름 = ID. 여러 PC가 따로 뽑으므로 6자(하루 32⁶)로 둔다.
- **새 주제 문서의 ID는 hook이 뽑아 둔다**(intake마다 3개, `kn_ids`). AI는 그중에서 쓴다 — AI가 지어낸 「무작위」는 무작위가 아니다.

## 3. 파일 형식

frontmatter는 **엄격한 부분 문법**만 허용한다: `key: value`, `key: [a, b]`(한 줄 목록), 빈 값. 키는 소문자·숫자·`_`·`-`. 그 밖의 YAML은 **파싱 실패로 크게 알린다**. 한 파일이 깨져도 다른 파일의 판정은 계속된다(깨진 파일은 목록·보고서에 이름으로 나온다).

### 3.1 키워드 `knowledge/vocabulary/<id>.md`
```
---
id: devanning              # 소문자·숫자·하이픈. 파일 이름과 같음
label: 디베이닝
aliases: [디배닝, devan, 컨테이너 하역]    # 입력에서 이 표기도 같은 키워드로 인식
---
설명 한두 줄.
```
- 입력의 키워드는 쉼표로 나누고, 통째로 안 맞을 때만 띄어쓰기로 나눈다(띄어 쓴 별칭이 먼저).
- 두 키워드가 같은 별칭을 쓰면 그 별칭은 인식하지 않고 알린다.

### 3.2 고정 항목 `knowledge/checklists/base.md`
모든 기록 입력에 실린다. 항목 줄은 `- <id> <이름>: <묻는 것>`. 바꾸면 그 뒤에 시작한 기록 입력부터 적용된다.
```
- G1 시점·트리거: 언제, 어떤 이벤트로 시작하나
- G2 입력 데이터 출처: 현장 스캔·사전 I/F·마스터 중 무엇인가
- G3 기준값 출처: 기준·임계값이 마스터·설정·협의값 중 어디서 오나
- G4 정상 흐름: 단계 순서와 완료 조건
- G5 예외·실패 처리: 실패·초과·불일치 시 어디로 보내고 누가 해제하나
- G6 판정·책임 주체: 누가 판정하고 결과를 어디에 남기나
- W1 처리 단위: 팔레트·케이스·낱개·SKU 중 무엇인가
- W2 위치·구간: 어느 스테이션·로케이션·라인인가
- W3 연계 시스템 데이터: WMS·WCS·설비 PLC·ERP와 무엇을 주고받나(I/F 항목)
- W4 수량·용량·처리 능력: 버퍼 용량, 시간당 처리량
- W5 우선순위·순서: 작업 우선순위, FIFO, 긴급 처리
- W6 상태 변화: 재고·작업 상태가 무엇에서 무엇으로 바뀌나
- W7 이상 상황 운영: 설비 고장·통신 단절 시 수동 운영과 복구
```
- **AI의 역질문:** 고정 항목 밖이라도 AI가 빈칸이라 판단하면 질문을 추가한다(`[Q-xx · 추가]`). 추가 질문은 항목 `A-xx`로 등록되어 **입고 기준에 들어간다.** AI는 항목을 더할 수 있지만 고정 항목을 뺄 수 없다.

### 3.3 원문 `knowledge/sources/SRC-*.md` — hook만 쓴다
```
---
id: SRC-20261017-AB2C3D
kind: input                # input(사람의 입력) | answer(질의응답 답)
intake: INT-20261017-K8WD7Q
question: Q-03             # answer일 때만
item: G2                   # answer일 때만
keywords: [inbound, devanning]
received: 2026-10-17T10:12:03+09:00
---
> [Q-03 · G2] 팔레트 식별은 현장 스캔인가요, 사전 I/F인가요?     # answer일 때만 — 리뷰 PC에는 state.json이 없다
(사람이 입력한 원문·답 그대로 — 대화상자에서 고른 선택지는 「라벨 — 설명」, 사람은 둘을 함께 보고 고른다)
```

### 3.4 주제 문서 `knowledge/topics/KN-*.md`
```
---
id: KN-20261017-7K3Q9P
title: 디베이닝 투입 전 입고 팔레트 중량 판정      # 대상·논점. 설비를 강제하지 않음
keywords: [inbound, devanning]
status: active             # active | rejected
supersedes: []             # 이 문서가 대체하는 KN id
---
## 규칙

- 판정 위치: 디베이닝 투입 직전 계량 컨베이어 CV-21 ← SRC-20261017-AB2C3D

- 기준: 품목 마스터 기준중량 ±3kg ← SRC-20261020-Q9ZT4K
  - 변경 2026-10-20: ±2kg → ±3kg · 설비사B 센서 사양 ← SRC-20261020-Q9ZT4K

## 미정

- W4 수량·용량: 계량 구간 버퍼 용량과 시간당 처리량 ← SRC-20261017-AB2G7M

## 해당 없음

- W7 이상 상황 운영: 설비가 자체 복구, 수동 운영 없음 ← SRC-20261017-AB2F8N
```
- **본문 문법(엄격):** 절 제목은 `## 규칙` · `## 미정` · `## 해당 없음` · `## 기각`만. 절 안에는 빈 줄, `- … ← SRC-…` 줄, 규칙 줄 바로 아래의 `  - 변경 YYYY-MM-DD: 전 → 후 · 사유 ← SRC-…` 줄만 둔다. 문단·표·`*`·번호 목록·다른 제목·git 충돌 표시는 위반이다 — 검사가 못 보는 줄이 생기지 않게.
- **근거 줄**(위 `- ` 줄 전부)은 끝에 실재하는 `SRC-…`(하나 이상)를 단다. `[추론]`(전각 괄호 포함)은 남기지 않는다.
- active 문서는 `## 규칙` 줄이 하나 이상. rejected 문서는 `## 기각` 절에 `- 사유: … ← SRC-…`.
- **변경 이력**은 지우지 않는다. **바뀜**은 저장하지 않고 계산한다: 다른 active 문서의 `supersedes`에 들어 있으면 바뀜.
- **미정 줄**은 항목 id로 시작한다. 개발 요청 목록과 같은 키워드의 기록 입력에 `미정 n: …`으로 실려, AI가 「이 입력이 그 미정을 정하는가」를 사람에게 확인한다. 정해지면 그 줄을 `## 규칙`으로 옮기고 `  - 변경 날짜: 미정 → 결정 · 사유 ← SRC-…`를 단다.
- 코드에서 미정을 기다리는 지점은 `미결: KN-… · <항목 id>` — 공유된 문서를 가리킨다(INT는 각자 PC에만 있다).
- frontmatter에 수정마다 바뀌는 값(어느 입력이 고쳤나, 고친 날)을 두지 않는다 — 같은 문서를 두 사람이 고치면 그 줄이 늘 충돌한다. 그 정보는 근거 줄의 SRC와 git이 준다.
- 같은 문서의 같은 자리에 두 사람이 동시에 줄을 더하면 git 충돌이 난다(빈 줄은 떨어진 자리의 수정만 자동 병합한다, P7). 충돌 표시가 커밋돼도 다른 문서의 판정은 계속되고, 그 문서는 보고서의 형식 위반에 뜬다. 표시를 지워 고친 Write는 관문이 받는다.

### 3.5 작성 중 `knowledge/intake/INT-*/state.json` — hook만 쓴다
```json
{
  "id": "INT-20261017-K8WD7Q",
  "session": "<session_id>",
  "keywords": ["inbound", "devanning"],
  "unknown_keywords": [],
  "sources": ["SRC-20261017-AB2C3D"],
  "items": {"G1": {"status": "open", "sources": [], "text": "시점·트리거: 언제, …"}, "A-01": {"status": "open", "sources": [], "text": "<역질문 문장>"}},
  "questions": {"Q-01": {"item": "G1", "text": "...", "answer_source": null}},
  "kn_ids": ["KN-20261017-7K3Q9P", "…", "…"],
  "created": "2026-10-17T10:12:03+09:00",
  "written": false
}
```
- `items[].status`: `open` | `answered` | `na` | `pending`. **사람의 답으로만 바뀐다.** 상태는 답이 라벨 `해당 없음`·`미정` 자체일 때만 na·pending이다(「미정이었던 것을 …로 확정」은 answered).
- 세션별 현재 intake: `knowledge/intake/.sessions/<session_id>` 파일에 INT id 한 줄. 마지막 연계 문서 목록은 같은 이름 `.list`(서브에이전트·압축 뒤 재주입용).
- 입고가 끝나면 `after.py`가 `"written": true`를 기록하고, 커밋할 정확한 파일 목록(그 문서 + 이번 intake의 원문)을 AI에게 준다 — 버린 입력의 원문은 올라가지 않는다.
- 사람이 `버리기:`하면 `"discarded": true` — 미완 알림과 입고에서 빠진다.

### 3.6 질문 형식
- 질문 문장은 `[Q-xx · <항목 id>] 질문` 형식이다. 예: `[Q-03 · G2] 팔레트 식별은 현장 스캔인가요, 사전 I/F인가요?` (P1: 이 접두가 답의 키로 그대로 돌아온다). 역질문은 `[Q-08 · 추가] …`.
- 모든 질문에 선택지 `미정`과 `해당 없음`을 넣는다(선택지는 최대 4개라 내용 선택지는 2개). 자유 입력은 「Other」로 늘 가능하다.
- 같은 번호를 다른 질문에 다시 쓸 수 없다(한 호출 안에서도). 같은 질문을 다시 묻는 것은 된다.
- 대화상자가 시간 초과(`afkTimeoutMs`)로 닫히면 답으로 기록하지 않는다.
- `gate.py`가 형식을 검사하고(어긋나면 거부·사유), 질문을 상태 파일에 등록한다.

## 4. 사람이 입력하는 형식
- **기록 입력**: 첫 줄 `키워드: a, b` + 다음 줄부터 내용(회의록·협의·명세 무엇이든).
- **개발 요청**: `연계 키워드: a, b` 줄을 포함한 요청(다른 줄은 자유 형식).
- **일반 대화로 답하기**: `Q-03: 답 내용`(여러 줄 가능 — 다음 `Q-xx:`까지가 한 답).
- **이어서 하기**: `이어서: INT-…` — 다른 세션에서 시작한 기록 입력을 이 세션의 현재 intake로 잡는다.
- **버리기**: `버리기: INT-…` — 사람만 입력할 수 있다.
- 키워드는 정본 id·label·aliases로 인식한다. 모르는 키워드는 알리고 정본 목록을 보여 준다.

## 5. hook 동작

| 스크립트 | 이벤트 | 하는 일 | 실패 시 |
|---|---|---|---|
| `prompt.py` | UserPromptSubmit | ① 기록 입력 → 목록을 먼저 만들고 INT 생성(고정 항목 실음)·원문 저장·세션의 현재 intake 지정, 입력 절차 skill·항목·같은 키워드 문서(미정 포함)를 붙임 ② 개발 요청 → 연계 문서 목록(5.1) ③ `Q-xx:` 답 기록 ④ `이어서:`·`버리기:` | 열림 |
| `gate.py` | PreToolUse (Write·Edit·MultiEdit·NotebookEdit·Bash·PowerShell·AskUserQuestion) | 입고 관문(6절) · 보호 경로 거부 · 셸 허용 목록 · 질문 형식 검사·등록 · 낮은 버전 1회 알림 | **닫힘**(`onFailure: block`) |
| `after.py` | PostToolUse (AskUserQuestion·Write·Edit·MultiEdit) | 대화상자 답 → 원문 저장·상태 갱신 · 입고 직후 커밋 명령 안내 · `knowledge/` 쓰기 직후 형식 알림 | 열림 |
| `subagent.py` | SubagentStart | 이 세션의 마지막 목록을 서브에이전트에 다시 넣음 | 열림 |
| `start.py` | SessionStart | 이 PC의 미완 intake 알림(startup·clear) · 재개·압축 뒤 현재 intake와 마지막 목록 재주입 | 열림 |
| `report.py` | 명령(`/weekly-review`) | 주간 리뷰 보고서(7절) | — |

- `settings.json`의 hook 등록은 `setup.py`가 만든다. 하네스 항목은 **실행 대상이 `.claude/harness/hooks/` 안**인 것으로 판정하고, 그 밖의 hook·설정은 그대로 둔다. 커밋되는 판은 Windows(`py -3`).
- 모든 hook은 `-c` 부트스트랩으로 호출한다(스크립트가 없으면 exit 1 — 프롬프트를 막지 않음, P6). 열린 hook의 판정 불가는 `systemMessage`로 사람에게 알린다.
- 출력은 ASCII 이스케이프 JSON(P5), 한 번에 하나. 읽기 `utf-8-sig`, 쓰기 `utf-8`·LF·원자적(Windows에서 파일이 잠겨 있으면 잠시 다시 시도).
- 프로젝트 루트는 `CLAUDE_PROJECT_DIR`(hook 입력의 cwd는 AI의 `cd`를 따라간다). 없으면 cwd의 git 루트. 둘 다 못 찾으면 `knowledge`·`.claude`를 건드리는 호출만 막는다.

### 5.1 개발 요청 목록
- 매칭: 요청 키워드와 문서 `keywords`의 **합집합**, 일치 개수 내림차순 → 상태(유효, 바뀜, 기각) → 최근 문서(ID 날짜) 순.
- 한 줄: `- KN-… · [유효|바뀜|기각] · 일치 n/m · 제목 · 대체함/대체됨 · 기각 사유 · 미정 n: … · 변경 n회`.
- 머리말: 「관련 문서를 골라 읽어라 · 목록 밖도 필요하면 검색 · 바뀜·기각된 안은 다시 시도하지 않는다 · 주제 문서와 설계 정본이 어긋나면 주제 문서를 따른다 · 결정 지점에 `근거: KN-…`, 미정을 기다리는 지점에 `미결: KN-… · <항목>`」.
- 7,000자를 넘으면 사람에게 경고(`systemMessage`)와 정리 권고. 9,000자에서 순서대로 싣고 나머지 건수 표시.
- 설계 정본 skill(`keywords`가 달린 `design-*`)도 같은 매칭으로 목록 맨 위에 「설계 정본: skill …」으로 싣는다. 형식이 깨진 문서·skill은 이름으로 알린다.

## 6. 입고 관문 (판단기준 3·4)
AI의 `knowledge/topics/` 쓰기는 **Write(문서 전체)만** 받는다 — Edit은 따옴표·이스케이프를 정규화해 다시 찾으므로 관문이 적용 결과를 같게 계산한다고 보장할 수 없다. Write는 **아래를 모두 만족할 때만 허용**한다.

0. 실행 중인 Claude Code가 최소 버전 이상이다 — transcript의 `"version"`으로 읽는다(실측: SessionStart·UserPromptSubmit 때는 transcript가 아직 없고 PreToolUse부터 있다. PATH의 `claude`는 실행 중인 것과 다를 수 있다). 미만이거나 읽지 못하면 거부.
1. 이 세션의 현재 intake가 있다(버리지 않은).
2. 그 intake의 모든 항목(고정 + 역질문 `A-xx`)이 닫혔다(`answered`·`na`·`pending` — 모두 사람의 답).
3. 형식(3.4)을 지킨다. 새 문서의 ID는 그 intake의 `kn_ids` 중 하나다. 문서 키워드가 intake 키워드와 하나 이상 겹친다.
4. **바뀐 내용이 이번 입력의 사람 답에 묶였다** — 옛 판과 절 단위로 비교해서:
   - 더해지거나 바뀐 근거 줄마다 이번 intake의 원문이 붙어 있고, 그 원문이 절에 맞는 답이다: `## 규칙`·`## 기각` ← 답·입력 원문, `## 미정` ← 미정 답, `## 해당 없음` ← 해당 없음 답.
   - 변경 이력 줄은 지울 수 없다. 줄을 지우기만 할 수는 없다(바꾼 줄과 함께만).
   - frontmatter(title·keywords·status·supersedes)만 바꿀 수 없다.
   - 옛 판이 깨져 있으면(충돌 표시) 원문 전체를 옛 본문으로 본다 — 병합을 고치는 쓰기가 막히지 않게.

거부할 때는 남은 항목·위반을 사유에 적는다(AI가 이어서 질문하거나 고치도록).

**보호 경로** — AI의 쓰기 도구는 항상 거부:
- `knowledge/sources|intake|checklists/`(원문·상태는 hook만, 고정 항목은 사람만).
- 하네스 자체: `.claude/harness/**`, `.claude/settings.json`, `.claude/settings.local.json`, 하네스 skill 셋, `review-checker` agent — AI가 고치면 관문을 끌 수 있다. 사람이 `install.py`로만 바꾼다.
- `knowledge/vocabulary|templates/`와 `design-*` skill은 허용하고 쓴 직후 형식을 알린다(설계 정본 변경은 주간 보고서에 뜬다).

**셸** — Bash·PowerShell 명령이 `knowledge`나 `.claude` 낱말을 품으면 아래만 허용한다. 경로 표기 변형(`./`, 글롭, 따옴표, 중괄호)을 일일이 쫓지 않고 형태로 가른다:
- 메타문자(`| & ; < > $ ( ) { } * ? !`·백틱·줄바꿈)가 없는 `git add|commit|status|log|diff|show|push|pull|fetch|grep|ls-files|blame|rev-parse|branch` — `&&`로 이을 수 있고 따옴표 안(커밋 메시지)은 보지 않는다. 파일을 쓰거나 명령을 띄우는 옵션(`-O`, `--output`, `--upload-pack`, `--receive-pack`, `--exec`, `--ext-diff`)은 안 된다.
- `py -3|python3 .claude/harness/hooks/report.py [--days N] [--out docs/harness/reviews/<이름>.md]`.
- 읽기는 Read·Grep·Glob 도구로 한다.
- **막지 못하는 것:** 경로를 글자로 쓰지 않는 우회(다른 곳에 스크립트를 만들어 실행, 설정 파일을 거친 간접 실행). 입력 절차가 우회를 금지하고 주간 보고서가 형식·근거를 다시 본다.

## 7. 주간 리뷰 보고서 (`/weekly-review`)
범위는 **지난 보고서가 적어 둔 기준 커밋 ~ 지금 HEAD**(커밋 날짜가 아니라 main에 들어온 순서 — 늦게 push된 변경·병합 커밋이 빠지지 않게). 지난 보고서가 없으면 `--days`(기본 config). 보고서 끝에 `기준 커밋: <HEAD>`를 적고, 보고서를 커밋해 다음 범위의 시작으로 쓴다.
- 문서별 더해진·**지워진** 근거 줄, 더해진 줄의 원문 발췌(질문 문장 포함), 이름 바뀜·삭제
- 바뀐 설계 정본 skill
- 형식 위반(깨진 문서·충돌 표시·키워드 정본 문제 포함)
- 미정 항목과 언제부터인지
- 고쳐야 할 코드 주석: 바뀜·기각·없는 문서를 가리키는 `근거:`·`미결:`, 이미 풀린 미정을 기다리는 `미결:`, INT를 가리키는 주석, 항목 id 없는 `미결:` — 소스 파일을 직접 읽어 UTF-8·cp949 모두 본다. 구분자는 `·` `-` `/` `,`
- 미결 주석(미정을 기다리는 코드)
- (선택) `review-checker` 서브에이전트가 「원문에 없는 내용」 의심 줄을 표시
보고서는 막지 않는다. 리뷰 시간에 위에서부터 본다.

## 9. 설치·업그레이드 (`install.py`)
- 하네스 소유 파일은 새 판으로 바꾼다. 설치 때 해시를 `.claude/harness/MANIFEST.json`에 남기고, 다음 설치에서 해시가 다르면(손으로 고침) `<파일>.local-<날짜>`로 백업한 뒤 바꾼다. 새 판에서 빠진 파일은 고치지 않았으면 지운다.
- 팀 파일(`knowledge/`의 키워드·고정 항목·양식, `config.json`)은 있으면 둔다.
- `CLAUDE.md`(절을 붙임), `.gitignore`·`.gitattributes`(없는 줄만 더함), `settings.json`(하네스 항목만)은 합친다.
- `--posix`(macOS·Linux 개인 PC): `settings.json`이 이미 git에 있으면 이 PC만 `python3`판으로 바꾸고 skip-worktree. 아직 없으면 Windows판을 쓰고 「먼저 커밋한 뒤 다시 실행」을 안내한다.
