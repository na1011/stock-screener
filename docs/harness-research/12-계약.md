# 협의 도서관 하네스 — 계약 (WP1)

이 파일은 하네스의 **형식과 동작 규칙의 정본**이다. 코드·skill·문서는 이 계약을 따른다. 근거: 계획 `export-plan.md` v4, 스파이크 결과(P1~P8).

## 0. 전제
- 대상: Claude Code ≥ 2.1.295(입고 관문의 `onFailure`), Windows 11 / macOS / Linux.
- 실행: Python ≥ 3.10, **표준 라이브러리만**. Windows는 `py -3`, 그 밖은 `python3`.
- 사람의 git 작업(커밋·push·브랜치)은 막지 않는다. 도서관은 main에 바로 커밋한다. 검증은 주 1회 팀 리뷰(보고서 명령이 돕는다).
- `bundle_version`: `.claude/harness/VERSION` (첫 판 `0.1.0`).

## 1. 디렉토리

```
CLAUDE.md
.gitignore                       # knowledge/intake/ 포함
.gitattributes                   # *.md *.json *.yml text eol=lf
knowledge/
  topics/        KN-*.md         # 도서관 본체: 완성 문서만 (개발 요청 때 목록에 실림)
  sources/       SRC-*.md        # 입력 원문·질의응답 답변 그대로 (hook만 씀, 고치지 않음)
  vocabulary/    <키워드>.md      # 정본 키워드 (키워드 하나 = 파일 하나)
  checklists/    <범주>.md        # 범주별 점검표
  templates/                     # 주제 문서 양식

.claude/

docs/harness/    사용자 가이드 · Windows 온보딩
```

## 2. ID
`<접두>-YYYYMMDD-XXXX` — XXXX는 무작위 4자(영대문자·숫자, 혼동 문자 0·O·1·I 제외). 접두: `KN`(주제 문서) · `SRC`(원문) · `INT`(작성 중). 파일 이름 = ID. 같은 ID가 이미 있으면 다시 뽑는다.

## 3. 파일 형식

frontmatter는 **엄격한 부분 문법**만 허용한다: `key: value`, `key: [a, b]`(한 줄 목록), 빈 값. 그 밖의 YAML(여러 줄 목록, 들여쓰기 맵 등)은 **파싱 실패로 크게 알린다**(조용히 건너뛰지 않음).

### 3.1 키워드 `knowledge/vocabulary/<id>.md`
```
---
id: devanning              # 소문자·숫자·하이픈. 파일 이름과 같음
label: 디베이닝
aliases: [디배닝, devan]    # 입력에서 이 표기도 같은 키워드로 인식
category: equipment        # 점검표 범주 id
---
설명 한두 줄.
```

### 3.2 점검표 `knowledge/checklists/<category>.md`
```
---
id: equipment
title: 설비 연계
---
- C-01 시점·트리거: 언제, 어떤 이벤트로 시작하나
- C-02 데이터 출처: 식별·수량 정보가 현장 스캔인가, 사전 I/F인가, 마스터인가
...
```
항목 줄은 `- C-xx 이름: 묻는 것` 형식. 범주가 여럿인 입력은 범주들의 항목을 합친다(id 앞에 범주를 붙여 구분: `equipment/C-01`).

### 3.3 원문 `knowledge/sources/SRC-*.md` — hook만 쓴다
```
---
id: SRC-20261017-AB2C
kind: input                # input(사람의 입력) | answer(질의응답 답)
intake: INT-20261017-K8WD
question: Q-03             # answer일 때만
keywords: [inbound, devanning]
received: 2026-10-17T10:12:03+09:00
---
(사람이 입력한 원문 그대로)
```

### 3.4 주제 문서 `knowledge/topics/KN-*.md`
```
---
id: KN-20261017-7K3Q
title: 디베이닝 투입 전 입고 팔레트 중량 판정      # 대상·논점. 설비를 강제하지 않음
keywords: [inbound, devanning]
status: active             # active | rejected
supersedes: []             # 이 문서가 대체하는 KN id
intakes: [INT-20261017-K8WD]
updated: 2026-10-17
---
## 규칙

- 판정 위치: 디베이닝 투입 직전 계량 컨베이어 CV-21 ← SRC-20261017-AB2C, SRC-20261017-AB2D

- 기준: 품목 마스터 기준중량 ±3kg ← SRC-20261020-Q9ZT
  - 변경 2026-10-20: ±2kg → ±3kg · 설비사B 센서 사양 ← SRC-20261020-Q9ZT

## 해당 없음

- equipment/C-10 운전 모드: 자동 운전만 존재 ← SRC-20261017-AB2F
```
- **규칙 줄**은 `- `로 시작하고 끝에 `← SRC-…`(하나 이상)를 단다. 규칙 줄 사이는 빈 줄(동시 작업 자동 병합, P7).
- **변경 이력**은 해당 규칙 줄 아래 들여쓴 `- 변경 날짜: 전 → 후 · 사유 ← SRC-…` 줄. 지우지 않는다.
- **바뀜**은 저장하지 않고 계산한다: 다른 active 문서의 `supersedes`에 들어 있으면 바뀜.
- `[추론]` 표시가 남아 있으면 안 된다.

### 3.5 작성 중 `knowledge/intake/INT-*/state.json` — hook만 쓴다
```json
{
  "id": "INT-20261017-K8WD",
  "session": "<session_id>",
  "keywords": ["inbound", "devanning"],
  "categories": ["equipment"],
  "mode": null,
  "sources": ["SRC-20261017-AB2C"],
  "items": {"equipment/C-01": {"status": "open", "sources": []}},
  "questions": {"Q-01": {"item": "equipment/C-01", "text": "...", "answer_source": null}},
  "created": "2026-10-17T10:12:03+09:00"
}
```
- `mode`: `new`(신규) | `change`(변경) | `reject`(기각 기록). **첫 질문 `Q-00`으로 사람에게 묻고 그 답으로 정한다.**
- `items[].status`: `open` | `answered` | `na`. **사람의 답으로만 바뀐다**(AI가 직접 바꿀 수 없음).
- 세션별 현재 intake: `knowledge/intake/.sessions/<session_id>` 파일에 INT id 한 줄.
- 입고가 끝나면(`topics/` 쓰기 성공) `after.py`가 `"written": true`를 기록한다 — 세션 시작 알림에서 빠진다.

### 3.6 질문 형식
- 질문 문장은 `[Q-xx · <항목 id>] 질문` 형식이다. 예: `[Q-03 · equipment/C-02] 팔레트 식별은 현장 스캔인가요, 사전 I/F인가요?` (P1: 이 접두가 답의 키로 그대로 돌아온다)
- `Q-00`은 입력 종류 질문이다: 선택지 `신규` / `변경` / `기각 기록`.
- 모든 질문에 선택지 `해당 없음`을 넣는다. 사람이 그것을 고르면 항목은 `na`, 다른 선택지나 자유 입력이면 `answered`.
- `gate.py`가 형식을 검사하고(어긋나면 거부·사유), 질문을 상태 파일에 등록한다.

## 4. 사람이 입력하는 형식
- **기록 입력**: 첫 줄 `키워드: a, b` + 다음 줄부터 내용(회의록·협의·명세 무엇이든).
- **개발 요청**: `연계 키워드: a, b` 줄을 포함한 요청(다른 줄은 자유 형식).
- **일반 대화로 답하기**: `Q-03: 답 내용`(대화상자 대신 직접 답할 때).
- 키워드는 정본 id·label·aliases로 인식한다. 모르는 키워드는 경고하고 정본 목록을 보여 준다.

## 5. hook 동작

| 스크립트 | 이벤트 | 하는 일 | 실패 시 |
|---|---|---|---|
| `prompt.py` | UserPromptSubmit | ① 기록 입력 → INT 생성, 원문(SRC) 저장, 세션의 현재 intake 지정, 입력 절차와 점검표를 붙임 ② 개발 요청 → 관련 문서 목록(아래 5.1) ③ `Q-xx:` 답 → SRC 저장, 상태 갱신 | 열림(프롬프트 통과) |
| `gate.py` | PreToolUse (Write·Edit·Bash·PowerShell·AskUserQuestion) | 입고 관문(6절) · `sources/`·`intake/` AI 쓰기 거부 · 질문 형식 검사·등록 | **닫힘**(`onFailure: block`) |
| `after.py` | PostToolUse (AskUserQuestion·Write·Edit) | 대화상자 답 → SRC 저장·상태 갱신 · `knowledge/` 쓰기 직후 형식 검사 결과를 AI에게 알림 | 열림 |
| `subagent.py` | SubagentStart | 이 세션의 마지막 목록을 서브에이전트에 다시 넣음 | 열림 |
| `start.py` | SessionStart (startup·resume·clear·compact) | Claude Code 버전 확인(2.1.295 미만 경고) · 이 PC의 미완 intake 알림 · 압축 뒤 마지막 목록 재주입 | 열림 |
| `report.py` | 명령(`/weekly-review`) | 주간 리뷰 보고서(7절) | — |

- 모든 hook은 `-c` 부트스트랩으로 호출한다(스크립트가 없으면 exit 1 — 프롬프트를 막지 않음, P6).
- 출력은 ASCII 이스케이프 JSON(P5). 읽기 `utf-8-sig`, 쓰기 `utf-8`·LF.
- 경로는 `/`로 정규화하고, 저장소 루트는 `git rev-parse --show-toplevel`로 정한다.

### 5.1 개발 요청 목록
- 매칭: 요청 키워드와 문서 `keywords`의 **합집합**, 일치 개수 내림차순 → 상태(active, 바뀜, rejected) 순.
- 한 줄: `- KN-… · [유효|바뀜|기각] · 일치 n/m · 제목 · 대체함/대체됨 · 사유`.
- 머리말: 「관련 문서를 골라 읽어라 · 목록 밖도 필요하면 검색 · 바뀜·기각된 안은 다시 시도하지 않는다 · 주제 문서와 설계 정본이 어긋나면 주제 문서를 따른다 · 코드의 결정 지점에 `근거: KN-…` 또는 `미결: INT-…`를 단다」.
- 7,000자를 넘으면 사람에게 경고(`systemMessage`)와 정리 권고. 9,000자에서 일치순 상위만 싣고 나머지 건수 표시.
- 설계 정본 skill(`keywords`가 달린 `design-*`)도 같은 매칭으로 목록 맨 위에 「설계 정본: skill …」으로 싣는다.

## 6. 입고 관문 (판단기준 3·4)
AI의 `knowledge/topics/` 쓰기(Write, 또는 Edit 적용 후 내용)는 **아래를 모두 만족할 때만 허용**한다.
1. 이 세션의 현재 intake가 있고, 쓰려는 문서의 `intakes`에 그 id가 있다.
2. intake의 `mode`가 사람의 답으로 정해져 있다.
3. `mode: new`이면 점검표 모든 항목이 `answered` 또는 `na`(둘 다 사람의 답).
   `mode: change` / `reject`이면 이번에 바뀐 규칙 줄마다 이 intake의 원문 ID가 붙어 있다.
4. 문서의 모든 규칙 줄에 실재하는 `SRC-…`가 붙어 있고, `[추론]`이 없고, frontmatter가 문법에 맞는다.

작성 중인 intake는 1~3을 만족하지 못하므로 같은 관문에 걸린다. 거부할 때는 남은 항목을 사유에 적는다(AI가 이어서 질문하도록).
- AI의 `sources/`·`intake/` 쓰기는 항상 거부(원문·상태는 hook만 쓴다).
- Bash·PowerShell 명령이 `knowledge/topics|sources|intake` 경로나 hook 스크립트를 가리키면 거부. 단 `git` 명령은 허용.
- 사람이 편집기로 직접 고치는 것은 막지 않는다(주간 리뷰가 본다).

## 7. 주간 리뷰 보고서 (`/weekly-review`)
지정 기간(기본 7일) git 이력에서 `knowledge/topics/` 변경을 모아:
- 문서별 바뀐 규칙 줄과 그 원문·질의응답 근거
- `해당 없음`으로 닫힌 항목과 그 답
- 원문 ID가 없거나 존재하지 않는 원문을 가리키는 줄
- 바뀜·기각 문서를 인용한 코드 주석(`근거: KN-…`), 미결 주석(`미결: INT-…`) 목록
- (선택) `review-checker` 서브에이전트가 「원문에 없는 내용」 의심 줄을 표시
보고서는 막지 않는다. 리뷰 시간에 위에서부터 본다.
