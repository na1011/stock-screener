## IMPORTANT — 쓰면 안 되는 엔드포인트

`fnlttSinglIndx.json`(단일회사 주요 재무지표)을 **쓰지 않는다.** 배제 사유가 셋이고 각각 단독으로 충분하다.

1. **계산된 비율을 반환한다.** 응답이 `idx_val`(지표값)이며 원본 계정이 아니다. `idx_cl_code`로 수익성(M210000)·안정성(M220000)·성장성(M230000)·활동성(M240000)을 고른다. spec §7의 "모든 지표는 원자료를 수집한 뒤 자체 계산"과 정면으로 충돌하며, `RawFinancialReport`에 비율 필드가 없는 것이 이를 타입 수준에서 막고 있다.
2. **2023년 3분기 이후만 제공한다.** 3년치 재무 이력(spec §7)을 만들 수 없다.
3. 두 시장(한국·미국)의 계산식을 통일한다는 목적 자체가 무너진다.

> 참고: 초기 메모에 있던 `fnlttCmpnyIndx.json`은 존재하지 않는 이름이다. 단일회사는 `fnlttSinglIndx.json`이다. 어느 쪽이든 위 사유로 쓰지 않는다.

## 1. 단일회사 주요계정 — `fnlttSinglAcnt.json` (채택)

한 번의 호출로 재무상태표(BS)와 손익계산서(IS)의 주요 계정을 모두 받는다.

**요청**

| 이름 | 필수 | 설명 |
|---|---|---|
| `crtfc_key` | Y | 인증키(40자리) |
| `corp_code` | Y | DART 고유번호(8자리). 종목코드가 아니다 |
| `bsns_year` | Y | 사업연도(4자리, 2015~) |
| `reprt_code` | Y | 보고서 코드 |

`reprt_code`: **`11011`** 사업보고서(연간) / **`11012`** 반기 / **`11013`** 1분기 / **`11014`** 3분기

`fs_div` 파라미터는 **없다.** 응답에 CFS(연결)와 OFS(별도)가 모두 담겨 오므로 소비 측에서 고른다.

**응답 필드** (실측으로 확인한 21개)

```
rcept_no, reprt_code, bsns_year, corp_code, stock_code,
sj_div, sj_nm, account_nm, fs_div, fs_nm, ord, currency,
thstrm_nm, thstrm_dt, thstrm_amount, thstrm_add_amount,
frmtrm_nm, frmtrm_dt, frmtrm_amount, frmtrm_add_amount,
bfefrmtrm_nm, bfefrmtrm_dt, bfefrmtrm_amount
```

- `sj_div`: 이 엔드포인트는 **`BS`(재무상태표)와 `IS`(손익계산서) 두 값만** 낸다. CIS/CF/SCE는 전체 재무제표 API에만 있다.
- `fs_div`: `CFS`(연결) / `OFS`(별도). **CFS 우선, 없으면 OFS 폴백** — 연결재무제표가 없는 회사가 있다.
- `thstrm_amount`: 당기 금액. **분기 보고서에서는 해당 분기 단독 금액**
- `thstrm_add_amount`: 당기 **누적** 금액. Q4 유도의 핵심
- `currency`: 통화(`KRW`)

**실측 — 삼성전자(00126380) 2025 사업보고서, CFS 기준 15개 계정**

| `sj_div` | `account_nm` | 값(2025) |
|---|---|---|
| BS | 유동자산 / 비유동자산 / **자산총계** | 자산총계 566.9조 |
| BS | 유동부채 / 비유동부채 / **부채총계** | 부채총계 130.6조 |
| BS | 자본금 / 이익잉여금 / **자본총계** | 자본총계 436.3조 |
| IS | **매출액** | 333.6조 |
| IS | **영업이익** | 43.6조 |
| IS | 법인세차감전 순이익 | 49.5조 |
| IS | **당기순이익(손실)** | 45.2조 |
| IS | 총포괄손익 | 51.3조 |

### 계정명 매핑

실측 결과 **삼성전자·KB금융·카카오·NAVER 네 회사 모두** `매출액`·`영업이익`·`당기순이익(손실)`·`자산총계`·`부채총계`·`자본총계`로 **일관**됐다. 금융지주(KB금융)도 `매출액`으로 나왔다 — 주요계정 API가 계정명을 정규화하는 것으로 보인다.

그래도 **후보군 집합으로 매칭한다.** 일관성이 확인된 것은 4개사뿐이고, 350종목에는 업종이 훨씬 다양하다.

| 목표 | 후보군 |
|---|---|
| revenue | `매출액`, `수익(매출액)`, `영업수익` |
| operatingIncome | `영업이익`, `영업이익(손실)` |
| netIncome | `당기순이익(손실)`, `당기순이익` |
| totalAssets | `자산총계` |
| totalLiabilities | `부채총계` |
| totalEquity | `자본총계` |
| currentAssets | `유동자산` |
| currentLiabilities | `유동부채` |
| retainedEarnings | `이익잉여금`, `이익잉여금(결손금)` |

아래 셋은 **응답에 원래 들어 있던 것**이다(위 실측표의 BS 행). 총계만 뽑고 버리고 있었을 뿐이라
호출 수도 응답 크기도 늘지 않는다. Altman Z-Score의 운전자본 항과 누적 수익성 항이 여기서 나온다.

**금융업은 유동/비유동을 구분하지 않는 재무상태표를 낸다.** 그 종목에서 `유동자산`·`유동부채`가
비는 것이 정상이며 null로 둔다 — 0으로 대체하면 운전자본이 0인 회사가 되어 값이 그럴듯하게 틀린다.
Altman Z는 애초에 금융업에 적용할 수 없는 지표이므로, 계산되지 않는 것이 옳은 결과다.

MUST: 매핑 실패를 **집계해 로그로 남긴다.** 대량 발생은 후보군을 보강해야 한다는 신호이며, 조용히 null로 두면 그 종목의 지표가 사라진 이유를 알 수 없다.

### 주의 — 숫자 파싱

금액이 **콤마 포함 문자열**이다: `"333,605,938,000,000"`. 음수는 `-` 접두. 빈 문자열(`""`)은 **null로 둔다 — 0으로 대체 금지**(0은 "값이 0"이라는 다른 사실이다).

### 주의 — 중복 행

실측에서 `당기순이익(손실)`이 **두 번** 나왔다(지배기업 소유주지분 / 비지배지분으로 추정되나 `account_nm`만으로는 구분되지 않는다). `ord` 오름차순 첫 행을 취하고, 중복이 사라지거나 3개 이상이 되면 알 수 있도록 로그를 남긴다.

### Q4 유도

**4분기 보고서는 존재하지 않는다.** 사업보고서(11011)가 연간 누계다.

```
Q4(손익) = 사업보고서 금액 − 3분기보고서의 thstrm_add_amount(누적)
```

실측(삼성전자 2025): 매출액 FY 333.6조 − 3Q누적 239.8조 = Q4 93.8조

**MUST: 손익(IS)만 차감한다. 재무상태표(BS)는 시점 잔액이므로 차감하면 안 된다** — 차감하면 자산총계가 음수가 된다. `sj_div`로 분기 처리한다.

## 2. 고유번호 — `corpCode.xml`

종목코드 → `corp_code` 매핑의 **유일한 공식 경로**.

- 요청: `crtfc_key` 하나
- 응답: **ZIP 바이너리**. 내부에 `CORPCODE.xml` 한 개
- 필드: `corp_code`(8자리), `corp_name`, `corp_eng_name`, `stock_code`(6자리, **상장사만 채워짐**), `modify_date`

**실측**: 3.5MB ZIP, 전체 118,664법인 중 `stock_code`가 있는 **상장사 3,925건**. 시드 15종목 전부 매핑 성공.

주의: **content-type이 `application/x-msdownload`**로 온다(`application/zip`이 아니다). 타입으로 분기하면 실패한다.

## 3. 발행주식수 — `stockTotqySttus.json`

주요계정에 발행주식수가 없으므로 PER·PBR에 필요하면 별도 호출한다.

- 요청: `crtfc_key`, `corp_code`, `bsns_year`, `reprt_code`
- **필드 계약은 §11-H**다. 자주 쓰는 것만: `se`(구분), `istc_totqy`(발행주식의 총수), `tesstk_co`(자기주식수), `distb_stock_co`(유통주식수)
- `se`가 보통주/우선주/합계로 나뉘므로 **행 선택 로직이 필요**하다. 값에 콤마가 포함된다.
- **감소 내역 넷(`redc`·`profit_incnr`·`rdmstk_repy`·`etc`)이 자사주 소각을 분해해 준다** — 발행주식수 배수로 분할 비율을 유도할 때 조용히 틀리는 자리다(§11-H·§10-B).

> v1 범위 판단: 초기 적재에서는 호출하지 않는다. 종목당 12콜이 이미 필요하고, 발행주식수는 `price_daily`가 아니라 `financial_statement.shares_outstanding`에 들어가므로 Phase 3에서 PER·PBR을 실제로 계산할 때 붙여도 늦지 않다.

## 4. status 코드 — HTTP 200과 함께 온다

**IMPORTANT — DART는 인증 실패도 HTTP 200으로 응답한다.** data.go.kr이 403을 주는 것과 정반대다. HTTP 상태코드만 보면 잘못된 키로 조회한 결과를 정상으로 오인한다. **`status` 필드 파싱이 필수다.**

| status | 의미 | → `Kind` |
|---|---|---|
| `000` | 정상 | — |
| `010` | 등록되지 않은 인증키 | `AUTH` |
| `011` | 사용할 수 없는 키(일시 중지) | `AUTH` |
| `012` | 접근할 수 없는 IP | `AUTH` |
| `013` | **조회된 데이터 없음** | `NOT_FOUND` |
| `014` | 파일이 존재하지 않음 | `NOT_FOUND` |
| `020` | 요청 제한 초과 | `RATE_LIMITED` |
| `021` | 조회 가능한 회사 개수 초과(최대 100) | `MALFORMED` |
| `100` | 필드의 부적절한 값 | `MALFORMED` |
| `101` | 부적절한 접근 | `AUTH` |
| `800` | 시스템 점검 중 | `TRANSIENT` |
| `900` | 정의되지 않은 오류 | `TRANSIENT` |
| `901` | 개인정보 보유기간 만료 키 | `AUTH` |

**실측 확인**: 없는 연도 조회 → HTTP 200 + `status 013`. 잘못된 키 → HTTP 200 + `status 010`.

## 5. 쿼터

**IMPORTANT — 한도는 계정 전체가 아니라 API별이다**(2026-08-11 사용자 제공, 미실측). 즉
`fnlttSinglAcnt`·`fnlttSinglAcntAll`·`company`·`fnlttMultiAcnt`가 **각자 자기 카운터를 쓴다.**
계정 합산으로 잡으면 실제로 도는 잡들을 근거 없이 서로 경쟁시키게 되고, 반대로 **한 엔드포인트에
쏠리는 잡 하나가 혼자 한도를 태우는 것**을 못 본다 — 실제 위험은 후자다.

| 값 | 출처 | 계획에 쓰는 값 |
|---|---|---|
| API당 일 **20,000**건 | 2차 출처 다수 + 사용자. 공식 문서에 명시를 찾지 못했다(status 020 설명에 "일반적으로는 20,000건 이상의 요청에 대하여") | **10,000 (절반)** |

**MUST: 착수 판단은 보수 예산 10,000으로 한다.** 20,000이 미실측이므로 그 값에 맞춰 짠 계획은
한도가 절반이면 그대로 깨진다. 절반으로 잡아 들어가면 실제 한도가 무엇이든 안전하고, 절반에서
넘치면 **그때가 폴백 비율을 실측하거나 날짜를 나눌 시점**이다.

- **분당 제한은 공식 문서에 없다.** 미검증이므로 보수적으로 간격을 둔다.

### 잡별 비용 (350종목 기준)

| 잡 | 엔드포인트 | 콜 | 보수 예산 대비 |
|---|---|---|---|
| 초기 적재 재무 3년 | `fnlttSinglAcnt` | 종목당 12 → **4,200** | 42% |
| `financial-refill` 3년 | `fnlttSinglAcnt` | 종목당 16 → **5,600** | 56% |
| P8 업종 | `company` | 종목당 1 → **350** | **3.5%** |
| P9 기업행위 (2020~오늘) | `irdsSttus` | 종목당 2 → **700** | **7%** |
| P10 연간 OCF (`11011`만) | `fnlttSinglAcntAll` | 종목당 6 → **2,100** | **21%** |
| P10 + `fs_div` 폴백 전량 | 〃 | 최대 **4,200** | **42%** |
| P10 §8 이익잉여금 (3종목) | 〃 | 3 × 24 → **72** | 0.7% |

**MUST: P10은 사업보고서(`11011`)만 부른다.** H-05의 가공법이
`sum(operatingCashFlow, 최근 5개 회계연도)`라 **분기가 필요 없다**(원본 명세 §H-05).
보고서 넷을 다 부르면 같은 일에 콜이 4배(8,400, 폴백 전량이면 16,800으로 보수 예산을 넘는다)가
되고, **그 4배는 아무 에러 없이 다른 잡의 여유를 먹는다.** 분기가 필요한 자리는 §8의
이익잉여금 결손 3종목뿐이고 그것은 종목으로 좁힌다.

**폴백 비율을 착수 전에 잴 이유가 없다.** 연간만이면 전량 폴백이어도 4,200으로 보수 예산의
42%다 — 순서를 뒤집으면 **존재하지 않는 예산 초과를 관리하느라 4배를 태운다.**
연수 6은 `--financial-years=5`가 `fromFiscalYear`부터 **올해까지** 도는 결과이고
(`DartFinancialAdapter`), 그중 올해분은 `status 013`으로 버려진다.

## 6. 정정공시 탐지

별도 플래그 필드가 **없다.**

`rcept_no`(14자리) = 접수일자(8) + 일련번호(6). 같은 `(corp_code, bsns_year, reprt_code)`에 대해 **`rcept_no`가 큰 쪽이 최신 정정본**이다.

- `publishedAt`은 `rcept_no` 앞 8자리에서 유도한다.
- 재무 API는 최신 보고서 기준으로 응답하므로, `FinancialWriter`의 기존 로직(`publishedAt`이 더 늦으면 정정본으로 보고 `revision_no + 1`로 append)이 그대로 성립한다.

## 7. 전체 재무제표 — `fnlttSinglAcntAll.json` (2026-08-10 실측)

주요계정이 주지 않는 것들(영업활동현금흐름·현금성자산·차입금·이자비용)을 얻으려고 실측했다.
표본은 삼성전자·NAVER·카카오·KB금융의 **2025 사업보고서(`reprt_code=11011`, `fs_div=CFS`)**다.

**요청**: 주요계정과 같되 **`fs_div`가 추가로 필수**다(`CFS` | `OFS`). 주요계정과 달리
**응답 행에 `fs_div` 필드가 없다** — 어느 쪽을 받았는지는 요청이 정하므로, CFS가 비면 OFS로
다시 부르는 폴백이 필요하고 그때만 호출이 2배가 된다.

**필드 계약은 §11-E다.** 특히 **`thstrm_amount`가 분/반기 (포괄)손익계산서에서는 [3개월]
금액**이라는 것 — TTM을 4분기 합으로 만들기 전에 그 절을 읽는다.

**응답 규모**: 229~349행(주요계정은 7~15행). `sj_div`가 다섯이다.

| 회사 | 총 행 | BS | CF | CIS | IS | SCE |
|---|---|---|---|---|---|---|
| 삼성전자 | 229 | 52 | 42 | 13 | 17 | 105 |
| NAVER | 239 | 51 | 53 | 30 | — | 105 |
| 카카오 | 233 | 65 | 41 | 36 | — | 91 |
| KB금융 | 349 | 42 | 69 | 49 | — | 189 |

**IMPORTANT — 손익이 `IS`에만 있다고 가정하면 안 된다.** 삼성전자만 `IS`가 있고 나머지 셋은
`CIS`(포괄손익계산서)뿐이다. 주요계정 API가 `BS`/`IS` 둘로 정규화해 주던 것을 여기서는
소비 측이 감당해야 한다.

### `account_id`(XBRL 표준계정ID)가 계정명보다 안정적이다

전 행에 `account_id`가 채워진다. 표준코드를 쓰지 않는 행은 `-표준계정코드 미사용-`이라는
**문자열 파수꾼**으로 오며 5~31행(2~9%)이다 — null이 아니므로 그 값으로 판별해야 한다.

이름이 회사마다 갈리는 것을 실측으로 확인했다:

| 항목 | 회사별 `account_nm` | 공통 `account_id` |
|---|---|---|
| 영업활동현금흐름 | `영업활동현금흐름` / `영업활동으로 인한 현금흐름` / `영업활동으로부터의 현금흐름` | `ifrs-full_CashFlowsFromUsedInOperatingActivities` |

계정명 후보군을 계속 늘리는 방식은 업종이 늘수록 반드시 새어 나간다. 이 엔드포인트를 쓴다면
매칭은 `account_id`를 우선하고 계정명은 폴백으로만 둔다.

### 얻을 수 있는 것과 없는 것 — **전환을 결정하기 전에 이 표를 본다**

| 목표 | 결과 | 근거 |
|---|---|---|
| **영업활동현금흐름** | **4/4 확보** | `ifrs-full_CashFlowsFromUsedInOperatingActivities` |
| 현금및현금성자산 | 4/4 확보 | `ifrs-full_CashAndCashEquivalents`. **단 `sj_div='BS'`로 좁혀야 한다** — KB금융은 CF의 `기초 현금 및 현금성자산`이 먼저 잡혔다 |
| 단기금융상품 | 3/4 | `ifrs-full_ShorttermDeposits…`. KB금융에 없다 |
| 총차입금 | **합성해야 한다** | 단기차입금·유동성장기부채·사채·차입부채가 회사마다 다른 조합으로 온다. 무엇을 더할지가 회사마다 다르므로 "총차입금"은 우리가 **만드는** 값이 된다 |
| **이자비용** | **1/4 (금융업만)** | `ifrs-full_InterestExpense`가 KB금융에만 있다. 비금융 3사는 `금융비용`(`FinanceCosts`)뿐이고 **그것은 이자비용이 아니다** — 외환손실·파생상품손실을 포함한다 |
| **감가상각비** | **1/4 — 후보가 하나뿐이던 수다** | `AdjustmentsForDepreciationAndAmortisation`이 KB금융에만 있다. **「표준코드로 오지 않는다」로 읽으면 안 된다** — 후보를 넓히면 다른 ID로 오는 회사가 있다(§15) |

**표본을 8개사로 늘려 더 잰 것이 §12(계정 여덟)와 §13(자본적지출)에 있다** — 매출원가·
법인세비용·주당이익이 §12에서, **자본적지출이 §13에서** 열린다. **감가상각비는 §15가 다시 쟀고 3/8이다**
(계정명 부분일치가 낸 오진까지 §12에 함께 적혀 있다).

**이 절의 표는 4개사 표본이 재지 못한 것을 「없다」로 세지 않는다** — 위 표에 없는 항목은
닫힌 것이 아니라 **이 표본이 묻지 않은 것**이다. 실제로 자본적지출이 그 자리에 있었고, 저장소는
그것을 재본 적 없이 결손으로 적어 두고 있었다(§13).

이자보상배율(EBIT ÷ 이자비용)은 **여전히 계산할 수 없다.** 순부채/EBITDA는 막는 것이 둘이며
**서로 성격이 다르다** — EBITDA는 §15가 3/8로 재서 **아직 좁고**, 순부채는 총차입금이 **원리적으로
합성값**이라 재도 안 갈린다. 금융비용을 이자비용으로 대신 쓰는 것은 다른 값을 같은 이름으로 부르는 것이라 하지 않는다.

**지표 말고 하나가 더 열린다 — §8의 이익잉여금 결손이다.** 이 표는 4개사 표본에서 "무엇을 얻는가"만
봐서 그것을 세지 못했다. 자본변동표(SCE)가 함께 오는 것이 그 답이며 실측은 §11-E에 있다.

**쿼터**: 종목·연도당 4콜로 주요계정과 같다(`reprt_code` 넷). `fs_div` 폴백이 필요한 종목만 8콜이다.
비용은 호출 수가 아니라 **응답 크기와 계정 매핑의 복잡도**에 있다.

## 8. 주요계정의 계정 집합은 회사마다 다르다 (2026-08-10 실측)

**§1의 "계정명 일관성" 미검증 항목이 실제로 새어 나갔다.** 결손 보정(ADR-0040) 뒤 편입 350종목
중 **이익잉여금만 세 종목에서 비었다** — 오리온·오리온홀딩스·에스티큐브. 유동자산·유동부채는
왔으므로 금융업 사유가 아니다. 탐침은 `DartAccountNameProbeLiveTest`이고 회사당 1콜이다.

| 회사 | CFS(연결) | OFS(별도) |
|---|---|---|
| 삼성전자(대조군) | 유동자산·유동부채·**이익잉여금**·자본금·총계 3종 | 같음 |
| 에스티큐브 | 이익잉여금·자본금 **없음** | **있음** |
| 오리온 | 이익잉여금 **없음** | **없음** |
| 오리온홀딩스 | 이익잉여금 **없음** | **없음** |

**IMPORTANT — 계정명 후보군을 늘려도 열리지 않는다.** 이름이 다른 것이 아니라 **행 자체가 없다.**
오진하기 쉬운 자리이므로 여기 적는다 — 다음 세션의 첫 시도가 `RETAINED_EARNINGS` 후보군 보강이
될 것이고, 그것은 아무것도 바꾸지 못한다.

**CFS/OFS 폴백으로도 열리지 않는다.** 어댑터는 "CFS가 비면 OFS"를 <b>보고서 단위</b>로 고른다.
에스티큐브처럼 CFS는 있고 그 안에 계정만 없는 경우, 계정 단위로 폴백하면 열리기는 한다 —
**그러나 연결 총자산과 별도 이익잉여금을 한 행에 섞는 것이라 뜻이 달라진다.** Altman Z가
그럴듯하게 틀린 값을 내고 화면에는 흔적이 없다. ADR-0039의 "뜻이 다른 값을 같은 이름으로
부르지 않는다"에 걸린다.

**남는 길은 전체 재무제표(`fnlttSinglAcntAll`)다.** §7의 표본에서 `account_id`가 전 행에 채워졌고
자본변동표(SCE)가 91~189행으로 함께 온다. 즉 **ADR-0039의 P10(전체 재무제표 전환)이 H-05뿐
아니라 이 결손도 연다** — 전환의 근거가 하나 늘었다.

영향은 작다(3종목). 다만 그중 오리온이 실제로 스크리닝 결과에서 빠졌으므로 **"영향이 없다"가
아니라 "지금은 3종목이다"** 로 읽는다.

## 9. 엔드포인트 카탈로그 — 무엇이 있고 무엇이 없는가 (2026-08-10)

이 절은 **"무엇이 있고 무엇이 없는가"의 정본**이고, "어떻게 부르는가"는 §10이, "어떤 필드가
오는가"는 §11이 답한다.

> **근거는 사용자가 DART 개발가이드 목록에서 옮겨 온 카탈로그 101줄이다.** 그 파일과 개발가이드
> 13종 원문은 **저장소에서 지웠고 git 이력에 있다**(§11 머리에 복구 명령). 아래 "액면분할 전용
> API가 없다"와 "다중회사 주요계정 복수조회 가능"의 근거가 그 101줄이며, **개발가이드는 이미
> 있는 API의 사용법이라 없는 API를 증명하지 못한다** — 두 자료는 답하는 질문이 다르다.
>
> **MUST NOT: 목록에 없다는 것을 얻을 수 없다로 읽지 않는다.** 이 절이 실제로 그렇게 한 번
> 틀렸다(액면분할 → §10-B가 뒤집었다).

| 우리가 막혀 있던 것 | 대응 API | 판정 |

| 업종 상대 비교(H-02·S-01·S-02) · Altman Z 금융업 제외 | 공시정보 **기업개황** | **있다.** 업종 코드가 실제로 오는지·분류 체계는 미확인 |
| 피인수 진행 제외(U-06) | 주요사항보고서 **회사합병 결정 · 주식교환·이전 결정 · 영업양수/양도 결정**, 증권신고서 **합병 · 주식의포괄적교환·이전** | **있다. 넉넉하다** |

| **액면분할 이력 → 수정주가(P9)** | **전용 API가 없다** | **아래 참조** |

### IMPORTANT — 카탈로그의 "분할"은 **회사분할**이지 **액면분할**이 아니다

목록에 분할이 셋 있다 — 주요사항보고서의 **「회사분할 결정」·「회사분할합병 결정」**, 증권신고서의
**「분할」**. **셋 다 우리가 찾는 것이 아니다.** 헷갈리기 쉬운 자리라 여기 적는다.

| | 무엇인가 | 주가에 하는 일 |
|---|---|---|
| **회사분할**(카탈로그에 있다) | 회사를 둘로 쪼갠다(물적·인적분할). **기업 구조**가 바뀐다 | 인적분할이면 자산이 빠져나가 **기준가가 조정된다** |
| **액면분할·주식분할**(카탈로그에 없다) | 1주를 N주로 쪼갠다. **주식 수**만 바뀐다 | 주가가 **1/N**이 된다 |

우리가 `adj_factor`에 필요한 것은 아래쪽이고, **주요사항보고서 36종에 유상·무상·유무상증자와
감자 결정은 있는데 그것만 없다.** (액면분할이 자본시장법상 주요사항보고 대상이 아니라
거래소 수시공시 대상이라 목록에 없는 것으로 보이나, 그 법적 근거는 **확인하지 않았다** —
관측은 "이 목록에 없다"까지다.)

**다만 회사분할도 무시할 것이 아니다.** 인적분할은 기준가 조정 사건이라 `adj_factor`가
필요하고, 그런데 **`CorporateAction.Type`에는 `SPLIT`/`REVERSE_SPLIT`밖에 없어 표현할 자리가
없다.** P9에서 액면분할과 함께 봐야 하고, 타입을 늘릴지가 그 phase의 결정 하나다.

즉 `adj_factor`를 만들 원자료를 **전용 엔드포인트로 받을 수 없다.** 남는 길은 셋이었고,
**2026-08-10 실측으로 2번이 열렸다**(§10-B).

1. **공시검색**으로 보고서 존재만 찾고 **원문을 파싱한다** — 가장 비싸다. **쓰지 않는다.**
2. **정기보고서 주요정보의 「증자(감자) 현황」** — **열렸다.** `isu_dcrs_stle`에
   **`주식분할`**이 오고 액면가와 일자가 함께 온다. 상세와 함정은 **§10-B**에 있다.
3. **「주식의 총수 현황」 + 시세 불연속** — 분할을 *탐지*할 수는 있으나 **추정이지 이력이 아니다.**
   §10-B가 그것을 실측으로 못박았다 — 삼성전자 2018은 발행주식수가 **50배가 아니다**(자사주
   소각이 겹쳤다). 배수로 비율을 유도하면 조용히 틀린다. **대조군으로만 쓴다.**

**전용 엔드포인트가 없다는 것이 P9을 막지 않는다.** 단 **회사분할**(인적분할)은 여전히
열려 있지 않다 — 「회사분할 결정」 개발가이드를 아직 받지 않았고, `CorporateAction.Type`에
표현할 자리도 없다.

### 부수 발견 — 호출 수를 줄일 수 있다

재무정보에 **「다중회사 주요계정」(복수 조회 가능)**이 있다. 지금 `financial-refill`은
종목당 1콜이라 350종목 × 4개년 × 4보고서 = 5,600콜인데, 복수 조회로 묶으면 그 수가 크게 준다.
**상한 100을 실측으로 확정했다 — §10-C.**

**「XBRL택사노미재무제표양식」**도 있다 — 표준계정과목 체계를 준다.

**MUST NOT: 이것을 회사별 계정 진단에 쓰려 하지 않는다.** 요청 인자가 `crtfc_key` + `sj_div`
둘뿐이라 **`corp_code`를 받지 않는다** — 회사별 재무제표가 아니라 **표준계정 사전**이므로
특정 회사가 무엇을 냈는지 원리적으로 알 수 없다(§10-C). 이름이 "재무제표양식"이라 §8의
이익잉여금 결손을 가르는 데 쓸 수 있어 보이는 것이 함정이다. 쓸 데는 따로 있다 —
P10의 계정 매칭 후보군 생성.

**업종 체계는 한국표준산업분류(KSIC)다.** 264=통신·방송장비 제조, 108=기타 식품 제조,

#### 10-B-2. 분할·병합의 비율과 효력일은 우리 DB가 이미 갖고 있다

**활성 유니버스의 지표 영향권 불연속 43건을 전수 대조한 결과(2026-08-12), 사건 종류가 같은 날
`listed_shares`가 어떻게 움직이는가로 완전히 갈린다.**

| 주식수 배수(같은 날) | 뜻 | 건수 | 예 |
|---|---|---|---|
| 가격 배수의 **역수** | **액면분할·병합** | 11 | F&F 5.0 / 0.190 · 대한전선 **0.1** / 10.63 · 휴림로봇 0.4 / 2.68 |
| **정확히 1.0000** | **무상증자 등 권리락** — 주식수는 나중에 는다 | 26 | 루닛 2023-11-09 · 2026-05-04 |
| 그 밖 | 인적분할·복합 사건 | 6 | 삼바 0.650 / 1.465 · SKT 3.04 / 0.187 · OCI 0.688 / 0.688 |

- **분할·병합의 비율은 `listed_shares` 배수가 정확하다.** 5.0000 · 2.0000 · 0.1000 · 0.4000으로
  읽히고, **효력일도 그 값이 바뀐 첫 거래일로 정확하다.** 종가 배수는 그날 시장이
  움직인 만큼 흐려진다(대한전선 10.63 vs 정확한 10). **비율을 종가에서 유도하지 않는다.**
- **IMPORTANT — 그 배수는 소수 넷째 자리까지만 깔끔하고, 전체 정밀도로는 떨어지지 않는다.**
  단수주 처리 때문이다. 실측(2026-08-12): 대한전선 `0.099999999277` · 휴림로봇 `0.399999997740` ·
  아시아나항공 `0.333333330`. 마지막은 1/3이라 **어떤 정밀도로도 정확히 표현되지 않는다.**
  관측값을 그대로 비율로 쓰면 `numeric(18,10)`에서 역수가 `10.0000000700`이 되어 1,492원짜리
  봉이 14,920이 아니라 **14,920.000104**로 조정된다. **관측 배수는 단순 유리수로 스냅해서 쓴다**
  (ADR-0049). 반올림 스케일을 낮추는 것은 해결이 아니라 악화다 — 1/3을 6자리로 접으면 역수가
  `3.0000030000`이 되어 오차가 40배 커진다.
- **MUST NOT: 주식수 변화 자체를 기업 행위로 읽지 않는다.** 유상증자·전환권행사·주식매수선택권
  행사가 상시 주식수를 조금씩 바꾼다(루닛 2025 보고서 한 장에 그런 행이 50개 넘는다).
  **무엇이 가격을 바꾸는 행위인가는 DART의 낱말이 답하고, 얼마나 바꾸는가는 `listed_shares`가
  답한다.** 둘 중 하나만으로는 되지 않는다.
- **무상증자는 두 날짜가 갈린다는 것 자체가 신호다.** 가격이 뛴 날 주식수가 그대로면 권리락이고,
  그 뒤 주식수가 뛰는 날이 신주상장이다. 루닛 2023은 **16거래일**, 2026은 14거래일 벌어졌다.
- **IMPORTANT — 무상증자 비율의 분모(`기존 주식수`)는 신주상장 <b>직전 거래일</b>이다.
  권리락일이 아니다.** 그 사이에 전환권행사류가 낄 수 있어 실측으로 갈린다 — 루닛 2023은
  권리락일 12,381,004인데 상장 직전은 14,238,154(11-24에 별개 증가)이고, 2026은 29,284,502 대
  37,191,318이다. 권리락일을 분모로 쓰면 **2.15·2.27이 나와 정답 2.0이 아니다.**
  상장일은 **주식수 증가분이 `isu_dcrs_qy`와 정수로 완전히 일치하는 날**로 찍힌다(표본 둘 다 성립).
- **IMPORTANT — 무상증자 배수는 스냅 대상이 아니다.** 이것도 정확히 안 떨어지지만 편차의 원인이
  단수주가 아니라 **자사주 미배정**이라 실체가 있다. 실측: 씨젠 2021은
  `52,225,994 = 2 × 26,234,020 − 242,046`이고 그 242,046이 자기주식이다(0.92%). 휴젤 2020은
  2.9331(정답 3), NHN 2021은 1.9176(정답 2)이다. KRX 권리락 기준가가 총주식수 기준이므로
  **`1.9907735833`이 정본이고 `2`가 아니다.** 위 스냅 규칙을 여기 걸면 실측 무상증자의 상당수가
  거부되어 계수가 영영 1로 남는다 — **스냅은 분할·병합 전용이다.**

- **DART는 중복을 접지 않고 항목 수로 센다** — 101건 요청은 12개를 순환 반복해 만든 것인데도
  `021`이 나왔다. 상한 판정이 유효하다는 뜻이다.
- **응답에 `corp_code`가 실제로는 온다.** 개발가이드 응답 표에는 `stock_code`만 있는데
  둘 다 채워진다. 다만 **표에 없는 필드에 의존하지 않는다** — 매핑은 `stock_code`로 한다.
- **비용**: 350종목 ÷ 100 = 4묶음 × 4개년 × 4보고서 = **64콜**. 지금의 5,600콜이 그만큼 준다.

**`xbrlTaxonomy.json` — 회사별 진단에는 쓸 수 없다.**

- 요청 인자가 `crtfc_key` + `sj_div` 둘뿐. **`corp_code`가 없다.**
- `sj_div=BS1`에 519행. `ifrs_RetainedEarnings`=이익잉여금(결손금),
  `dart_RetainedEarningsBeforeAppropriations…`=미처분이익잉여금이 **표준계정에 존재한다.**
- **그러므로 §8의 결손은 "이름을 모르는 것"이 아니라 "그 회사가 그 계정을 안 낸 것"이 맞고,
  이 엔드포인트는 그것을 가려 주지 못한다.** 표준계정 사전이기 때문이다.
- 쓸 데: `account_id` ↔ `label_kor` 사전을 만들어 **P10의 계정 매칭 후보군을 손으로 늘리지
  않고 생성**하는 것. `sj_div` 하나당 1콜이다.

### 10-D. 합병·주식교환 · 감사의견 → **U-06은 절반만 열린다**

`cmpMgDecsn.json`(합병) · `stkExtrDecsn.json`(주식교환·이전). `corp_code`와 `bgn_de`/`end_de`가
전부 필수라 **종목별로 돌아야 한다 — API당 350콜, 둘이면 700콜.**

셀트리온(2023 셀트리온헬스케어 흡수합병) 관측:

- **`bddd`(이사회결의일)=`2023년 08월 17일` · `mgsc_mgdt`(합병기일)=`2023년 12월 28일`** —
  둘 다 채워진다. **U-06이 겨냥하는 "진행 중" 구간을 정의할 수 있다.**
- **날짜가 `YYYY년 MM월 DD일` 한국어 문자열이다.** 다른 엔드포인트의 `YYYYMMDD`·`YYYY-MM-DD`와
  또 다르다. 파서를 공유하면 깨진다.
- **IMPORTANT — `mg_stn`(합병형태)이 `해당사항없음`이라 방향을 가를 수 없다.** 존속/소멸은
  `mg_mth`(합병방법)에 **자유 텍스트**로만 있다(*"(주)셀트리온이 (주)셀트리온헬스케어를
  흡수합병 / 존속회사(합병법인) : … / 소멸회사(피합병법인) : …"*). 즉 이 API로 **"합병에
  관여했다"까지는 구조화되어 오고 "피인수인가"는 파싱이 필요하다.**
- `mgsc_trspprpd_bgd`/`_edd`(거래정지 예정기간)는 **`-`로 비어 왔다.**
- 대조군 삼성전자는 양쪽 다 `status 013`이다. **정상 응답과 데이터 없음이 제대로 갈린다.**

**감사의견 — `accnutAdtorNmNdAdtOpinion.json`** (부수 발견, 채택 미정)

- `adt_opinion` = **`적정의견`**(`적정`이 아니다). 1콜에 당기·전기·전전기 **3개년**이 온다.
- **`bsns_year`가 연도가 아니다.** `제57기 \n(당기)`처럼 **기수 + 줄바꿈 + 구분**이다.
  개발가이드는 "사업연도(당기, 전기, 전전기)"라고만 적었다. 연도로 파싱하면 실패한다.
- **행이 정확히 2배로 온다**(3개년인데 6행). 연결·별도로 추정되나 **필드로 구분되지 않는다** —
  §1의 `당기순이익(손실)` 중복 행과 같은 병이다.
- **표본 둘 다 `적정의견`이라 비적정의 표기는 미확인이다.** 그것을 보기 전에는 판정 로직을
  만들지 않는다.

**IMPORTANT — `thstrm_amount`가 언제나 같은 기간이 아니다.** 원문 주석 그대로:
**"분/반기 보고서이면서 (포괄)손익계산서일 경우 [3개월] 금액"**이다. `frmtrm_q_amount`도 같다.

분기 단독, `thstrm_add_amount`를 누적으로 주던 것과 **규칙이 같지 않다** — 여기서는 재무제표
구분까지 함께 봐야 한다.

| 필드 | 뜻 | 함정 |

**미확인 — 현금흐름표(`CF`)의 분기 금액이 3개월인지 누적인지 재지 않았다.** 위 원문 주석이
[3개월]이라 밝힌 것은 **(포괄)손익계산서뿐**이고 `CF`는 어디에도 적혀 있지 않다. P10은 이것을
**미확인으로 남긴 채** 갔다 — 어댑터가 **연간(`11011`)의 OCF만 저장하고 분기 OCF는 버린다**
(`DartFullStatementAdapter.operatingCashFlow`). 연간만 쓰는 동안은 드러나지 않으므로,
**분기 OCF를 쓰는 조건이 붙기 전에 반드시 여기부터 잰다** — 모른 채 저장하면 4배나 1/4로
조용히 틀리고, 그때는 그 값을 쓰는 쪽이 **모른다는 사실조차 모른다.**

**계정 매칭 실측 (2026-08-13, 350종목 적재)** — §7의 4개사 표본이 놓친 것들이다.

- **영업활동현금흐름 총계가 `-표준계정코드 미사용-`으로 오는 회사가 있다.** 삼성전자

셋 있다 — 오리온의 `투자부동산감가상각비 조정`·`사용권자산감가상각비 조정`, 그리고 여러 회사의
`대손상각비`. **투자부동산 한 항목의 조정액을 EBITDA에 더하면 영업이익에 엉뚱한 수를 얹는다.**
§11-E의 *"`영업활동에서 창출된 현금`은 총계가 아니다"* 와 같은 병이고, 이쪽은 **틀린 값이 훨씬
작아 눈에 덜 띈다.**

**그러나 이 절이 낸 「실질 2/8」은 후보 `account_id`가 하나뿐이던 조건의 수다.** 그때 완전일치로
센 것은 `ifrs-full_AdjustmentsForDepreciationAndAmortisationExpense` 하나였고, 나머지는 계정명
부분일치로 판정했다. **후보를 넓혀 다시 재니 3/8이고 두 회사의 판정이 뒤집힌다** — 오리온과
POSCO홀딩스는 **표준코드로 온다**(`ifrs-full_AdjustmentsForDepreciationExpense`). §15가 정본이다.

**MUST: 「후보에 없어서 못 잡은 것」을 「소스가 안 주는 것」으로 적지 않는다.** 이 절이 그렇게
적었고, 그 문장이 EBITDA를 두 phase 동안 닫아 두었다.

### 계속영업손익 1/8은 "닫혔다"가 아니다 — 구분할 것이 있는 회사만 낸다

값이 온 유일한 회사(삼성바이오로직스)가 **중단영업손익도 함께 가진 유일한 회사**다.
K-IFRS는 **중단영업이 있을 때만** 손익계산서에 계속/중단을 갈라 표시하고, 없으면 당기순이익
한 줄로 끝난다. 관측이 그 규칙과 정확히 일치한다.

**그래서 결론이 뒤집힌다 — 대부분의 종목에서 "지속사업순손실"은 이미 `net_income`과 같다.**
새로 받아야 하는 것은 **중단영업이 있는 소수 종목**뿐이고, 그 종목에서만 두 값이 갈린다.

- **MUST NOT: 1/8을 "소스가 주지 않는다"로 적지 않는다.** 그렇게 적으면 다음 세션이
  원본 명세 P-01을 원자료 부재로 분류하는데, **막고 있는 것은 그것이 아니다.**
- **표본 8로는 그 소수가 350 중 몇인지 알 수 없다.** 재적재가 답한다.

### P-01(계속사업 기준 희석 EPS)이 반쯤 열렸다 — 그러나 표준코드로는 못 찾는다

삼성바이오로직스는 **`계속영업기본주당이익(손실)`·`계속영업희석주당이익(손실)`** 을 내는데
**둘 다 `-표준계정코드 미사용-`이다.** 나머지 일곱은 표준코드를 쓰되 이름이 넷으로 갈린다 —
`기본주당이익` / `기본주당순이익` / `기본주당이익(손실)` / **`지배기업 소유주 기본주당이익`**.

- **MUST: `지배기업 소유주 …`를 우리 자체 계산 EPS와 대조할 때 그 차이를 결함으로 읽지 않는다.**
  우리 `EPS_TTM`은 `당기순이익 ÷ 발행주식수`라 지배·비지배를 가르지 않는다. CJ대한통운처럼
  소스가 지배주주 기준을 주면 **두 값이 원래 다르다** — 그 차이를 드러내는 것이 대조 컬럼의
  목적이며(`FinancialFigures`의 javadoc), 어느 쪽이 틀린 것이 아니다.
- **P-01이 요구하는 값은 계정명으로만 찾을 수 있고 회사마다 다르다.** 표준코드 매칭으로는
  일반 EPS가 잡히고, 그것은 P-01이 금지한 *"일회성 손익 포함 EPS"* 다.

### 이 절이 열지 못한 것

- **총차입금은 원리적으로 탐침 대상이 아니다.** §7이 *"무엇을 더할지가 회사마다 다르므로
  총차입금은 우리가 **만드는** 값"* 이라고 적은 그대로다. 8종목에서 실제로 관측된 조합이

  리스부채·단기차입금·사채·장기차입금` … 으로 전부 달랐다. **합성 규칙이 350에 통하는지는

- **커버리지는 어느 항목도 답하지 못했다.** 8종목은 **"닫혔다"는 결론만** 낼 수 있다 —

### 부호 — 8종목 표본이 일반화되지 않은 실례

**재적재 전 이 절은 "부호는 여덟 모두 양수다"라고 적을 수 있었다. 그것이 틀렸다.**

LG화학(FY2023·2024) · S-Oil(FY2024) · 롯데쇼핑(FY2023)과 소형주 열 곳.

**값이 틀린 것이 아니라 표기가 다른 것이다.** LG화학 FY2023이 −12.96조인데 그 해 실제
설비투자가 그 규모다. **계정이 「유형자산의 취득」이라 음수일 수 없으므로**(회사가 유형자산을
"음(陰)으로 취득"할 수는 없다) 음수는 그 회사가 투자활동 유출을 음수로 적었다는 뜻이다.

- **MUST: 크기로 읽는다.** 부호를 그대로 빼면 그 22행에서 `OCF − capex`가 덧셈이 되어

- **MUST NOT: 이 처리를 순증감 계정에 복사하지 않는다.** 여기서 안전한 이유는 「취득」이

**이 절은 §12의 원칙이 실제로 작동한 기록이다** — *"8종목은 「닫혔다」는 결론만 낼 수 있다"*.

일반화한 문장**이 틀렸다. 표본으로 답할 수 있는 것은 존재 여부이고, **분포는 전수가 답한다.**

| 어디 | 관측된 행 | 좁히지 않으면 |
|---|---|---|
| `CF` | 오리온 `재고자산의 감소(증가)` = `ifrs-full_AdjustmentsForDecreaseIncreaseInInventories` | **증감분**을 잔액으로 저장한다 — 「재고 증가율」이 *증감의 증감*이 된다 |
| `CF` | POSCO `재고자산평가손실`·`재고자산평가손실환입` = `dart_AdjustmentsForWritedownsOfInventories` 등 | 손익 조정을 잔액으로 읽는다 |
| `BS` | 이마트 `상품권` = **1.7조**, `-표준계정코드 미사용-` | **계정명 부분일치가 이것을 문다.** 재고와 무관한 부채성 항목이다 |

**MUST NOT: 계정명 폴백을 두지 않는다.** 위 마지막 행이 그 이유다 — 표준코드가 없는 행이라
`account_id` 완전일치로는 애초에 걸리지 않는다.

### 유형자본을 빼는 규칙 — §13이 못 낸 답

**두 코드는 배타적이다.** 오리온만 `OtherThanGoodwill` + `Goodwill` 둘로 나눠 내고, 나머지
일곱은 `AndGoodwill` 하나로 합쳐 낸다. 둘이 동시에 온 회사가 **0/8**이다.

```
무형자산총계 = IntangibleAssetsAndGoodwill            (합쳐 내는 회사)
             = IntangibleAssetsOtherThanGoodwill + Goodwill   (나눠 내는 회사)
```

- **MUST: 3.6(유형자본)을 열려면 위 둘을 갈라 합산한다.** §13처럼 한 칸에 묶으면 **나눠 내는
  회사에서 영업권이 통째로 빠져**(오리온 253.7억) 유형자본이 과대해진다. 값이 그럴듯해 드러나지
  않는다.
- **MUST NOT: 두 코드를 더하지 않는다.** 배타적이므로 더하면 합쳐 내는 회사에서 영업권을 두 번
  뺀다 — 이 표본에서는 동시 출현이 없어 무해하지만, **그것은 8종목이 답한 것이지 전수가 답한
  것이 아니다.**

### 전수가 답한 것 — 표본 여덟이 답할 수 없던 것

**MUST NOT: 위 표에 커버리지·분포를 읽어 넣지 않는다.** 표본 여덟은 「닫히지 않았다」까지만
낸다. 아래는 **350종목 재적재**(FY2021~2025, 실제콜 2,714)가 낸 답이다.

| | 행 | 채워짐 | |
|---|---|---|---|
| **금융 중분류(64·65·66) 제외** | 1,430 | **1,310 (91.6%)** | capex의 88%와 같은 수준 |
| 금융 중분류(64·65·66) | 192 | 107 (55.7%) | **아래 참조 — 절반이 지주회사다** |
| **음수** | — | **0행** | 표본의 「양수뿐」이 전수에서도 유지됐다(capex와 갈린다) |

**IMPORTANT — 금융 중분류의 절반이 재고자산을 낸다. 「금융업은 없다」로 세면 틀린다.**
KSIC 64가 금융업과 **지주회사**를 겸하는데(ADR-0067이 코드로 가를 수 없다고 적은 자리),
지주회사는 연결에 사업 자회사가 들어와 **재고자산이 있다** — CJ·GS·효성·LS·HD한국조선해양·

없는 쪽이 `649`·`64992`를 **함께** 쓰고, 순수 금융만 `64121`(은행)·`64913`으로 갈린다.

**연도별로 안정적이다.** FY2021~2025에서 채워진 비율이 273/289 · 278/297 · 281/334 · 290/348 ·
295/353이다 — 과거 연도에서 계정이 달라지지 않는다. **소비 지표가 증가율이라 2개년이 동시에
있어야 하는데, 이 분포가 그것을 답한다.**

**정정공시가 낀 4종목은 이번에도 채워지지 않았다**(`정정보류=4`). `FILL_WITHOUT_REVISION`이
공시일이 더 늦은 소스를 채우지 않고 미루기 때문이며, capex 때와 같은 자리다.

### 아직 비어 있는 것 — 분기 잔액 행

**Q4 잔액 행 1,604개가 전부 NULL이다.** 매퍼와 `toFourthQuarterBalance`는 재고자산을 담지만
**그 경로가 아직 한 번도 돌지 않았다** — `full-statement-refill`이 `--quarters=true` 없이는
`[FY]`만 요청하고, Q4 잔액 행은 `Q3`가 요청 목록에 있을 때만 유도된다.

**결함이 아니라 잡의 범위다.** 대조군이 같은 표에 있다 — **같은 저량인 `cash_and_equivalents`도
Q4에서 0/1,604**이다(V27로 들어온 뒤 같은 이유로 비어 있다). `retained_earnings`만 1,014인 것은
그 컬럼이 분기를 도는 다른 잡으로 채워졌기 때문이다.

### 이 절이 답하지 못하는 것

**셋을 이름으로 가른다.** 같은 문장 형태로 두면 다음 세션이 「재보지 않았다」·「재서 닫혔다」·
「재서 열려 있으나 적재하지 않았다」를 구별하지 못한다.

| | 상태 | 다음 |
|---|---|---|
| **재고자산** | **재서 열렸고 적재했다**(`financial_statement.inventories`) | 지표가 없어 **화면은 안 바뀐다**. 커버리지는 ADR-0069의 `premise`가 계속 잰다 |
| 무형자산 둘·영업권 | **재서 열려 있으나 적재하지 않았다** | 3.6을 열 때 위 합산 규칙으로 적재한다 — **재측정이 필요 없다.** ADR-0067이 3.6을 미뤘다 |
| 이자비용 | **재서 닫혔다 — 다만 표본이 넷뿐이다**(§7, 1/4, 금융업만) | §12·§13·§14의 여덟으로 다시 재면 3.2 이자보상배율이 갈린다. **콜은 8이다** |

- **분기 재고자산.** 재고자산은 **저량**이라 §11-E의 「3개월인지 누적인지」 함정이 없다 —
  담을 수 있고 코드도 담지만, 위처럼 **아직 안 돌았다.**

## 15. 감가상각비 — 후보를 넓혀 세 번째로 쟀다 (2026-08-21 실측, P18/P19)

**§7(1/4)과 §12(실질 2/8)가 「닫혔다」로 적었는데, 그 둘이 완전일치로 센 `account_id`는
`ifrs-full_AdjustmentsForDepreciationAndAmortisationExpense` 하나뿐이었다.** 나머지는 계정명
부분일치였고 그중 하나가 오진이라 수가 한 번 정정되기도 했다. **「그 하나가 안 왔다」와
「감가상각비 계정이 없다」는 다르다** — 이 절은 축을 넓혀 같은 여덟에게 다시 물은 결과다.

표본·연도·`fs_div`가 §12·§13·§14와 **같다**(2025 사업보고서 CFS, 8콜, 8/8 응답).
탐침은 `DartDepreciationProbeLiveTest`다.

| 축(`account_id`) | 결과 |
|---|---|
| `AdjustmentsForDepreciationAndAmortisationExpense` (감가+무형 합산) | **1/8** — KB금융 |
| **`AdjustmentsForDepreciationExpense` (감가 단독)** | **2/8** — 오리온·POSCO홀딩스 |
| **`AdjustmentsForAmortisationExpense` (무형 단독)** | **2/8** — 오리온·POSCO홀딩스 |
| 상각+손상 합산 · 성격별 손익(IS/CIS) 축 둘 · 유형자산 주석 축 | **0/8** |
| **축을 하나라도 잡은 회사** | **3/8** |

### 판정이 뒤집힌 것 둘 — §12의 회사별 기록이 틀렸다

- **오리온은 오진이 아니었다.** §12는 `투자부동산감가상각비 조정`을 잡아 오진으로 판정하고 그
  회사를 뺐는데, **같은 응답에 `감가상각비에 대한 조정`(`…AdjustmentsForDepreciationExpense`,
  146,875,397,092)이 따로 있었다.** 오진 판정은 옳았고 **회사를 뺀 것이 틀렸다.**
- **POSCO홀딩스는 「표준코드 미사용」이 아니었다.** 같은 ID로 온다. §12가 후보에 없어 못 잡고
  계정명으로 판정했을 뿐이다.

**MUST NOT: 이것을 「부분일치를 써도 된다」로 읽지 않는다.** 오리온 한 회사의 현금흐름표에
`감가상각`을 무는 계정이 **셋**이다(`투자부동산감가상각비 조정`·`사용권자산감가상각비 조정`과
총액). §12의 금지는 그대로 살아 있다 — 바뀐 것은 **후보 `account_id`를 넓히면 총액을 완전일치로
잡을 수 있다**는 사실뿐이다.

### 그래도 EBITDA는 아직 좁다 — 5/8은 낱말 자체가 본표에 없다

삼성전자·NAVER·CJ대한통운·삼성바이오로직스·이마트 **다섯은 `감가상각`·`상각`이 든 행이 본표에
하나도 없다.** 후보 부족이 아니다. `fnlttSinglAcntAll`이 주는 것은 본표(BS/IS/CIS/CF)이고 그
회사들은 그 항목을 **주석에 둔다.**

**더 넓힐 후보가 없다는 것도 함께 쟀다.** 이름에는 걸리는데 후보에 없던 `account_id` 여덟은
전부 **총액이 아닌 것**이었다 — 대손상각비 둘, 상각후원가 금융자산 넷, 투자부동산·사용권자산
감가상각 둘. **총액 후보는 하나도 남지 않았다.**

### 그래서 무엇이 열리고 무엇이 안 열리는가

- **EBITDA는 3/8이다.** 8종목은 커버리지를 답하지 못하므로(§12의 MUST) 실제 수는 350종목
  재적재만이 답한다. **다만 「소스가 안 준다」는 아니다** — 주는 회사가 있고 우리가 못 잡고 있었다.
- **EV는 이것과 무관하게 서지 않는다.** 총차입금이 §7·§12가 적은 대로 **원리적으로 합성값**이고
  ADR-0062 §버린 대안이 그것을 기각했다. **MUST NOT: 이 절의 3/8을 「EV/EBITDA를 만들어도 된다」로
  읽지 않는다.**
- **순부채/EBITDA(원본 H-03)도 같은 이유로 안 열린다.**

**`premise` 펜스를 두지 않는다.** 이 측정으로 **코드를 바꾸지 않았기 때문**이다 — 매퍼의 후보를
넓혀도 담을 컬럼이 없고, 컬럼을 만들어도 3/8을 쓸 소비자가 없다. **재는 것과 적재하는 것을
가르는 자리**이며 §14가 무형자산에서 같은 판단을 했다(*"재서 열려 있으나 적재하지 않았다"*).
넓힌 후보 ID는 위 표에 있으므로 **적재를 결정하면 재측정 없이 그대로 쓴다.**

### 표본으로는 원리적으로 못 재는 것 — **착수 판단에 필요한 셋**
