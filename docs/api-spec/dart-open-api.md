# DART Open API — 소스 계약과 엔드포인트 색인

금융감독원 전자공시. 국내 재무·공시 소스.

- 기본 URL: `https://opendart.fss.or.kr/api/` · 환경변수 `DART_API_KEY`(40자리)

**이 파일은 소스 자체의 계약**(인증·실패·쿼터·무엇이 있고 없는가)**과 색인만 담는다.**

## IMPORTANT — 쓰면 안 되는 엔드포인트

`fnlttSinglIndx.json`(단일회사 주요 재무지표)을 **쓰지 않는다.** 배제 사유가 셋이고 각각 단독으로 충분하다.

1. **계산된 비율을 반환한다.** 응답이 `idx_val`이며 원본 계정이 아니다. spec §7의 "모든 지표는
   원자료를 수집한 뒤 자체 계산"과 정면으로 충돌하며, `RawFinancialReport`에 비율 필드가 없는 것이
   이를 타입 수준에서 막고 있다.
2. **2023년 3분기 이후만 제공한다.** 3년치 재무 이력을 만들 수 없다.
3. 두 시장(한국·미국)의 계산식을 통일한다는 목적 자체가 무너진다.

## status 코드 — HTTP 200과 함께 온다

**IMPORTANT — DART는 인증 실패도 HTTP 200으로 응답한다.** 공공데이터포털이 403을 주는 것과
정반대다. HTTP 상태코드만 보면 잘못된 키로 조회한 결과를 정상으로 오인한다.
**`status` 필드 파싱이 필수다.**

| status | 의미 | → `Kind` |
|---|---|---|
| `000` | 정상 | — |
| `010` | 등록되지 않은 인증키 | `AUTH` |
| `011` | 사용할 수 없는 키(일시 중지) | `AUTH` |
| `012` | 접근할 수 없는 IP | `AUTH` |
| `013` | **조회된 데이터 없음** | `NOT_FOUND` |
| `014` | 파일이 존재하지 않음 | `NOT_FOUND` |
| `020` | 요청 제한 초과 | `RATE_LIMITED` |
| `021` | 조회 가능한 회사 개수 초과(최대 100) | `MALFORMED` |
| `100` | 필드의 부적절한 값 | `MALFORMED` |
| `101` | 부적절한 접근 | `AUTH` |
| `800` | 시스템 점검 중 | `TRANSIENT` |
| `900` | 정의되지 않은 오류 | `TRANSIENT` |
| `901` | 개인정보 보유기간 만료 키 | `AUTH` |

**실측**: 없는 연도 조회 → HTTP 200 + `status 013`. 잘못된 키 → HTTP 200 + `status 010`.

**MUST NOT: `status 013`을 「그런 사건이 없다」로 읽지 않는다.** 회사가 표를 `status 000` +
전 필드 `-`인 1행으로 낼 수도 있고, 없는 보고서를 부른 결과일 수도 있다. 각 표의 함정은
위 세 파일에 있다.

**응답 공통**: `status`·`message`. 목록형은 `list` 배열로 온다 —
**`company.json`만 평면 객체다**(아래).

## 쿼터

**IMPORTANT — 한도는 계정 전체가 아니라 API별이다**(사용자 제공, 미실측). 즉
`fnlttSinglAcnt`·`fnlttSinglAcntAll`·`company`·`fnlttMultiAcnt`가 **각자 자기 카운터를 쓴다.**
계정 합산으로 잡으면 실제로 도는 잡들을 근거 없이 서로 경쟁시키게 되고, 반대로 **한 엔드포인트에
쏠리는 잡 하나가 혼자 한도를 태우는 것**을 못 본다 — **실제 위험은 후자다.**

| 값 | 출처 | 계획에 쓰는 값 |
|---|---|---|
| API당 일 **20,000**건 | 2차 출처 다수 + 사용자. 공식 문서에 명시를 찾지 못했다(`status 020` 설명에 "일반적으로는 20,000건 이상의 요청에 대하여") | **10,000 (절반)** |

**MUST: 착수 판단은 보수 예산 10,000으로 한다.** 20,000이 미실측이므로 그 값에 맞춰 짠 계획은
한도가 절반이면 그대로 깨진다. 절반에서 넘치면 **그때가 폴백 비율을 실측하거나 날짜를 나눌 시점**이다.

- **하루 17,000콜에서도 한도에 안 걸린 관측이 있다.** **MUST NOT: 그것을 「20,000이 맞다」로
  읽지 않는다** — 관측은 **17,000까지 안 걸렸다**까지이고, 위 보수 예산 10,000은 그대로 선다.
  한 엔드포인트에 쏠린 잡이 아니라 여러 잡의 합이었다는 것도 함께 읽는다.
- **분당 제한은 공식 문서에 없다.** 미검증이므로 보수적으로 간격을 둔다.
- **우리 리미터는 `dartRateLimiter` 빈 하나로 DART 전체를 센다** — 소스 쪽 한도는 안 겹쳐도
  **우리 쪽에서 먼저 막힌다.**

### 잡별 비용 (350종목 기준)

| 잡 | 엔드포인트 | 콜 | 보수 예산 대비 |
|---|---|---|---|
| 초기 적재 재무 3년 | `fnlttSinglAcnt` | 종목당 12 → **4,200** | 42% |
| `financial-refill` 3년 | `fnlttSinglAcnt` | 종목당 16 → **5,600** | 56% |
| 업종 | `company` | 종목당 1 → **350** | **3.5%** |
| 기업행위 (2020~오늘) | `irdsSttus` | 종목당 2 → **700** | **7%** |
| 연간 OCF (`11011`만) | `fnlttSinglAcntAll` | 종목당 6 → **2,100** | **21%** |
| 〃 + `fs_div` 폴백 전량 | 〃 | 최대 **4,200** | **42%** |
| **거버넌스 적재** | 여덟 표 × 연도 22쌍 | **7,700** | **77%** |
| 정정공시 탐침 | `fnlttMultiAcnt` | 연도 8 × 보고서 4 × 4묶음 = **128** | 1.3% |

**MUST: 전체 재무제표는 사업보고서(`11011`)만 부른다.** H-05의 가공법이
`sum(operatingCashFlow, 최근 5개 회계연도)`라 **분기가 필요 없다.** 보고서 넷을 다 부르면 같은
일에 콜이 4배(8,400, 폴백 전량이면 16,800으로 보수 예산을 넘는다)가 되고, **그 4배는 아무 에러
없이 다른 잡의 여유를 먹는다.**

**진짜 위험은 합산이 아니라 쏠림이다** — **그 자리에서 예산을 정하는 것은 콜 수가 아니라
"어느 보고서 코드가 필요한가"다.** 순서를 뒤집어 폴백 비율부터 재면 **존재하지도 않는 예산
초과를 관리하느라 4배를 태운다.**

**거버넌스(7,700)와 `financial-refill`(5,600)이 같은 날 겹치면 우리 쪽 리미터에서 넘는다.**
표를 나눠 돌리는 수단이 `--governance-endpoints`다.

**연수 6은 `--financial-years=5`가 `fromFiscalYear`부터 올해까지 도는 결과이고**
(`DartFinancialAdapter`), 그중 올해분은 `status 013`으로 버려진다.

## 고유번호 — `corpCode.xml`

종목코드 → `corp_code` 매핑의 **유일한 공식 경로**.

- 요청: `crtfc_key` 하나
- 응답: **ZIP 바이너리**. 내부에 `CORPCODE.xml` 한 개
- 필드: `corp_code`(8자리), `corp_name`, `corp_eng_name`, `stock_code`(6자리, **상장사만 채워짐**),
  `modify_date`
- **실측**: 3.5MB ZIP, 전체 118,664법인 중 `stock_code`가 있는 **상장사 3,925건**

**주의: content-type이 `application/x-msdownload`로 온다**(`application/zip`이 아니다).
**타입으로 분기하면 실패한다.**

## 기업개황 — `company.json`

- 요청: `crtfc_key` · `corp_code`(STRING(8), 필수). **종목당 1콜**, 유니버스 350종목이면 350콜.
- 응답: `corp_name` `corp_name_eng` `stock_name` `stock_code` `ceo_nm` `corp_cls`
  `jurir_no` `bizr_no` `adres` `hm_url` `ir_url` `phn_no` `fax_no` **`induty_code`**
  **`est_dt`** **`acc_mt`**

**IMPORTANT — 응답이 `list`가 아니라 평면 객체다.** 다른 엔드포인트와 형태가 다르므로
`DartResponse.requireList`를 그대로 쓰면 빈 결과가 된다. 그 자리는 `requireSuccess`다.

| 필드 | 뜻 | 함정 |
|---|---|---|
| `corp_cls` | 법인구분 | `Y`(유가) `K`(코스닥) `N`(코넥스) `E`(기타) |
| `induty_code` | 업종코드(KSIC) | **자릿수가 3·4·5로 섞인다** — 아래 |
| `est_dt` | **설립일**(YYYYMMDD) | **상장일이 아니다.** 삼성전자 19690113은 설립 1969년이고 상장은 1975년이다. **응답 전체에 상장일 필드가 없다** |
| `acc_mt` | 결산월(MM) | 2자리 숫자. 350종목 중 12월이 아닌 것은 **1종목**(신영증권 = 3월)이고, `periodRange()`의 12월 결산 근사가 틀리는 자리가 거기 하나다 |

**350종목 전수 실측**: `induty_code` **350/350** 채워짐(빈 값도 `status 013`도 없다) ·
**자릿수 3자리 105 · 4자리 52 · 5자리 193.**

- **MUST: 자릿수를 3과 5로 전제하지 않는다. 3·4·5가 모두 온다.** 그 전제로 만든 CHECK 제약이
  **52종목을 실제로 거부한 적이 있다**(SK하이닉스 2612, POSCO홀딩스 2411, LX인터내셔널 4610).
  앞 2·3자리를 잘라 쓰는 것은 세 형태 모두에서 옳으므로 **범위만 넓히면 된다** — 자릿수로 분기하지 않는다.
- **MUST: 금융업 판정은 앞 2자리(중분류)로 한다.** 전체 문자열 비교나 특정 자릿수 전제는 다른
  자릿수 종목을 통째로 놓치고, 결과는 "그 종목만 조용히 안 걸린다"로 나타난다.
- **IMPORTANT — 중분류 64는 "금융업"이지만 실질은 *지주회사 버킷을 겸한다.*** `64992`(그 외 기타
  금융업)에 **신한지주·KB금융 같은 금융지주와 LG·SK·GS 같은 비금융 사업지주가 함께 들어 있고,
  3자리 `649`에도 미래에셋벤처투자와 효성·HDC가 섞인다.** 즉 **코드만으로는 금융/비금융 지주를
  가를 수 없다.** 350종목 실측: 64·65·66에 51종목이 있고 그중 22종목이 `ALTMAN_Z` 값을 갖는데
  **21개가 비금융 사업지주**였다(진짜 금융사 29종목은 유동/비유동 미구분 재무제표라 이미 값이 없다).
  이 비대칭이 Altman Z 제외 범위를 65·66으로 좁힌 근거다(ADR-0044).

**업종 체계는 한국표준산업분류(KSIC)다.** 264=통신·방송장비 제조, 108=기타 식품 제조,
2612=반도체 소자, 63120=포털·인터넷정보매개, 64992=그 외 기타 금융, 65121=손해보험.

## 정정공시 탐지

별도 플래그 필드가 **없다.**

`rcept_no`(14자리) = 접수일자(8) + 일련번호(6). 같은 `(corp_code, bsns_year, reprt_code)`에 대해
**`rcept_no`가 큰 쪽이 최신 정정본**이다.

- `publishedAt`은 `rcept_no` 앞 8자리에서 유도한다.
- 재무 API는 최신 보고서 기준으로 응답하므로, `FinancialWriter`의 로직(`publishedAt`이 더 늦으면
  정정본으로 보고 `revision_no + 1`로 append)이 그대로 성립한다.
- **전 종목을 싸게 훑는 경로는 다중회사 주요계정이다**(`fnlttMultiAcnt`, 128콜). 절차는
  `batch-load` skill에 있다.

## 엔드포인트 색인 — 무엇을 어디까지 믿을 수 있나

**지위가 곧 신뢰도다.** "사용 중"은 코드가 매일 부르는 것이고, "미착수"는 스펙만 읽은 것이다.

|---|---|---|---|

| `fnlttSinglAcnt.json` | **사용 중** | [`dart-financial.md`](./dart-financial.md) | 종목·연도당 4 |
| `fnlttSinglAcntAll.json` | **사용 중** | 〃 | 종목·연도당 1(연간 전용), 폴백 시 2 |
| `fnlttMultiAcnt.json` | **탐침만** (정정 탐지) | 〃 | **100종목 묶음** = 64 |
| `xbrlTaxonomy.json` | 미착수 (계정 사전) | 〃 | `sj_div`당 1 |

**공통 요청 인자**: `crtfc_key`(STRING(40), 필수). 각 파일의 표는 그 외의 것만 적는다.

### 받았지만 아직 안 쓰는 넷

**「미착수」의 뜻이 넷에서 갈린다.** `elestock`·`tesstkAcqsDspsSttus`는 **쓸 자리가 정해졌고
필드 표만 안 옮긴 것**이다. `majorstock`은 소비처가 아직 없고, `list.json`은 증자(감자) 현황이
열려 필요가 줄었다.

| 엔드포인트 | 요청 인자 | 쓸 곳 |
|---|---|---|
| `elestock.json` (임원·주요주주 소유보고) | `corp_code`. **기간 파라미터가 없다** | **거버넌스 축의 내부자 순매수** — 린치 §4.4가 이 소스를 이름으로 지목한다 |
| `majorstock.json` (대량보유 상황보고) | `corp_code`. **기간 파라미터가 없다** | 거버넌스 축의 후보. 소비처가 아직 정해지지 않았다 |
| `tesstkAcqsDspsSttus.json` (자기주식 취득·처분) | `corp_code` · `bsns_year` · `reprt_code` | `SHARES_GROWTH_3Y`의 교란 요인(소각) |
| `list.json` (공시검색) | `corp_code` · `bgn_de` · `end_de` 등 | **응답 결과 표가 원문에 빠져 있었다** |

## 카탈로그 — 무엇이 있고 무엇이 없는가

**MUST NOT: 「목록에 없다」를 「얻을 수 없다」로 읽지 않는다.** 이 판정이 실제로 한 번 틀렸다 —
액면분할 전용 API가 없어 닫혔다고 적었는데 「증자(감자) 현황」의 `isu_dcrs_stle`가 `주식분할`을

### IMPORTANT — 카탈로그의 "분할"은 **회사분할**이지 **액면분할**이 아니다

목록에 분할이 셋 있다 — 주요사항보고서의 **「회사분할 결정」·「회사분할합병 결정」**, 증권신고서의
**「분할」**. **셋 다 우리가 찾는 것이 아니다.** 헷갈리기 쉬운 자리라 여기 적는다.

| | 무엇인가 | 주가에 하는 일 |
|---|---|---|
| **회사분할**(카탈로그에 있다) | 회사를 둘로 쪼갠다(물적·인적분할). **기업 구조**가 바뀐다 | 인적분할이면 자산이 빠져나가 **기준가가 조정된다** |
| **액면분할·주식분할**(카탈로그에 없다) | 1주를 N주로 쪼갠다. **주식 수**만 바뀐다 | 주가가 **1/N**이 된다 |

`adj_factor`에 필요한 것은 아래쪽이고, **주요사항보고서 36종에 유상·무상·유무상증자와 감자
결정은 있는데 그것만 없다.** (액면분할이 자본시장법상 주요사항보고 대상이 아니라 거래소 수시공시
대상이라 목록에 없는 것으로 보이나, **그 법적 근거는 확인하지 않았다** — 관측은 "이 목록에
없다"까지다.)

**회사분할도 무시할 것이 아니다.** 인적분할은 기준가 조정 사건이라 `adj_factor`가 필요한데
**`CorporateAction.Type`에 `SPLIT`/`REVERSE_SPLIT`밖에 없어 표현할 자리가 없다.**
「회사분할 결정」 개발가이드도 아직 받지 않았다 — `TODO.md`의 「회사분할 결정」 절이 그것을 든다.
