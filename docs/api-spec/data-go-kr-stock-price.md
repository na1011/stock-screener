## 엔드포인트

```
https://apis.data.go.kr/1160100/service/GetStockSecuritiesInfoService/getStockPriceInfo
```

- REST(GET), XML·JSON 모두 지원 → **`resultType=json`을 쓴다.** XML 파서 의존성이 필요 없어진다.
- 최대 메시지 4000 byte, 평균 응답 500ms, **초당 최대 30 TPS**
- 데이터 갱신주기: 일 1회. **기준일자로부터 영업일 하루 뒤 오후 1시 이후**에 갱신된다(§공개 지연)
- 서비스 URL의 다른 오퍼레이션(신주인수권증서·수익증권·신주인수권증권)은 이 프로젝트에서 쓰지 않는다.

### IMPORTANT — 종목별 기간 조회가 가능하다

`likeSrtnCd` + `beginBasDt` + `endBasDt`를 함께 주면 **한 종목의 기간 시세를 1콜에** 받는다. 실측(삼성전자 2026-07-27~08-06)에서 `totalCount: 8`로 8거래일이 한 번에 왔다.

이것이 초기 적재 비용을 결정한다. 종목별 기간조회가 되므로 **350종목 × 1콜 ≈ 350콜**이다. 일자별 전종목 조회만 가능했다면 500거래일 × 1콜이 되어 형태가 완전히 달랐다.

### IMPORTANT — serviceKey 이중 인코딩 함정

발급받은 키는 이미 URL 인코딩된 형태다(`%2F`·`%3D` 포함). HTTP 클라이언트가 이것을 **다시** 인코딩하면 `%252F`가 되어 인증에 실패한다.

MUST: 키를 **디코딩해서** 넘기고 URI 빌더가 한 번만 인코딩하게 한다. 실측에서 이 처리를 해야 통과했다.

## 응답 필드

정상 응답은 `response.header` + `response.body` 구조다.

**header**: `resultCode`(2자리, `00`이 정상), `resultMsg`
**body**: `numOfRows`, `pageNo`, `totalCount`, `items.item[]`

| 필드 | 의미 | 매핑 |
|---|---|---|
| `basDt` | 기준일자 `YYYYMMDD` | → `tradeDate` |
| `srtnCd` | 단축코드(6자리) | 티커 |
| `isinCd` | ISIN 코드 | — |
| `itmsNm` | 종목명 | → `name` |
| `mrktCtg` | 시장구분 `KOSPI`\|`KOSDAQ`\|`KONEX` | → `marketCode` |
| `clpr` | 종가 | → `close` |
| `vs` | **기준가** 대비 등락(`clpr − 기준가`) | 저장하지 않음 — 아래 「`vs`가 기준가를 준다」 |
| `fltRt` | 등락률 | 쓰지 않음(파생값) |
| `mkp` | 시가 | → `open` |
| `hipr` | 고가 | → `high` |
| `lopr` | 저가 | → `low` |
| `trqu` | 거래량 | → `volume` |
| `trPrc` | 거래대금 | → `tradeValue` |
| `lstgStCnt` | 상장주식수 | — |
| `mrktTotAmt` | 시가총액(종가 × 상장주식수) | 쓰지 않음(파생값) |

**`trPrc`(거래대금)를 실제로 제공한다.** V1 마이그레이션의 "`close × volume`으로 합성 금지" 규칙을 지키면서 값을 채울 수 있다는 뜻이다. 합성이 아니라 실측값이다.

`fltRt`·`mrktTotAmt`는 소스가 계산한 파생값이므로 저장하지 않는다(spec §7 — 모든 지표는 원자료에서 자체 계산).

### `vs`가 기준가를 준다 — 기업행위의 날짜와 가격 배수다 (2026-09-17 실측)

**`clpr − vs`가 KRX 기준가이고, 그것이 직전 종가와 다른 날이 거래소가 권리락·배당락·분할·병합으로
가격을 조정한 날이다.** spec §7의 금지는 **지표 값**을 소스에서 받지 말라는 것이라 이 값에 걸리지 않는다 —
이것은 지표가 아니라 거래소가 매긴 기업행위의 기록이다.

- 국내 `price_daily`가 있는 484종목 × 2020-01-02~2026-09-16(종목당 1콜 · 잘림 0): 조정일 **291**.
  대조군 삼성전자는 분기 현금배당·소각 2회에도 **843행 중 0**이다 — **현금배당은 기준가를 안 바꾼다.**
- 기존 원장 `APPLIED` 분할·병합·무상증자 106행의 배수와 **최대 0.357% · 평균 0.05%** 차 — 호가단위
  반올림 크기다.
- 거래 중인데 `vs = 0`인 조정일 6은 **종가가 기준가와 같았던 날**이다(메지온 2022-04-05 72,500 → 24,200 ·
  ×2.996 = 1:3 분할의 반올림).

**함정**
- **정지 뒤 첫 거래일의 기준가는 기계적일 수도, 경매가일 수도 있다** — 정지 뒤 조정 62 중 기준가 ≠ 시가
  27 · 정지 봉 위 조정 2 · **기준가 = 시가 33**(2026-09-17). 뒤쪽에도 기계적 조정이 섞인다 — 대한전선
  2022-02-07 기준가 1,675는 권리락 산식(1차 발행가 약 1,485원)으로 재현된다. 인적분할 재상장(한화에어로스페이스
  2024-09-27 300,000 = 시가)은 기준가가 시가라 가격 배수를 안 주고, 분할비율은 `cmpDvDecsn`이 준다.
  기업행위가 아닌 재설정도 기준가 = 시가 모양이다 — 코넥스 → 코스닥 이전상장 · 상장적격성 심사 뒤 재개 · 스팩 합병 재상장.
- **정지 봉 위의 조정은 `base = open`이 늘 참이다** — 정지 봉을 평탄화해 저장하기 때문이다(ADR-0160).
  코다코 2024-09-27 ×1/40 · 2026-09-04 ×1/8 병합이 조정일 자체가 정지 봉이다. 「`base = open`이면 경매」로
  가르면 진짜 병합을 버린다.
- **거래 중 기계적 조정도 우연히 시가가 기준가와 같다**(유한양행 2021-12-29 · 한온시스템 2025-11-13) —
  `base = open` 하나로 경매를 가르지 않는다.

## 실측한 응답 형태 4가지

**MUST: 네 가지를 모두 처리한다.** 봉투 구조가 상황에 따라 달라진다.

### 1. 정상 — HTTP 200

```json
{"response":{"header":{"resultCode":"00","resultMsg":"NORMAL SERVICE."},
 "body":{"numOfRows":20,"pageNo":1,"totalCount":8,"items":{"item":[{...}]}}}}
```

### 2. 미등록 키 — HTTP 403, **봉투가 다르다**

```json
{"OpenAPI_ServiceResponse":{"cmmMsgHeader":{
  "errMsg":"SERVICE_KEY_IS_NOT_REGISTERED_ERROR",
  "returnAuthMsg":"등록되지 않은 서비스키",
  "returnReasonCode":"30"}}}
```

IMPORTANT — 정상 응답의 `response.header`가 아니라 `OpenAPI_ServiceResponse.cmmMsgHeader`다. 최상위 키부터 다르므로 하나의 DTO로 파싱할 수 없다. → `AUTH`

### 3. 빈 결과 — HTTP 200, `resultCode:"00"`, `totalCount:0`

```json
{"response":{"header":{"resultCode":"00","resultMsg":"NORMAL SERVICE."},
 "body":{"numOfRows":5,"pageNo":1,"totalCount":0,"items":{"item":[]}}}}
```

**IMPORTANT — 이 프로젝트에서 가장 위험한 지점이다.** 아래 셋이 응답상 **완전히 동일하다**:

| 상황 | 실측 응답 |
|---|---|
| 존재하지 않는 종목코드(`likeSrtnCd=999999`) | 위와 동일 |
| 휴장일 조회(`basDt=20260801` 토요일) | 위와 동일 |
| **잘못된 파라미터 값**(`basDt=NOTADATE`) | 위와 동일 |

즉 **날짜 형식 오타가 "그날 데이터 없음"으로 조용히 저장된다.** `resultCode` 검사만으로는 잡히지 않는다.

MUST: **요청을 보내기 전에 파라미터를 검증한다** — 날짜는 `\d{8}`, 티커는 `\d{6}`. 그래야 "빈 결과"의 의미가 "휴장 또는 미상장"으로 좁혀진다. 그 뒤의 판정은 `DailyUpdateJob`이 한다 — 대상일에 시세가 한 건도 안 들어오면 알린다. **휴장인지 미공개인지는 구분하지 않는다**(구분할 근거가 응답에 없다).

### 4. 잘못된 요청 — HTTP 400

한글 파라미터 값(`likeItmsNm=삼성`) 등에서 발생. 본문이 JSON이 아닐 수 있다. → `MALFORMED`

## 페이징 (2026-08-06 실측)

**IMPORTANT — 페이징하지 않으면 조용히 잘린다.** 이 API에서 가장 위험한 두 번째 함정이다(첫째는 "잘못된 파라미터와 빈 결과가 구별되지 않는다").

실측 결과:

| 요청 | `totalCount` | 반환 행 수 |
|---|---|---|
| 삼성전자 2년 (`numOfRows=1000`) | 487 | 487 |
| 삼성전자 6.5년 (`numOfRows=1000`) | 1,618 | **1,000** — 오래된 618일 소실 |
| 삼성전자 6.5년 (`numOfRows=2000`) | 1,618 | 1,618 |
| KOSDAQ 전종목 `pageNo=2` (`numOfRows=1000`) | 1,820 | 820 |

- **`numOfRows`는 2,000까지 허용된다.** 다만 공식 문서에 상한이 없어 벤더가 언제든 조일 수 있다. 이 값에 기대지 말 것.
- **`pageNo`는 정상 동작한다.** 2페이지 요청이 나머지를 준다.
- 초과분은 **아무 경고 없이** 잘린다. `resultCode`는 `00`이고 HTTP도 200이다.

**종료 조건은 `누적 수신 >= totalCount`여야 한다.** "한 페이지가 `numOfRows`보다 적으면 끝"으로 판단하면 안 된다 — `likeSrtnCd`가 부분 일치라 다른 종목이 섞이고, 그것을 걸러내면 페이지당 유효 건수가 항상 `numOfRows`보다 적어 첫 페이지에서 멈춘다. 같은 이유로 **진행도는 필터 전 행 수로 세야 한다.**

## 공개 지연

**소스는 기준일자의 데이터를 그 다음 영업일 13시 이후에 낸다.** 공급자 공식 안내다.

> 금융위원회에서 제공하는 모든 서비스는 실시간이 아니며, 데이터 갱신은 **기준일자로부터
> 영업일 하루 뒤 오후 1시 이후**에 업데이트됩니다. 예를 들어, **금요일 데이터는 차주
> 월요일**에 제공됩니다. (**월요일이 공휴일인 경우, 다음 영업일**에 제공됩니다)

2026-08-10 실측이 이것과 일치한다. **같은 콜에 들어온 대조군이 파라미터를 보증하므로 0은 요청 문제가 아니다.**

| `basDt` | 조회 시각 | `totalCount` |
|---|---|---|
| 2026-08-10 (당일) | 20:13 · 22:18 · 23:43 | **0** |
| 2026-08-07 (금) | 같은 세 시각 | **2,872** (23:43은 단일종목 범위조회라 1행) |
| 2026-08-06 (목) | 20:13 | 2,872 |

배치의 실행 결과는 이 안내가 **지금도 참인지**를 재는 쪽에 쓴다 — 0건이면 `DailyUpdateJob`이 WARNING을 내고, 거래일마다 오면 규칙이 바뀐 것이다(ADR-0042의 premise가 세션 시작에 같은 것을 잰다).

### 함정

- **MUST NOT: 공개 시각을 늦추는 것으로 해결하려 하지 않는다.** 20:13·22:18·23:43이 모두 같은 0이었다 — **그날 안에는 몇 시로 옮겨도 안 나온다.** 배치를 뒤로 미는 것은 대응책이 아니다.
- **"영업일"이라 연휴를 건너뛴다.** 월(거래)·화(공휴일)·수(거래)면 월요일치는 **수요일** 13시에 나온다. 대상 일자를 직전 *평일*로 잡으면 그 이동을 따라가지 못하고, 그 결손은 조회 창이 흡수한다(ADR-0042).
- **MUST: 지연을 잴 때는 경과 일수가 아니라 경과 *영업일*로 센다.** 아래 0건 모호성 때문에 "늦은 것인가 휴장인가"를 손으로 판정할 일이 남아 있고, 주말을 대기 시간으로 세면 **"안 나오는 날"과 "아직 안 나온 날"이 뒤바뀐다.**
- **MUST NOT: 0건을 휴장으로 단정하지 않는다.** 응답은 **없는 종목·휴장일·미공개·파라미터 오타에 전부 동일**하다(§status). 공개 규칙을 알게 된 것과 응답이 갈리는 것은 다른 문제다 — 휴장인지 미공개인지는 **소스 밖의 달력**을 봐야 갈린다. `MarketCalendar`의 javadoc이 이 구분 불가를 정확히 적어 두었고, **단정하는 쪽은 문서와 로그였다** — `MarketCapUniverseAdapter`가 `"{}이 휴장일이라 …"`로 찍는 줄이 그 예다.

### 대조군을 응답 안에 넣는 법 — 1콜로 0건의 모호성을 가른다

`likeSrtnCd` + `beginBasDt`/`endBasDt` 범위조회를 쓰면 **대상일과 대조일이 같은 응답에 담긴다.**

```
likeSrtnCd=005930 & beginBasDt=20260807 & endBasDt=20260811   # 이상/미만 → 08-07 ~ 08-10
```

대조일 행이 오고 대상일 행만 없으면 **그 응답 하나가 키·날짜형식·파라미터 오타를 전부 배제한다.**
두 번 호출해 비교하는 것보다 싸고, 두 호출 사이에 소스가 갱신될 여지도 없다. 결손을 의심할
때 **350콜을 태우기 전에 이것부터** 던진다.

- **거래량 0이 판별에 가장 확실하다.** 정상 거래일에 거래량이 0인 종목은 없다.

### 정지 중의 기준가·상장주식수·시총은 서로 다른 날의 기저를 섞는다 (2026-09-17 실측)

코다코(046070)는 2024-03-22 ~ 2026-09-09 정지 중에 회생 절차를 두 번 거쳤고, 소스가 그 사이를 이렇게 준다:

| `basDt` | `clpr` | `lstgStCnt` | `mrktTotAmt` | 일어난 일(DART) |
|---|---|---|---|---|
| 2024-09-26 | 257 | 42,786,056 | 11.0B | 정지 직전 가격 그대로 |
| **2024-09-27** | **10,280** (×40) | **14,064,588** | 144.6B | 2:1·20:1 병합(계 40:1) + 출자전환 2.6억 주가 같은 날 상장 |
| **2026-09-04** | **82,300** (×8.006) | 14,099,576 | **1,160.4B** | 8:1 병합 + 출자전환 9,733만 주 |
| 2026-09-10 | 410 | 14,099,576 | 5.8B | **상장폐지 정리매매 개시**(시가 800) |

- **기준가는 병합 비율로만 조정되고, 상장주식수는 출자전환 신주를 함께 싣는다.** 그래서 정지 중 `clpr × lstgStCnt`(= `mrktTotAmt`)는 **시장이 매긴 값이 아니다** — 액면가로 발행된 채권자 몫까지 옛 기준가로 평가한다. 유니버스 순위가 이 값을 그대로 써 코다코가 2026-09-07 `KOSDAQ_TOP150`(72위)에 들었다.
- **정지 중 편입권 종목 자체는 드물지 않고 대개 정당하다** — 표본 16기준일에 상위 N×1.2 안 정지 종목이 기준일당 0~2개였고 인적분할·분할·주식교환 대기가 대부분이다. **합성은 「정지 중 주식수가 늘어난 것」**이고 표본에서 코다코와 국일제지(2025-05-02, 출자전환으로 ×9.21)뿐이었다.
- 탐침: `KrCapitalEventProbeLiveTest`(`probeCapitalEvents` · `probeHaltedNearTopN`).

## 적재된 결손 평일은 전부 휴장이었다 (2026-08-11 전수 확인)

**소스는 실제 휴장 달력을 그대로 반영한다.** `price_daily`의 2020-01-02~2026-08-07에서 평일인데
빈 날을 전수로 뽑으면 **102일이고 전부 공휴일**이다. **무작위로 흩어진 날이 하나도 없다** —
수집 결손이 있었다면 반드시 거기 나타난다. 임시공휴일(2020-08-17 · 2023-10-02 · 2025-01-27)까지
정확히 빠져 있는 것이 "달력을 반영한다"의 직접 증거다.

```bash
psql -d stock_screener -c "SELECT extract(year FROM d)::int, count(*), string_agg(to_char(d,'MM-DD'),' ' ORDER BY d) FROM generate_series('2020-01-02'::date, (SELECT max(trade_date) FROM price_daily), '1d') d WHERE extract(isodow FROM d)<6 AND NOT EXISTS(SELECT 1 FROM price_daily WHERE trade_date=d::date) GROUP BY 1 ORDER BY 1"
```

**이것이 §대조군보다 먼저 던질 질문이다** — 콜을 태우지 않고, 한 날짜가 아니라 이력 전체를 본다.
연도별 개수가 13~19에서 벗어나거나 공휴일이 아닌 날이 끼면 그때 대조군 1콜로 좁힌다.

### 함정

- **MUST NOT: 이 결과를 "그 날짜가 휴장이다"의 증명으로 쓰지 않는다.** 증명하는 것은
  **적재 경로가 날짜를 빠뜨리지 않는다**이고, 개별 날짜의 성격은 여전히 소스 밖의 달력이 정한다
  (§함정의 0건 모호성은 그대로다). 다만 **102/102가 공휴일이면 103번째도 공휴일일 확률이 압도적**이라,
  새로 나타난 결손일 하나를 조사할 때의 사전 확률이 완전히 달라진다.
- **종목 축을 함께 보지 않으면 절반만 본 것이다.** 날짜 축이 깨끗해도 **특정 종목만** 며칠째 안
  들어올 수 있다(위 §거래정지가 그 원인이다). 그쪽은
  `SELECT max(trade_date) FROM price_daily GROUP BY stock_id`가 답한다.
