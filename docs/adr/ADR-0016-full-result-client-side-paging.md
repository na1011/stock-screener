# ADR-0016. 스크리닝 응답은 전량을 반환하고 정렬·페이징은 클라이언트가 한다

## 결정

스크리닝 결과를 한 응답에 전부 담는다. 서버는 기본 순서만 정하고(`SCORING`은 점수 내림차순, `FILTER`는 종목 id 오름차순) `sortedBy`로 알린다. 정렬·필터·페이징은 PrimeVue DataTable이 클라이언트에서 한다. 안전장치로 `MAX_ROWS`(2,000) 상한을 두되 넘으면 `truncated: true`를 **반드시** 싣는다.

## 규칙

- MUST NOT: 서버 페이징(`page`/`size`) 파라미터를 추가하지 않는다.
- MUST: 상한에 걸려 잘렸으면 `truncated: true`를 낸다. 조용히 자르지 않는다.
- MUST: 조건 정의는 응답의 `conditions` 사전에 한 번만 싣고, 행은 `conditionIndex`로 참조한다.
- MUST: 행의 `values`는 지표 코드를 키로 하는 맵이다. 지표별 DTO 필드를 만들지 않는다.
- MUST: 판정 상태를 `MATCHED`/`NOT_MATCHED`/`NOT_EVALUABLE` 세 값으로 낸다. boolean으로 접지 않는다(ADR-0003).

## 검증

```bash
./gradlew test --tests "*ScreeningApiContractTest*"
```
HTTP 결과가 인메모리 판정과 일치하고, 세 상태가 그대로 실리는 것을 확인한다.

```bash
grep -rn 'Pageable\|PageRequest\|@RequestParam.*page' src/main/java/com/stockscreener/screening/web/
```
아무것도 반환하지 않아야 한다.

**재검토 신호**: 운영에서 `truncated: true`가 관측되는 날. 그것이 ADR-0003이 말한 "성능이 문제가 되면 재검토한다"가 발동하는 시점이며, 답은 `ORDER BY` 표현식을 SQL로 내리는 것이다.

## 배경

ADR-0003이 이미 절반을 정했다 — SCORING은 좁히는 WHERE가 없어 전 종목이 대상이고 점수 접기가 메모리에서 일어나므로 **`LIMIT` 푸시다운이 불가능하다.** 그 위에 서버 페이징을 얹으면 페이지를 넘길 때마다 스크리닝 전체를 다시 도는 구조가 된다. 서버는 이미 전 행을 메모리에 올려놨으므로 잘라 보내도 DB 작업이 줄지 않는다.

규모가 이 교환을 성립시킨다. 유니버스 350종목 × (지표 10 + 조건 8) ≈ 300~500KB, gzip 후 40~60KB다. 사용자가 한 자릿수인 개인 서비스(spec §2)에서 문제가 되지 않는다.

EAV의 알려진 약점도 여기서 상쇄된다 — "임의 컬럼 정렬이 자연스럽지 않다"가 EAV의 실질적 대가인데, 클라이언트 정렬은 그 문제를 정면으로 우회한다. spec §6이 PrimeVue DataTable을 "정렬·필터·가상스크롤을 무료로 지원"한다는 이유로 채택한 것과도 맞물린다.

## 버린 대안

- **서버 페이징** — 위 배경 참조. SCORING에서 매 페이지가 전체 재계산이 된다.
- **상한 없이 전량** — 유니버스가 예상 밖으로 커지면 응답이 무한히 늘어난다. 상한 없이 두면 그 순간을 아무도 모른다.
- **상한에 걸리면 오류** — 사용자가 할 수 있는 것이 없는데 결과를 통째로 잃는다. 자르되 잘랐다고 말하는 편이 낫다.
- **행마다 조건 메타데이터 반복** — 프론트 코드가 단순해지지만 350행 × 8조건에서 페이로드가 10배가 된다.
- **지표별 응답 필드(`per`, `pbr`, …)** — 타입이 명시적이지만 지표를 추가할 때마다 DTO를 고쳐야 한다. 그것이 "지표 코드에 분기하지 않는다"의 HTTP 계층 위반이다.

## 결과

- 쉬워지는 것: 화면이 정렬 기준을 바꿔도 서버 왕복이 없다. 서버가 정렬 파라미터를 검증할 필요도 없다.
- 어려워지는 것: 유니버스가 크게 늘면(미국 시장 추가 등) 이 전제가 흔들린다. `truncated`가 그 신호다.
- 되돌리려면: 응답 계약과 프론트 DataTable 설정을 함께 고쳐야 하고, `ScreeningRepository`가 정렬을 SQL로 내리도록 바뀐다.
