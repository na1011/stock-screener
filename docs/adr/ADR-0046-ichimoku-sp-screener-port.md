# ADR-0046. 주봉 일목 스크리너를 세 번째 외부 명세로 들이고, 로드맵 순서를 바꾼다

## 결정

사용자가 반입한 `docs/external/ichimoku_sp_screener_patched.txt`(TradingView Pine Script v6, 1,167줄)를
이 프로젝트로 이식한다. 주봉 일목균형표 13 수식자 + 호소다 값폭관측론 파동 판정 + 외부 시그널 2종을
단계 의존 매트릭스로 점수화해 **Tier 1~4**를 내고, `ICHIMOKU_SP_KR` 프리셋이 `ICHI_TIER <= 3`으로 거른다.

**`progress.md`가 못박고 있던 `P10 → T-08` 순서를 `P9 → 시장 지수 → Ichimoku → P10`으로 바꾼다.**

이 이식이 요구하는 것이 P10(전체 재무제표)과 무관하고, 대신 **T-08의 원자료(시장 지수 시계열)와
지표 계약 확장을 선행으로 요구**하기 때문이다. 즉 이 phase가 T-08의 가장 비싼 부분을 함께 연다.

## 규칙

- **MUST: 이 파일을 세 번째 사람이 쓴 문서로 다룬다.** 정본 서열은 `docs/stock-screener-project-spec.md`(기획) >
  `docs/external/screener-spec-midterm-swing.md`(스윙 프리셋 조건셋, ADR-0041) 이고, 이 문서는 그 둘과 겹치지
  않는 **별개 프리셋의 정본**이다. 겹치는 자리가 생기면 spec이 이긴다.
- **MUST NOT: 원본과 다르게 옮긴 자리를 기록 없이 만들지 않는다.** 아래 셋이 승인된 이탈의 전부다.
  더 생기면 그때 ADR을 다시 연다.
  1. **207 주봉 미만이면 행을 쓰지 않는다.** 원본의 `sufficient_data` 가드는 130 주봉만 보장하는데
     `span_b_arr[129]`의 소비는 **207 주봉**까지 간다. 그 사이 종목은 `nz()`가 0을 채워
     `close > max(0,0)`·`c_i > c_26(=0)`이 **항상 참**이 되고, 결과가 **강세 방향 거짓 양성**으로 나온다.
     실측 이 밴드는 10종목이다.
  2. **시장 지수가 결손이면 그날 `ICHI_TIER` 행을 쓰지 않는다.** 원본은 `nz(idx_close[130])`가 0이면
     `idx_ret = 0`으로 접어 **D5가 상대 수익률에서 절대 수익률로 조용히 바뀐다.** 전역 CLAUDE.md의
     silent fail 금지와 ADR-0039의 "뜻이 다른 값을 같은 이름으로 부르지 않는다"가 원본 충실보다 우선한다.
  3. **주봉 경계는 "진행 중인 주 포함"으로 모든 일자에 일관 적용한다.** Pine의 `request.security(…, "W", …)`는
     비대칭이라 **실시간 봉에서는 진행 중인 주, 과거 봉에서는 마지막 확정 주**를 준다. Pine Screener는
     마지막 봉만 평가하므로 사용자가 보는 것은 전자이고, 그쪽에 맞춘다. **결과로 과거 일자는 TradingView
     *차트*와 값이 다르다 — 그것은 버그가 아니다.**
- **MUST: 내부 연산을 `double`로 한다.** 이 저장소의 관례는 `BigDecimal` + `HALF_UP`이지만
  Pine은 float64이고 `math.round`가 **ties round up**(−1.5 → −1)이라 `HALF_UP`(−1.5 → −2)과 갈린다.
  `score_d2`의 폴백 가지가 정확히 그 자리에 있고, `drv_41 == 0`은 흔한 조합이며 `ext_base = 3`
  구간이라 **Tier 1·2 후보에서 1점이 틀린다.** 경계(`IndicatorPoint`)에서만 `BigDecimal`로 바꾼다.
- **MUST NOT: 원본에서 죽은 코드를 옮기지 않는다.** 옮기면 검증 대상만 늘고 출력은 안 바뀐다.
  - 일봉 블록에서 살아 있는 것은 `drv_43`(→`drv_45`)과 `drv_55` **둘뿐**이다.
    `px_*`·`atr_01`·`atr_02`·`vol_01`·`vol_02`·**`vol_05`(일봉 OBV)**·`ich_d_05`·`_06`·`_08`·`drv_48`이 죽었다.
    **살아 있는 OBV는 주봉 `obv_w` 하나다.**
  - `drv_36`·`drv_37`·`drv_38`(V·E·NT 목표가)은 선언만 되고 미사용이다. leaf가 쓰는 것은 `drv_35` 하나다.
  - `vol_sma_w`·`drv_04`·`drv_49`, 반환만 되고 미소비인 `w_pa`·`w_pb`·`w_pc`·`w_pass34`·`w_drop`.
- **MUST: 도달 불가 분기를 알고 옮긴다.** 모르면 검증할 수 없는 셀에 시간을 쓴다.
  - `leaf = 7`(데이터 부족)은 도달 불가다.
  - `leaf 3`은 `stage 5·6` 전용이라 **`leaf_score`가 언제나 0**이다. `(leaf 3, stage 4)` 셀은 도달 불가다.
  - `stage 1`(신생)은 언제나 `leaf 9`다. **즉 Tier 1 후보에게 값폭관측론(VW1~VW6·피벗 A·B·C)의
    점수 기여는 0이다** — 코드량이 가장 큰 부분이 Tier 1 판정과 무관하다.
  - `DRV-54`의 `n_54 = 26`은 비교 기준이 자기 자신이라 발화하지 않는다.
- **MUST: `hosoda_arr`의 실효 anchor를 9개로 센다** — `9·17·26·33·42·52·65·76·**129**`.
  `drv_51 ∈ [0,128]`이라 172·200·257은 도달 불가이지만 **129는 `drv_51 = 128`에서 ±1로 걸린다.**
  그때 stage 4이고 `score_e`가 ±3이라 **빠뜨리면 6점이 뒤집힌다.**
- **MUST: 동점 처리를 VW3·VW4에서만 검증한다.** 규칙은 "더 과거(인덱스 큰 쪽) 채택"이고
  VW3은 과거방향 `>=`·미래방향 `>`의 **의도된 비대칭**이다. **VW2는 `pivot_a`의 인덱스를 쓰지 않아
  `<=` ↔ `<`가 출력에 흔적을 남기지 않는다** — 거기에 테스트를 걸면 항등식이 된다(D-13·D-14 패치는
  무의미한 패치였다).
- **MUST: 임계 3개(결론 5 · 강한 15 · 중간 8)를 코드 상수로 고정하고 설정으로 노출하지 않는다.**
  원본은 Pine `input.int`라 사용자가 바꿀 수 있고, `Tier`·`CONCLUSION`·`CONFIDENCE`가 전부 그 함수다.
  **골든 픽스처를 받은 뒤에는 그때 어떤 값이었는지 확인할 방법이 없다** — 요청 시 기본값인지 함께 묻는다.
- **MUST NOT: TradingView 대조를 평일에 하지 않는다.** 위 이탈 3 때문에 평일에는 두 의미론이 갈린다.
  **주말에 뜨면 TradingView의 마지막 주봉이 확정된 월~금이고 우리 `asOf = 금요일`과 같은 봉이 된다** —
  두 의미론이 일치하는 유일한 시점이라 그때만 불일치가 곧 결함이다.

## 검증

이식 착수 전이므로 코드에 걸 정적 검증이 아직 없다. 대신 **이 ADR 고유의 전제** 둘을 남긴다.

**수정 계수가 전량 1인지는 여기서 재지 않는다** — ADR-0039의 premise가 이미 그것을 묻고 있고,
사실 하나의 정본은 한 곳이어야 한다(`.claude/rules/doc-facts.md`). 그쪽이 "1이 아니다"로 바뀌면
P9가 진행된 것이고, 그때 이 ADR의 착수 조건이 열린다.

```premise 일목 이식 — 207주 미만 이탈이 아직 필요한가
psql -d stock_screener -At -c "SELECT CASE
  WHEN count(*) = 0 THEN '잴 것이 없었다 — price_daily가 비어 있다'
  WHEN count(*) FILTER (WHERE wk BETWEEN 130 AND 206) = 0
    THEN 'OK 130~206주 밴드가 비었다 — 원본 가드와 우리 이탈이 같은 결과를 낸다'
  ELSE 'OK 130~206주 밴드 ' || count(*) FILTER (WHERE wk BETWEEN 130 AND 206)
       || '종목 / 207주 이상 ' || count(*) FILTER (WHERE wk >= 207) || '종목'
  END FROM (SELECT stock_id, count(DISTINCT date_trunc('week', trade_date)) wk
            FROM price_daily GROUP BY 1) w"
```

```premise 일목 이식의 선행 조건 — 시장 지수 시계열이 아직 없는가
psql -d stock_screener -At -c "SELECT CASE
  WHEN count(*) = 0 THEN 'OK market_index_daily 테이블이 없다 — 지수 파이프라인 미착수'
  ELSE 'market_index_daily가 생겼다 — EXCESS_RETURN_26W와 지표 계약 확장이 어디까지 왔는지 확인하라'
  END FROM information_schema.tables WHERE table_name = 'market_index_daily'"
```

## 배경

이 저장소에는 사람이 쓴 명세가 둘 있었다(ADR-0041). 2026-08-11에 셋째가 들어왔다 —
TradingView Pine Screener용으로 쓰인 주봉 일목 스크리너이고, 기존 두 문서와 **어휘가 하나도 겹치지 않는다**
(`screener-spec-midterm-swing.md`에 일목 관련 낱말이 0건이다). 즉 대체가 아니라 **새 프리셋의 추가**다.

명세 분석 결과 원자료는 충분했다(207 주봉이 필요하고 320/356 종목이 충족한다). 막는 것은 둘이었다 —
**시장 지수 시계열이 없어 D5(±3점)를 낼 수 없고**, 그 ±3이 신뢰도 임계 8/15를 넘나들어 Tier를 실제로
뒤집는다. 그리고 **`adj_factor`가 전량 1이라 원주가로 130주 일목을 계산하게 되는데**, KRX 가격제한폭
±30%를 넘는 기업행위성 불연속이 최근 5년에 43건·42종목 있다(그마저 **하한**이다 — 30% 이내 기업행위는
정상 등락과 구별할 수 없다). 액면분할이 −80% 폭락으로 보이면 3역호전과 피벗이 통째로 무너지는데
**값은 그럴듯하게 나온다.**

**P10을 뒤로 미루는 판단의 근거는 이것이다.** P10이 여는 것은 H-05와 3종목이고(ADR-0039 §별도 phase),
이 이식이 여는 것은 새 프리셋 하나 + T-08의 원자료 + 지표 계층이 종목 밖 시계열을 받는 길이다.

## 버린 대안

- **D5를 0으로 두고 지수 없이 이식한다** — `progress.md`의 "결손이 생길 때마다 조건을 빼서 해결하지 않는다"에
  정면으로 걸린다. Tier가 원본과 다른 물건이 되고, 그 사실이 화면에 흔적을 남기지 않는다.
- **원주가 그대로 착수하고 P9를 나중에 한다** — 42종목 이상이 조용히 틀린 채 화면에 나온다.
  게다가 P9가 끝나면 전량 백필을 다시 돌아야 해 **같은 일을 두 번** 한다.
- **불연속을 감지해 해당 종목만 판정불가로 돌린다** — 30% 이내 기업행위를 못 잡으므로 방어가 새고,
  "원자료를 여는 길을 먼저 본다"(2026-08-10 사용자 판단, `ALTMAN_Z` 전례)에 어긋난다.
- **Tier 산출을 조건 엔진으로 표현한다** — `screen_condition`은 `지표 × 비교연산자 × {상수|지표×계수}`가
  전부라 52셀 매트릭스·9등급·Tier를 표현할 수 없다. 지표 계층에서 Tier까지 내는 것이 유일한 길이다.
- **원본 컬럼 48개를 전부 지표로 저장한다** — `score_a`~`score_m`·leaf·D2·D5 점수 16개는
  (수식자·단계·임계)에서 결정론적으로 유도되는 순수 중복이고, `indicator_value`가 2.4배가 된다.
  **30개로 좁혔고 기준은 "유도 가능성"이 아니라 "조건·정렬·진단 중 어디에 쓰이는가"다.**

## 결과

- **쉬워지는 것**: T-08(2년 주간 베타)이 계산기 하나만 남는다 — 이 phase가 새 테이블·어댑터·지표 계약을
  다 열기 때문이다. 지표 계층이 **종목 밖 시계열**을 받는 길이 처음 생기고, 이후 상대 지표가 그 길을 쓴다.
- **어려워지는 것**
  - **`maxEffectiveLookback`이 751 → 1,100으로 오른다.** 재귀 지표(`ATR_14`·`RSI_14`·`MACD`·`MACD_V`)의
    시드가 349봉 앞으로 가 **저장값이 미세하게 바뀌는데, 이 회귀는 테스트가 못 잡는다** — 테스트는 짧은
    픽스처를 쓰고 러너는 있는 만큼만 읽어 값이 그대로다. 배포 전후 대조로만 드러난다.
  - **`SHARES_GROWTH_3Y`의 쓰기 일자가 1 → 350으로 바뀐다.** 값은 같지만 쓰기 부피와 백필 특성이 달라지고,
    `TradingDays750Calculator` javadoc과 `batch-load` skill의 "실행당 1일치" 서술이 **낡는다.**
  - **`indicator_value`가 41 → 71 코드(약 1.7배, 전체 ≈1.8GB)가 된다.** 그래서 착수 순서에 제약이 하나 붙는다 —
    **2026-08-12 배치 뒤 인덱스 확인(ADR-0045의 최종 확인)이 끝나기 전에는 지표를 늘리지 않는다.**
    늘리면 인덱스가 커진 원인이 블로트 재발인지 새 데이터인지 가릴 수 없고, ADR-0045는 영영 미확인으로 남는다.
  - **P9의 범위가 넓어진다 — 거래량도 보정한다.** `PriceScaling`은 `adjClose/close` 비율을 곱하는 가격
    축척이라 거래량에 쓸 수 없고, `price_daily`에 `adj_volume`이 없다. 5:1 분할이면 분할 후 거래량이 5배가
    되고 그것이 주봉 OBV 누적에 영구히 남아 `drv_26 → drv_41 → score_d2`(±3)가 틀린다.
    **이 이식이 이 저장소에서 거래량 수정 문제를 처음 만나는 자리다** — ADR-0002는 거래량을 논의하지 않았다.
  - **원본의 4단 사전식 우선순위(신호강도 → 신선도 → 외부시그널 → 기둥)를 옮기지 못한다.** FILTER 모드에는
    서버 정렬이 없고(ADR-0016) 클라이언트 다중정렬은 사용자가 매번 맞춰야 한다.
    `ScreenPreset.description`에 결핍으로 적는다(ADR-0039의 MUST 승계).
  - **센티널(−1·−2)이 섞인 지표 6개가 생긴다.** 원본대로 저장하되 `bands`·`direction`을 붙이지 않고,
    "조건의 좌변으로 쓰지 말 것"을 `interpretation`에 적는다. `ICHI_FRESHNESS <= 5`가 −1(해당 없음)을
    통과시키고 정렬에서 −1이 맨 위로 오는 것이 남는 대가다.
- **되돌리려면**: `market_index_daily`와 지표 계약 확장은 T-08이 이어받으므로 남는다. 되돌릴 것은
  `ICHI_*` 지표 30개와 프리셋, 그리고 `maxEffectiveLookback` 값이다. **읽기 창을 되돌리면 재귀 지표
  저장값이 또 한 번 바뀐다** — 되돌리기가 무증상이 아니다.
