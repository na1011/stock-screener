# ADR-0074. 스윙 명세의 마지막 후손을 폐기하고, 그 근거를 결과 수에서 출처로 옮긴다

## 결정

`SWING_TREND_KR`을 폐기한다(2026-08-20 사용자 결정). `PresetCatalog`의 선언에서 빼면
`PresetSynchronizer`가 `is_active = false`로 내린다. 활성 프리셋은 아홉에서 여덟이 됐다.

**근거는 출처다.** 이것은 `docs/external/screener-spec-midterm-swing.md`의 자리를 물려받은
프리셋이고, javadoc이 T-08·H-02·S-02를 「원문에서 되살린 것」으로 적어 **그 명세의 조항 ID를
직접 인용하는 유일한 활성 프리셋**이었다. 그 명세가 지배하던 원래 프리셋은 2026-08-14에
테스트베드로 판정돼 폐기됐고(ADR-0061), 나머지 프리셋 다섯은 문헌을 이름으로 댄다
(Piotroski/Sloan/Novy-Marx · Minervini · Weinstein · Connors · 저변동성 이상현상).

**MUST NOT: 이 폐기를 「0건이라 걷었다」로 읽지 않는다.** 폐기 시점에 이 프리셋의 결과는
실제로 0건이었으나 **그것은 근거가 아니다.** 아래 §갈래 보고가 원인을 국면으로 귀속시킨다.

## 규칙

- **MUST: 프리셋 코드를 하드코딩한 펜스는 폐기와 같은 커밋에서 걷는다.** 폐기는
  `is_active = false`일 뿐 **`screen_condition` 행은 남으므로**(ADR-0017), 그 코드로 DB를 재던
  펜스는 폐기된 프리셋을 재면서 **영원히 `OK`를 내는 실패할 수 없는 펜스**가 된다. 이번에
  ADR-0039에서 셋을 걷었다 — 결핍 낱말 여섯, 규모 조건 premise, 깔때기 SQL의 정본 참조.
- **MUST NOT: 결과 수를 프리셋 폐기의 근거로 쓰지 않는다.** `phase-criteria.md`가 0건 예외의
  부여를 금지하는 것과 같은 자리다. **폐기는 「조건을 고친다」보다 강한 조치이므로 그 금지에
  더 세게 걸린다.** 0건이면 갈래 보고를 먼저 내고, 폐기하려면 **결과 수가 아닌 근거**를 댄다.
- **MUST NOT: 조건 수 여유(`상한 - 사용`)를 테스트에서 단언하지 않는다.** 이 프리셋이 24개로
  상한 25에 붙어 있어 「여유 ≥ 1」이 뜻을 가졌지만, 폐기 후 최대가 17로 내려와 여유가 8이 됐다.
  그 형태를 유지하면 **새로운 실패할 수 없는 펜스**가 된다. `PresetCatalogTest`는 여유가 아니라
  **가장 큰 프리셋의 조건 수 자체**를 숫자로 못박는다.
- **MUST NOT: 소비자를 잃은 지표를 지우지 않는다.** 아래 §지표 넷 참조.

## 갈래 보고 — 0건의 원인은 국면이다

`phase-criteria.md`가 요구하는 형태로 폐기 직전에 냈다. 기준일은 2026-08-20, 모집단은 최신
`ADJ_CLOSE`가 있는 **347종목**이다(`universe_membership` 활성 편입은 350이지만 그 수로는
재현되지 않는다).

**게이트별 단독 통과(필수 17개):**

| 게이트 | 통과 | 게이트 | 통과 |
|---|---|---|---|
| `TRADING_DAYS_750` | 314 | `SMA_200_SLOPE_60` | 238 |
| `DISPARITY_200` | 295 | `DEBT_RATIO_SECTOR_REL` | 215 |
| `PROFITABLE_QUARTERS_4` | 283 | `SMA_200_MOM_21` | 214 |
| `MARKET_CAP` | 273 | `ALTMAN_Z` | 190 |
| `SMA_150` | 259 | `SMA_60` | 144 |
| `BETA_104W` | 253 | `ADJ_CLOSE > SMA_200` | 128 |
| `DEBT_RATIO` | 246 | `ATR_PCT_14` | 109 |
| `TURNOVER_60` | 245 | **`PCT_FROM_52W_HIGH`** | **66** |
| `PCT_FROM_52W_LOW` | 242 | | |

**통과 게이트 수 분포**(누적 교집합이 아니다 — 그것은 얹는 순서에 따라 값이 달라져 재현되지
않는다, ADR-0070): 17개 **0** · 16개 **6** · 15개 18 · 14개 36.

**16/17을 넘은 여섯이 서로 다른 게이트에서 걸린다** — LG는 52주 고점, GS리테일·씨젠은
거래대금, 한올바이오파마는 ATR, KT&G는 업종 부채배수, BGF리테일은 부채비율이다.

**판정: ③ 시장 국면.** 어느 게이트도 지배하지 않는다. 그리고 이 수는 ADR-0044가 2026-08-13에
낸 판정과 **같다** — 그때가 67~314(가장 좁은 것이 52주 고점 67종목)이고 지금이 66~314다.
**일주일 사이 프리셋 쪽에서 바뀐 것이 없다.** 1건 → 0건은 시장이 한 칸 더 내려온 것이다.

`PresetCatalog`의 javadoc이 *「`DISPARITY_200 <= 1.25`가 이 프리셋의 성격을 정한다 — 급등
종목이 구조적으로 나오지 않으며 그것은 부작용이 아니라 설계다」*라고 적었다. 조정장의 0건은
그 설계의 예상 출력이다.

## 지표 넷이 활성 소비자를 잃었다

활성 프리셋 중 이 프리셋만 쓰던 지표가 넷이다.

| 지표 | 나온 자리 |
|---|---|
| `ALTMAN_Z` | ADR-0040 — 결손 컬럼을 좁게 재수집해 0건을 푼 성과 |
| `OPERATING_MARGIN_SECTOR_PCTL` | ADR-0044 — 업종 축 |
| `TRADING_DAYS_750` | ADR-0039의 U-05 premise가 지금 재는 값 |
| `DISPARITY_200` | 이 프리셋의 성격을 정하던 조건 |

**넷 다 남긴다.** 근거는 `ICHI_*` 18개와 같다(ADR-0061) — **조건 빌더에서 계속 고를 수 있고,
사용자가 저장한 전략이 그것을 건다.** 지우면 그 전략이 조용히 판정불가가 된다.

**관련 ADR의 `## 검증`은 손대지 않았다.** 셋 다 프리셋 소비가 아니라 **계산기와 모집단**을
재기 때문이다 — ADR-0040은 보험·금융서비스에 `ALTMAN_Z` 행이 없는지, ADR-0044는 백분위가
유니버스 안에서 매겨지는지와 업종 커버리지를, ADR-0039의 U-05는 `SHARES_GROWTH_3Y` 보유가
`TRADING_DAYS_750` 통과의 부분집합인지를 잰다. **다만 U-05 premise에 걸린 것이 좁아졌다** —
붉어져도 조용히 바뀌는 활성 프리셋이 이제 없고, 남은 소비자는 사용자 저장 전략이다.
그 사실을 ADR-0039에 적었다.

## Phase 7 완료 판정은 무엇을 근거로 서는가

`phase-criteria.md`의 Phase 7 기준 셋이 프리셋 이름에 묶여 있었고, 그중 「프리셋 설명이
원본에서 옮기지 못한 조건을 명시한다」의 검증을 ADR-0039가 이 프리셋으로 옮겨 두었다.
**대상이 사라졌으므로 그 검증은 비활성 행을 재며 영원히 초록이 된다** — 그래서 걷었다.

**「7 완료」는 취소하지 않는다. 근거는 이것이다.** Phase 7이 물은 것은 **「필수 조건이라는 새
축이 기존 두 판정 방식을 깨지 않는가」**와 **「외부 명세를 옮기며 없는 것을 있는 것처럼 만들지
않았는가」** 둘이었다. 앞의 축은 프리셋과 무관하게 코드에 남아 계속 검증된다(`required`가
SCORING에서 종목을 빼는가, 점수·달성률에 섞이지 않는가, 판정불가가 통과로 읽히지 않는가 —
전부 테스트가 잡는다). 뒤의 축은 **이식이 정직했는가에 대한 판정이고, 그 판정은 ADR-0039의
대조표가 기록으로 들고 있다.** 이식물을 나중에 걷는 것이 「그때 정직하지 않았다」로 소급되지는
않는다.

**MUST NOT: 이것을 「기준이 대상 없이도 통과한다」로 읽지 않는다.** 기준은 지우지 않고 남기며
(`phase-criteria.md`가 금지한다), 다음 프리셋 이식이 그 회귀 체크리스트를 그대로 쓴다.

## 검증

`PresetCatalog`에 이 코드가 남아 있지 않아야 한다:

```bash
rg -n "SWING_TREND_KR" src/main/java/
```

DB에서 비활성인지 — **행은 남아 있어야 한다**(ADR-0017은 DELETE를 금지한다):

```bash
psql -d stock_screener -At -c "SELECT code || ' is_active=' || is_active FROM screen WHERE code = 'SWING_TREND_KR'"
```

`SWING_TREND_KR is_active=f`가 나와야 한다. 아무것도 안 나오면 행이 지워진 것이고, `t`면
선언에서 안 빠진 것이다.

폐기된 프리셋을 코드로 하드코딩해 재는 펜스가 남지 않았는지 — **아무것도 반환하지 않아야
한다.** 주석·기록 문단은 걸리지 않도록 SQL 안의 문자열 리터럴만 본다. **이 문서를 빼는 이유는
바로 위 명령이 같은 형태이기 때문이다** — 안 빼면 이 펜스가 자기 자신을 잡고 영원히 붉다:

```bash
rg -n "code *= *'(SWING_TREND_KR|SWING_MIDTERM_KR|QVG_KR|ICHIMOKU_SP_KR)'" \
  docs/adr/ .claude/ --glob '!ADR-0074-*'
```

```premise 활성 프리셋이 전부 코드 선언에서 온다
psql -d stock_screener -At -c "WITH a AS (SELECT count(*) n FROM screen WHERE screen_type = 'PRESET' AND is_active), d AS (SELECT count(*) n FROM screen WHERE screen_type = 'PRESET' AND NOT is_active) SELECT CASE WHEN (SELECT n FROM a) = 0 THEN '활성 프리셋이 0개다 — 시더가 안 돌았거나 선언이 비었다' WHEN (SELECT n FROM a) <> 8 THEN '활성 프리셋이 ' || (SELECT n FROM a) || '개다(선언은 8개) — PresetCatalog와 DB가 갈렸다. 앱을 띄우면 동기화된다' ELSE 'OK 활성 ' || (SELECT n FROM a) || ' / 폐기 보관 ' || (SELECT n FROM d) END"
```

## 버린 대안

- **버핏·린치 외 여섯을 전부 폐기** — 최초의 사용자 지시가 이것이었다. 재보니 근거가 갈렸다:
  「근거가 빈약한 테스트베드」는 `SWING_MIDTERM_KR`·`ICHIMOKU_SP_KR`을 가리키는 말이고 그 둘은
  이미 폐기돼 있었으며, 나머지 다섯은 javadoc이 문헌을 이름으로 댄다. **그 사실을 보고하고
  범위를 하나로 좁혔다.**
- **0건을 근거로 폐기** — 첫 계획이 이 형태였고 독립 반증이 잡았다. `phase-criteria.md`가
  금지하는 형태이며, 갈래를 실제로 재보니 원인이 국면이었다. **근거를 출처로 바꿨다.**
- **폐기하지 않고 0건 예외를 승계** — 원래 물었던 것이고 코드 변경이 0이다. 버린 이유는
  **명세의 후손을 언제까지 들고 갈 것인가가 남기 때문**이다. 사용자가 출처를 근거로 정리하는
  쪽을 골랐다.
- **`screen` 행을 DELETE** — ADR-0017이 금지한다. 워치리스트·상호작용 로그가 `screen_id`를
  참조하고, 비활성 행은 그 참조를 살려 둔 채 화면에서만 사라진다.
