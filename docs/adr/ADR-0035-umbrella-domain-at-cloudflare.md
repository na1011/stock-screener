# ADR-0035. 우산 도메인을 Cloudflare Registrar에서 사고 앱은 서브도메인에 둔다

## 결정

`na1011.net`을 Cloudflare Registrar에서 등록하고(연 $11.86), 이 앱의 주소는 서브도메인 **`screener.na1011.net`**으로 한다. 프로젝트마다 도메인을 사지 않는다.

## 규칙

- MUST: 다음 프로젝트도 새 도메인이 아니라 이 도메인의 **서브도메인**을 쓴다. Tunnel이 호스트명별로 다른 로컬 포트에 붙으므로 Public Hostname만 추가하면 된다. 서브도메인은 개수 제한도 추가 비용도 없다.
- MUST: 자동 갱신을 켜 둔 상태로 유지한다. 만료되면 사이트뿐 아니라 **OAuth 리디렉션까지 한꺼번에 끊긴다.**
- MUST: 엣지의 `Always Use HTTPS`를 켠 채로 유지한다(`SSL/TLS → Edge Certificates`). 끄면 평문 요청이 터널을 타고 그대로 들어오고, Spring이 `X-Forwarded-Proto: http`를 신뢰해 `redirect_uri`를 `http://`로 만들어 Google이 `redirect_uri_mismatch`를 낸다. **화면은 200으로 멀쩡히 뜨고 로그인만 깨진다.** 2026-08-10에 실제로 이 상태였다 — `forward-headers-strategy`가 옳게 들어 있어도 **클라이언트가 http로 말하면 소용이 없다.** 그 설정은 스킴을 헤더에서 읽으라는 것이지 https를 강제하는 것이 아니다.
- MUST NOT: `.kr`·`.co.kr`을 Cloudflare Registrar에서 사려 하지 않는다 — **지원하지 않는다.** 한국 ccTLD가 필요해지면 등록처를 나눠야 하고, 그때는 네임서버 변경과 전파 대기가 다시 생긴다.
- MUST NOT: 등록처를 다른 곳으로 옮기지 않는다. 옮기는 순간 아래 "전파 대기가 없다"는 이점이 사라진다.

## 검증

```bash
dig NS na1011.net +short
```
`*.ns.cloudflare.com` 두 개가 나와야 한다. 다른 네임서버가 보이면 등록처나 위임이 바뀐 것이고, Tunnel 라우트가 조용히 죽는다.

```bash
curl -I https://screener.na1011.net/
```
`200`이어야 한다. `502`면 앱이 안 떠 있거나 Tunnel의 Service Type을 `HTTPS`로 잡은 것이지 도메인 문제가 아니다.

**MUST NOT: 위 `https` 확인만으로 로그인이 산다고 판정하지 않는다.** https만 재면 평문 진입점이 열려 있어도 통과한다 — 2026-08-10의 고장이 정확히 그렇게 통과했다. 아래 전제가 그 나머지 절반이다.

```premise 엣지가 평문 http를 https로 올린다
R=$(curl -sS -o /dev/null -m 5 -w '%{http_code} %{redirect_url}' http://screener.na1011.net/) || exit 1
case "$R" in
  30[178]" "https://*) echo "OK $R" ;;
  30[178]" "*)         echo "리다이렉트는 하는데 대상이 https가 아니다: $R" ;;
  *)                   echo "평문 http가 그대로 응답한다($R) — Always Use HTTPS가 꺼졌다. 도메인 로그인이 redirect_uri_mismatch로 깨진다" ;;
esac
```

네트워크가 없으면 `curl`이 비정상 종료해 **판정 불가**로 잡힌다. 거짓 `OK`가 나오지 않는 쪽으로 기울여 둔 것이다.

## 배경

spec §6이 외부 접속 경로로 Cloudflare Tunnel을, 인증으로 Google OAuth를 이미 확정했다. 둘 다 **고정 HTTPS 도메인**을 요구하는데 spec은 "개인 도메인을 보유·구매할 의향이 있다"까지만 정하고 어떤 이름을 어디서 살지는 비워 두었다. 이 기록이 그 빈칸을 채운다.

**등록처를 Cloudflare로 정한 이유는 이미 Tunnel이 확정돼 있었기 때문이다.** 같은 곳에서 등록하면 zone이 자동 생성되고 네임서버가 처음부터 Cloudflare라 **네임서버 변경과 전파 대기(수 시간~48시간)가 통째로 사라진다.** 등록 대행 마진도 없다(도매 원가 판매). WHOIS 개인정보 대행은 기본 제공이라 별도 결제 항목이 아니다.

**프로젝트 도메인이 아니라 우산 도메인을 산 이유는 범위가 변한다는 것이다.** 이 스크리너는 v1.1에 미국 시장이 붙으므로(ADR-0010) `jongmok`(종목) 같은 이름을 샀다면 이미 어긋났을 것이다. 우산 도메인은 프로젝트 범위가 바뀌어도 주소가 죽지 않고, 갱신비가 프로젝트 수만큼 늘지 않는다.

**이름은 GitHub 사용자명과 철자를 맞췄다.** 포트폴리오 주소와 저장소 주소가 어긋나지 않는다.

이 결정은 2026-08-08에 내려 실행했고, 근거는 발급 목록 문서에 흩어져 있었다. 그 문서를 걷으면서 여기로 옮겼다.

## 버린 대안

- **`na1011.com`** — 쓸 수 없다. 2026-04-27에 이미 등록됐다(A 레코드 없이 보유만 하고 있다, RDAP 조회 2026-08-08).
- **`na-1011.com`** — 등록업체가 제시한 대안이지만 **하이픈이 부채다.** 구두로 전달할 때마다 설명이 필요하고, 빠뜨린 오타가 남의 도메인으로 간다.
- **`.dev`** — 용도 제한이 있는 TLD는 아니지만(Google Registry의 범용 gTLD) **비개발자에게 개발·테스트 사이트로 읽힌다.** 지인이 쓰는 서비스라 인상이 비용이다.
- **`.co`** — 인상은 낫지만 연 $25 수준이라 `.net` 대비 차액만큼의 이득이 없었다.
- **프로젝트마다 도메인 구매** — 갱신비가 프로젝트 수에 비례해 늘고, 범위가 바뀐 프로젝트의 이름이 그대로 남는다.

## 결과

- 쉬워지는 것: 다음 프로젝트는 도메인 구매도 DNS 작업도 없다. Tunnel 상세 화면에서 Public Hostname 하나를 추가하면 끝난다.
- 어려워지는 것: 한국 ccTLD를 원하게 되면 등록처가 둘로 갈린다.
- 되돌리려면: 새 도메인 등록 + Tunnel 라우트 재생성 + **Google OAuth 승인된 리디렉션 URI 교체**가 함께 필요하다. 마지막 것을 빠뜨리면 화면은 뜨는데 로그인만 깨지고, 호스트는 맞고 스킴·호스트명만 다른 형태라 화면만 봐서는 원인을 못 찾는다(ADR-0018).
