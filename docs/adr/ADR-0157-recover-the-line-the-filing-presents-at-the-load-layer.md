# ADR-0157. 은행 매출을 복원하고, ADR-0104의 계층 규칙을 다시 연다

## 결정 1 — 은행의 매출은 **순이자손익 + 비이자수익**이다

미국 은행형 종목(두 재료를 **다 내는** 회사)의 `revenue`를 그 합으로 만든다.
**재료가 하나라도 없으면 유도하지 않는다.**

## 결정 2 — ADR-0104의 계층 규칙 둘을 다시 연다

ADR-0104 §규칙의 다음 둘을 **이 결정이 대체한다.**

> - MUST NOT: 유도를 적재 계층으로 내리지 않는다.
> - MUST NOT: 실적 원수치 화면에 유도값을 넣지 않는다.

**새 경계는 계층이 아니라 「화면이 거짓을 말하는가」다.**

- **적재 계층에서 유도한다** — 소스가 **그 개념을 다른 태그로 이미 말하고 있고**, 유도값이 그
  태그와 일치함을 실측으로 보일 수 있을 때.
- **지표 계층에서 유도한다** — 그 개념이 **공시에 없고 우리가 만드는 것**일 때
  (ADR-0104의 은행 영업이익이 그 자리다. 은행은 영업이익을 신고하지 않는다).

## 왜 다시 여는가 — **그 규칙을 지키면 화면이 틀린 값을 말한다**

ADR-0104의 근거는 *"거기에 유도값을 넣으면 화면이 공시와 어긋난다"*였다. **이 자리에서는
정반대가 된다.**

| 종목 | 규칙을 지킬 때 화면 | 유도할 때 화면 | 어느 쪽이 참인가 |
|---|---|---|---|
| `WAL` FY2025 | **136M** | **3,543M** | 유도 — 소스의 `Revenues`가 좁은 하위 항목이다 |
| `ZION` FY2025 | **662M** | **3,385M** | 유도 |
| `RF` FY2025 | **비어 있음**(= "안 신고했다") | **7,526M** | 유도 |

**규칙의 목적이 「화면이 공시와 어긋나지 않게」인데, 규칙을 지키는 쪽이 어긋난다.**
낡아서가 아니라 **축이 거칠어서**다 — 「적재/지표」로 갈랐는데 실제 축은 「복원/생성」이었다.

**MUST: 이 결정이 ADR-0104를 통째로 뒤집는 것이 아니다.** ADR-0104의 §결정
(영업수익 − 영업비용 · **2026-08-31 사용자 결정**)과 나머지 세 규칙은 그대로다.
다시 여는 것은 **에이전트가 쓴 계층 규칙 둘**뿐이다.

## 측정

**이 공식은 우리가 정한 정의가 아니다** — 소스가 이미 그렇게 쓴다(2026-09-15 · `.factcache/` 407종목).

| 물음 | 답 |
|---|---|
| 소스가 `Revenues`를 제대로 내는 은행 15 중 저장/공식 = 1.00 | **14** (`BAC`·`C`·`JPM`·`USB`·`PNC`·`COF`…) |
| 회사 자신이 붙인 `RevenuesNetOfInterestExpense`와 일치 | **92/96 (95.8%)** |
| 총액 공식(총이자수익 + 비이자수익)이 맞는 칸 | **2/257 (0.8%)** — 기각 |
| `US_TOP1000` 최신 FY 은행형 69 중 결손·과소 | **NULL 27 · 비이자수익보다도 작은 과소 11** |
| 과소 크기 | `WAL` **26.1배** · `AX` 18.2배 · `COLB` 13.0배 · `ZION` 5.1배 · `AXP` 1.7배 |
| 유도 대상(두 재료를 다 내는 종목) | **53종목 · 전부 금융**(DB 전수) |

## 규칙

- MUST: **두 재료가 다 있을 때만 유도한다.** `NoninterestIncome`은 금융 전용 태그가 아니다 —
  `MPLX`(파이프라인 MLP)가 매출의 80%를 그것으로 낸다. 둘을 요구하면 대상이 금융으로 닫힌다.
- MUST NOT: **소스가 준 값과 큰 쪽을 고르지 않는다(`max`).** 두 가지를 깨뜨린다 —
  `STT` FY2023은 같은 10-K 안에서 `Revenues` 11,945M인데 `max`가 12,239M을 골라 **과대계상**이
  되고(둘 어디에도 안 드는 별도 라인 −294M), `IBKR`은 해마다 승자가 갈려 **매출성장률 부호가
  −14.0% ↔ +14.5%로 뒤집힌다.**
- MUST: **재료가 있으면 언제나 유도한다.** **스크리너는 성장률·5년 중앙값을 읽으므로 한 종목
  안에서 기저가 하나인 것이 셀 단위 충실도보다 앞선다.** 소스가 제대로 신고하는 자리에서는
  둘이 같다(같은 공시 안에서 **89.5%**가 1% 이내).

## 함께 고친 것 — `InterestExpense`의 택소노미 퇴역

`InterestExpense`가 2024년 US-GAAP 택소노미에서 사실상 퇴역하고 `InterestExpenseOperating`이
그 자리를 받았는데 **우리 후보가 하나뿐이라 조용히 무너져 있었다.**
은행형 행의 이자비용 보유가 **FY2023 60/66 → FY2024 8/65 → FY2025 8/69**로 떨어졌고,
ADR-0104의 **은행형 영업이익 유도 재료 셋을 다 갖는 행이 44 → 5**가 됐다.
둘 다 오는 110칸에서 **109(99.1%)**가 1% 이내로 같다. 후보만 더하면 **5 → 46종목**이 산다.

## 검증

```bash
# 재료가 하나만 있을 때 유도가 안 도는가 — 둘을 함께 요구해야 한다
rg -n -A 8 "private static BigDecimal revenue\(" \
  src/main/java/com/stockscreener/pipeline/datasource/us/SecEdgarFacts.java \
  | rg -c "netInterest != null && noninterest != null"   # 1이 나와야 한다
```

## 버린 대안

- **총액(총이자수익 + 비이자수익)으로 국내와 맞춘다** — 국내 소스가 총액 쪽이라 대칭이 되지만
  **미국 소스와 0.8%밖에 안 맞는다.** 맞는 값 14종목을 틀리게 만든다.
- **`max(소스, 유도)`** — 위 §규칙의 두 반례로 기각(독립반증이 찾았다).
- **안 고치고 은행을 매출 조건에서 제외한다** — 지금 맞는 15종목까지 죽인다. 그리고
  **틀린 값 11종목은 그대로 남는다.**
- **`RevenuesNetOfInterestExpense`를 후보에 넣는 것으로 끝낸다** — NULL 27 중 **4만** 덮고,
  `HWC` FY2011이 728M 대신 979M(+34%)이 된다(독립반증 실측).

## 결과

**닫힌 것**(재적재 뒤 전수 · `US_TOP1000` 최신 FY)

| | 전 | 후 |
|---|---|---|
| 은행형 종목의 매출 NULL | **27** | **0** |
| 매출이 비이자수익보다 작은 과소 | **11** | **0** |
| 은행형 이자비용 보유 | **8** | **54** |
| `OPERATING_MARGIN` 미국(최신 거래일) | 795 | **840** |

`ROE` 미국 **908** · `DEBT_RATIO` 미국 **926**. **국내는 재무행 17,485 그대로**이고
`total_equity_controlling`이 **0행**이다.

**함께 드러난 결함 하나를 고쳤다** — 유도가 적재 계층에 들어오면서 `financial_column_absence`가
**「태그의 유무」를 말하는데 저장은 「유도된 값」**을 갖게 됐다. 그 결과 화면이 `ABBV`·`KO`·
`WMT`의 총부채와 `GS`·`TFC`의 매출에 **수를 보여주면서 "소스가 안 냅니다"**라고 말했다
(전수 **226종목**). ADR-0147의 전제가 그것을 잡았고, 값이 난 컬럼의 부재 행을 빼서 **226 → 0**.

**전제 전수**: 세션 시작 **참 128 · 발견 5 · 판정 불가 2** → **참 129 · 발견 6 · 판정 불가 0.**

**남는 것 — 화면이 유도값을 표시하지 못한다.** `StockFinancialsAssembler`는
`netIncome`·`operatingCashFlow`·`totalLiabilities`·`totalEquity`·`revenue`를 그대로 그리는데
**어느 것이 소스값이고 어느 것이 유도값인지 저장에 없다.** P13이 경계한
*"소스가 준 것처럼 보이는 자리"*가 그대로 남는다. **이 결정은 그 자리를 안 닫는다** —
지금은 유도값이 **더 참**이라 화면이 나아지지만, 출처 표시는 별도 칸이다(`docs/progress.md`).
