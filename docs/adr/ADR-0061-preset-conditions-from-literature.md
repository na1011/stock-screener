# ADR-0061. 프리셋 조건의 출처를 문헌으로 두고, 테스트베드 둘을 폐기한다

> **2026-08-20 — 아래에서 새로 세운 넷 중 `SWING_TREND_KR`이 폐기됐다**(ADR-0074, 사용자 결정).
> 근거는 결과 수가 아니라 **출처**다 — 그것만이 폐기된 외부 명세의 조항 ID를 직접 인용했다.
> **이 결정의 나머지는 그대로다**: 조건 출처를 문헌에 두는 것도, 셋을 갈라 적는 규칙도,
> 폐기를 `is_active=false`로만 하는 것도 계속 지배한다. 프리셋은 일곱에서 여덟이 됐다가
> (버핏 추가) 지금 **여덟**이다.

## 결정

프리셋 조건을 **실제로 검증된 스크리닝 이론**에서 가져온다. 각 조건이 어느 문헌·어느 기관
기준에서 왔는지를 `PresetCatalog`의 javadoc이 적고, **원문 그대로 옮긴 것 / 국내 분포로
재보정한 것 / 원문에 없는데 더한 것** 셋을 갈라 적는다.

`SWING_MIDTERM_KR`과 `ICHIMOKU_SP_KR`을 폐기한다(2026-08-14 사용자 결정 — **둘 다
지표를 늘려 보기 위한 테스트베드였다**). 그 자리에 `SWING_TREND_KR`·`STAGE2_BREAKOUT_KR`·
`PULLBACK_UPTREND_KR`·`LOWVOL_QUALITY_KR`을 둔다. 프리셋은 다섯에서 일곱이 됐다.

## 규칙

- **MUST: 조건의 출처를 셋으로 갈라 적는다.** 갈리지 않으면 다음 세션이 **우리가 정한 값을
  문헌이 검증한 값으로 읽는다.** 이것이 이 결정의 핵심이며 나머지는 그 따름이다.
- **MUST: 절대 임계값은 국내 분포를 재고 정한다.** 미국 문헌의 값을 그대로 옮기면 그 값이
  재는 위치가 달라진다. 실측 둘이 근거다 — 2년 주간 베타 1.3은 국내에서 **82%가 통과**했고
  (중앙값이 1이 아니라 0.75다), 거래량 「평소의 2~3배」는 국내에서 **상위 10%에도 못 미친다.**
- **MUST NOT: 통과율이 90%를 넘는 조건을 필수 게이트에 두지 않는다.** 게이트 개수는
  안전장치의 개수로 읽힌다. 초안의 발생액 ≤0.10이 **96% 통과**였고, 그 상태는 화면·테스트·
  배치 로그 어디에도 드러나지 않았다.
- **MUST NOT: 결과 수를 근거로 임계값을 풀지 않는다.** 원인을 ① 조건 ② 데이터 ③ 시장 국면
  으로 가른 뒤 숫자만 보고한다. 가르는 법은 **게이트별 단독 통과 수**다 — 각 게이트가 홀로
  충분히 통과시키는데 교집합만 좁으면 국면이다.
- **MUST NOT: 없는 조건을 근사로 메우지 않는다.** 막히면 **원자료를 여는 길을 먼저 본다.**
  눌림목이 그 사례다 — 스토캐스틱으로 근사할 뻔했으나 `RSI_2` 계산기 하나로 원문이 그대로
  열렸다(원자료는 이미 있었다). 근사로 갔으면 원문보다 좁은 조건을 「Connors 이식」이라
  부르게 됐다.
- **MUST: 옮기지 못한 조건과 없어진 안전장치를 `description`에 적는다.** 결핍은 어떤 에러도
  내지 않고 화면에도 흔적이 없다.
- **MUST NOT: 추세 프리셋을 「알파의 원천」으로 설명하지 않는다.** 한국 시장에서 모멘텀
  이상현상은 코스피만 보면 재현율이 20%로 떨어지고 우리 유니버스는 대형주뿐이다.
- **MUST NOT: `ICHI_*` 18개를 「쓰는 프리셋이 없다」는 이유로 지우지 않는다.** 근거는
  **조건 빌더에서 계속 고를 수 있다**는 것 하나이고, **미사용 지표 전부에 똑같이 걸린다**
  (2026-08-20 실측 57개). 애초 근거였던 「그 18개가 읽기 창을 붙들고 있다」는 ADR-0066이
  죽였다 — 지금은 지워도 창이 안 내려간다.
- **MUST: 읽기 창을 바꿀 때 U-05를 함께 본다.** ADR-0039가 「읽기 창이 바뀌면 U-05가 기존
  게이트보다 강하게 자르기 시작하는데 결과 수는 그대로일 수 있어 화면에서 안 드러난다」고
  경고했다. 이 경고는 창의 주체가 무엇이든 유효하다.
- **MUST NOT: 폐기한 프리셋의 `screen` 행을 DELETE하지 않는다**(ADR-0017). `is_active=false`
  뿐이며, **`screen_condition` 행은 남는다** — 프리셋 이름을 하드코딩한 자동 펜스가 그것을
  계속 재면 **실패할 수 없는 펜스**가 된다.
- **MUST: 프리셋 조건을 바꾸면 그것을 참조하는 워치리스트의 `last_satisfied`를 NULL로
  되돌린다.** 시더 경로에는 그 리셋이 없다(`WatchlistStore`의 리셋은 사용자가 `screen_id`를
  바꿀 때만 돈다). 되돌리지 않으면 다음 배치에서 **프리셋 정의가 바뀐 것을 「종목이 조건을
  새로 충족했다」로 알린다.**

## 검증

절대 임계를 쓴 조건들이 **분포 이동으로 뜻을 잃지 않았는가**. 백분위 조건은 자동 적응하므로
전제가 아니다.

```premise 프리셋의 절대 임계가 의도한 분위에 아직 앉아 있다
psql -d stock_screener -At -c "WITH d AS (
  SELECT indicator_code, value,
         percent_rank() OVER (PARTITION BY indicator_code ORDER BY value) pr
  FROM indicator_value
  WHERE trade_date = (SELECT max(trade_date) FROM indicator_value)
    AND indicator_code IN ('ATR_PCT_14','VOLUME_RATIO_20','BETA_104W')),
p AS (
  SELECT
    max(pr) FILTER (WHERE indicator_code='ATR_PCT_14'      AND value <= 5.9) atr,
    max(pr) FILTER (WHERE indicator_code='VOLUME_RATIO_20' AND value <  1.5) vol,
    max(pr) FILTER (WHERE indicator_code='BETA_104W'       AND value <= 0.40) beta
  FROM d)
SELECT CASE
  WHEN (SELECT count(*) FROM d) = 0 THEN '잴 것이 없었다 — 세 지표 중 하나도 값이 없다'
  WHEN atr IS NULL OR vol IS NULL OR beta IS NULL
    THEN '한 임계가 분포 밖으로 나갔다 — 통과가 0이거나 전부다'
  WHEN atr BETWEEN 0.15 AND 0.45 AND beta BETWEEN 0.15 AND 0.45 AND vol BETWEEN 0.6 AND 0.9
    THEN 'OK ATR ' || round(atr::numeric,2) || ' / 베타 ' || round(beta::numeric,2)
       || ' / 거래량 ' || round(vol::numeric,2)
  ELSE (SELECT string_agg(t, ' · ') FROM (
      SELECT 'ATR ' || round(atr::numeric,2) t FROM p WHERE atr NOT BETWEEN 0.15 AND 0.45
      UNION ALL SELECT '베타 ' || round(beta::numeric,2) FROM p WHERE beta NOT BETWEEN 0.15 AND 0.45
      UNION ALL SELECT '거래량 ' || round(vol::numeric,2) FROM p WHERE vol NOT BETWEEN 0.6 AND 0.9) x)
    || ' 축만 밴드 밖이다(나머지는 안). **임계가 움직였다는 뜻이 아니다** — 등록 근거는 같은 날 단면이고(phase-criteria의 「검증된 이론 기반 프리셋 개편」 절), 그 기준으로 다시 재기 전에는 국면과 못 가른다. **MUST NOT: 이것을 근거로 임계를 풀지 않는다**(§규칙)' END
FROM p"
```

> **2026-08-20 — 위 분위 펜스가 붉다. 거래량 하나 때문이고, 임계를 풀 근거가 아니다.**
> 실측 `ATR 0.29 / 베타 0.28 / 거래량 0.94`인데 앞의 둘은 의도(하위 30%)에 앉아 있고 거래량만
> 밴드 상단(0.9)을 넘었다. **날짜별로 재보면 08-12부터 0.89·0.82·0.88·0.84로 내내 상단에
> 붙어 있다가 08-19에 넘어갔다** — 임계 1.5배가 움직인 것이 아니라 시장의 거래량이 20일
> 평균 대비 조용해진 것이다.
>
> **MUST NOT: 이것을 근거로 1.5배를 내리지 않는다**(위 §규칙의 「결과 수를 근거로 임계값을
> 풀지 않는다」가 그대로 걸린다). 판단이 필요한 것은 **밴드 상한 0.9가 국내 분포에 비해
> 좁은가**이고, 그건 이 펜스가 아니라 사람이 정한다.
>
> **MUST NOT: 이 펜스를 보존 창 전체를 합친 분포로 다시 재지 않는다.** 등록 근거가 **같은 날
> 단면**이라(`phase-criteria`의 「검증된 이론 기반 프리셋 개편」 절, 2026-08-13) 창을 바꾸면
> 다른 임계를 재게 된다. 실제로 그렇게 재어 **셋 다 신고와 어긋난다**는 결론에 도달한 적이
> 있는데(풀 45.2% / 17.4% / 13.1%), 등록 기준으로 같은 날 다시 재면 **ATR 29.6% · 베타 27.3%로
> 등록값 그대로이고 어긋난 것은 거래량뿐**이다(2026-08-25). 창이 답을 정하는 측정으로는
> 임계를 판정할 수 없다.

조건의 출처가 코드에 남아 있는지 — 아래가 **활성 프리셋 수(지금 8) 이상**이어야 한다.
프리셋마다 셋 중 적어도 하나는 해당하기 때문이다. **하한이지 목표가 아니다** — 2026-08-14에
14줄이었고 2026-08-20 실측이 **27줄**이라(폐기된 프리셋의 표기 둘이 함께 빠졌다) 여유가 크다. 이 펜스가 잡는 것은 「출처 표기가
통째로 사라졌는가」이고, 프리셋 하나의 표기가 빠지는 것은 못 잡는다(그건 javadoc을 읽어야 한다).

```
rg -c "원문 그대로|국내 분포로 재보정|원문에 없는데 더한|원문보다 약하게 옮긴" src/main/java/com/stockscreener/screening/preset/PresetCatalog.java
```

## 배경

지표가 84개로 늘었는데 **프리셋이 쓰는 것은 33개뿐**이었고, 최근 더한 오실레이터
(`ADX_14`·`CMF_21`·`MFI_14`·`STOCH_*`·`BOLLINGER_PCT_B`·`OBV_T_13`·`VOLUME_RATIO_20`·
`MACD_V_PCTL`·`DISPARITY_200`·`MA_ALIGN_SCORE`·`GOLDEN_CROSS_AGE`)는 **어느 조건에도**
쓰이지 않았다. 조건 재료는 풍성해졌는데 그것을 묶는 전략이 그대로였다.

임의로 조합하면 통과 종목이 바뀌면서 **왜 바뀌었는지 답할 수 없게 된다.** 그래서 출처를
문헌으로 고정했다.

**국내 재현율이 설계를 셋 바꿨다.** 한국거래소 2000-01~2019-06 표본에서 148개 이상현상 중
37.8%만 재현됐는데, 범주별로 갈린다 — 가치 69.2%, 모멘텀 66.7%(엄격한 기준에서는 26.7%),
거래 마찰 48.1%, **수익성 5.0%**.

1. 가치 축을 가장 두껍게 준다.
2. **수익성 절대 임계에 기대지 않는다.** `ROE`를 총이익성과 발생액으로 바꿨고, 결과로
   **`ROE`·`ROE_PCTL`을 쓰는 프리셋이 하나도 없다** — 지표는 남기고 조건에서만 뺐다.
3. 추세 프리셋을 국면 판별기로 설명한다.

## 버린 대안

- **쓰이지 않는 지표를 채워 넣기** — 사용자 요구가 「추가된 지표를 활용하라」였으므로
  자연스러운 해석이다. 그러나 근거 없는 조건은 통과 종목을 바꾸면서 왜 바뀌었는지 답하지
  못한다. `CCI_20`·`MFI_14`·`BOLLINGER_PCT_B`는 `RSI_2`·`CMF_21`과 재는 것이 겹쳐 뺐고,
  `GOLDEN_CROSS_AGE`는 **44/350에만 값이 있어** 조건에 걸면 나머지가 판정불가로 조용히
  빠진다. 무엇을 왜 안 썼는지는 계획서 §쓰지 않는 지표가 답한다.
- **`SWING_MIDTERM_KR`의 조건을 늘려 개선하기** — 그 프리셋의 조건셋 정본은 사람이 쓴 외부
  명세이고 에이전트가 고칠 수 없다(ADR-0041). 원본을 개정하려면 사용자 승인이 먼저다.
  사용자가 **폐기 후 대체**를 골랐다.
- **`RSI_14`를 완화해 눌림목을 만들기** — 임계를 45~50으로 올리면 결과는 나온다. 그러나
  Connors의 규칙은 「RSI(2) < 10」이고 그것은 **이틀 사이의 극단**을 말한다. 값이 그럴듯하게
  나오는 것과 원문을 옮긴 것은 다르다.
- **F-Score 아홉 항목을 전부 옮기기** — 전년 대비 변화가 다섯이라 지표가 다섯 더 필요하다.
  셋만 옮기고 나머지를 `description`에 결핍으로 적었다.

## 결과

- 프리셋을 고치려면 여전히 배포가 필요하다(ADR-0017).
- **조건 수 상한이 25다.** 상한에 붙으면 네 곳(`ScreenDefinitionValidator`·
  `wire-contract.json`·`frontend/src/api/limits.ts`·`PresetCatalogTest`)을 함께 올린다.
  **가장 큰 프리셋이 지금 몇 개를 쓰는지는 `PresetCatalogTest`가 숫자로 못박는다**
  (`SWING_TREND_KR` 24개가 여유를 1로 만들던 상태는 그 프리셋이 폐기되며 끝났다).
- **점수 조건의 배점이 전부 같으면 화면에서 점수 막대가 그려지지 않는다**
  (`frontend/src/lib/scoreLane.ts`). 그 형태의 **프리셋**은 `SWING_TREND_KR` 폐기로 없어졌고,
  지금 그 분기를 타는 것은 FILTER 전략과 사용자가 저장한 배점 미지정 전략이다.
- **ADR-0044 §승인된 예외의 대상이 사라졌고, 후계자도 사라졌다.** 「`SWING_MIDTERM_KR`에 한해
  결과 0건은 실패가 아니다」였고 범위가 그 프리셋 하나로 못박혀 있었다. 자리를 받았던
  `SWING_TREND_KR`이 2026-08-20에 폐기되면서(출처가 근거다 — 아래 개정) **승계 여부를 물을
  대상 자체가 없어졌다.** 예외는 승계되지 않은 채 끝난다.
- 2026-08-13 실측 통과 수: 추세 상승 16 · 2국면 돌파 3 · 눌림목 1 · 중장기 스윙 1.
  **스윙 1건의 원인은 국면이다** — 게이트별 단독 통과 수가 67~314로 어느 하나가 지배하지
  않고, 가장 좁은 것이 52주 고점 25% 이내(67종목)다. 지금 시장이 큰 조정 중이다.
