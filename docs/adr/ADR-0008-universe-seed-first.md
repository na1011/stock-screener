# ADR-0008. 지수 구성종목은 시드 CSV를 기본으로 두고 스크래핑을 보조로 얹는다

> **IMPORTANT — [ADR-0012](./ADR-0012-market-cap-universe.md)가 이 결정의 "기본 소스"를 개정했다.** 기본은 이제 시가총액 상위 N을 산출하는 `MarketCapUniverseAdapter`이고, 시드 CSV는 **영구 폴백**으로 내려왔다. 정확한 지수 구성종목 CSV를 구할 경로가 실질적으로 없다는 것이 나중에 확인됐기 때문이다.
>
> 아래의 나머지 — 스냅샷의 완전성, 조용한 폴백 금지, 시드 구현을 지우지 않을 것, 집합 차집합과 반열림 구간 — 는 **그대로 유효하며 ADR-0012가 명시적으로 승계한다.** 이 문서만 읽고 시드를 기본으로 되돌리지 마라.

## 결정

지수 구성종목의 기본 소스를 클래스패스의 시드 CSV로 둔다(→ ADR-0012가 시총 어댑터로 개정). 스크래핑 어댑터는 나중에 그 위에 얹되, 시드 구현을 **영구 폴백으로 유지**한다. 폴백이 일어나면 반드시 알린다.

## 규칙

- MUST: `UniverseSnapshot`은 **전체** 구성종목이다. 불완전하면 어댑터가 `DataSourceException`을 던진다. 부분 목록을 스냅샷으로 만들지 않는다.
- MUST: 제외 종목이 임계 비율을 넘으면 반영을 거부하고 알린다. 소스의 파싱 실패 한 번이 유니버스를 통째로 비우면 안 된다.
- MUST: 편입·제외를 **집합 차집합**으로 계산하고 교집합은 건드리지 않는다. 이것이 멱등성의 근거다.
- MUST: 제외는 `effective_to = 기준일`로 닫고 편입은 `effective_from = 기준일`로 연다. 반열림 구간이므로 겹치지 않는다.
- MUST: 스크래핑 실패로 시드에 의존하게 되면 알림을 보낸다.
- MUST NOT: 시드 구현을 "쓰이지 않는 코드"로 보고 지우지 않는다.
- MUST NOT: 스크래핑 실패 시 **조용히** 시드로 폴백하지 않는다.
- MUST NOT: 유니버스 반영에 종목 단위 실패 격리를 쓰지 않는다. 전체가 하나의 정합적 스냅샷이다.

## 배경

Phase 2 착수 시점 조사에서 **코스피200·코스닥150 구성종목을 주는 공식 무료 API가 확인되지 않았다.** KRX Data Marketplace OPEN API의 서비스 목록에 지수구성종목이 없고, 과거 구성종목은 KRX 정보데이터시스템의 유료 데이터 판매 항목이다. 유일한 자동 경로는 비공식 스크래핑인데, spec §7이 인용한 "국내 거래소 정보 시스템의 회원제 전환" 전례가 정확히 그 계열이다. S&P500은 위키피디아 스크래핑이 사실상의 표준이지만 역시 비공식이다.

시드를 기본으로 둔 근거가 셋이며 각각 단독으로도 충분하다. (1) 정기 리밸런싱은 연 2회뿐이라 자동화 실패의 대가가 낮다. (2) **유니버스가 없으면 다른 어떤 배치도 대상 종목을 정하지 못하므로** 이것이 파이프라인 전체의 병목이며, 가장 깨지기 쉬운 것에 병목을 걸 수 없다. (3) 시드가 있으면 API 키 없이 파이프라인 전체를 구성·검증할 수 있고, 실제로 Phase 2의 1~7단계가 그렇게 완주됐다.

IMPORTANT — 조용한 폴백을 금지하는 이유가 이 결정에서 가장 중요하다. 스크래핑이 깨졌는데 시드로 조용히 넘어가면 "6개월 전 유니버스로 스크리닝하고 있었다"는 상태가 되고, **그 상태는 아무 에러도 내지 않는다.** 편입된 종목이 빠져 있어도 결과 표는 정상으로 보인다.

제외 비율 안전장치에 최소 건수 하한(5건)을 둔 이유는 구성종목이 적을 때 비율만으로는 오탐이 나기 때문이다. 3종목 중 1종목 제외가 33%다. 실제 유니버스는 150~500종목이고 정기 리밸런싱의 교체 규모는 10종목 안팎이므로 하한이 실제 운영에서 검사를 무력화하지 않는다.

## 버린 대안

- **스크래핑만 사용** — 소스가 깨지면 유니버스를 갱신할 수 없고, 그것이 파이프라인 전체를 멈춘다.
- **시드만 사용하고 자동화 포기** — `data-pipeline.md`의 "수동 개입 없이 자동 반영" MUST를 정면으로 위반한다.
- **KRX 유료 데이터 구매** — spec §2의 "인프라 운영 비용 최소화"와 충돌한다. 연 2회 변경에 지불할 비용이 아니다.
- **ETF 구성종목(PDF/CU)으로 대용** — 공식 경로지만 지수와 100% 일치하지 않는다(현금·선물 편입). 스크리닝 대상이 지수와 미묘하게 달라지면 그 차이를 설명할 수 없다.
- **편입 여부를 `stock`의 불리언 컬럼으로** — V1이 이미 기각했다. 종목은 편입→제외→재편입되며, 관리자 기능이 이력을 조회한다.
- **유니버스 반영에 종목 단위 격리 적용** — 부분 적용된 유니버스는 "제외만 되고 편입이 안 된" 중간 상태를 스크리닝에 노출한다.

## 결과

- 쉬워지는 것: API 키·스크래핑 없이 파이프라인 전체를 구성·검증할 수 있다. 스크래핑이 깨져도 서비스가 멈추지 않는다.
- 어려워지는 것: 스크래핑 어댑터가 붙기 전까지 연 2회 사람이 CSV를 갱신해야 한다. `data-pipeline.md`의 자동 반영 요구는 그 어댑터가 붙는 시점에 완전히 충족된다.
- 되돌리려면: `datasource/universe`의 구현과 시드 CSV, `UniverseReconciler`를 함께 고쳐야 한다.
