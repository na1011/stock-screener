# ADR-0012. 유니버스를 시가총액 상위 N으로 정의하고 지수명을 차용하지 않는다

## 결정

스크리닝 대상을 **시가총액 상위 N종목**으로 정의하고, 공공데이터포털 시세 API의 전종목 조회로 매주 자동 산출한다. 유니버스 코드는 `KOSPI_TOP200`·`KOSDAQ_TOP150`으로 **새로 만들고**, 기존 `KOSPI200`·`KOSDAQ150`은 시드 CSV 담당으로 남긴다.

## 규칙

- MUST: 유니버스 코드에 **지수명을 차용하지 않는다**. `KOSPI200`이라는 이름에 시총 상위 200을 담지 않는다.
- MUST: 보통주만 편입한다(종목코드 끝자리 `0`). 우선주를 넣으면 같은 회사가 두 번 편입된다.
- MUST: 후보는 **정기 재무공시를 내는 보통주 발행사**이고, 빼는 것은 **보통주가 아닌 증권**(ETF·우선주·워런트·유닛 — 종목코드·이름·증권 종류 축)과 **사업이 없는 백지수표 회사**(스팩 — 국내 이름 「스팩」 · 미국 SIC `6770`)뿐이다(2026-10-31 개정).
  업종 때문에 어떤 지표가 성립하지 않으면 그 지표가 업종으로 판정불가를 낸다(은행·보험과 같다 — `AltmanZCalculator`). 원장이 재무를 안 주는 발행사는 편입되고 지표만 미표시다(`KnownSourceGaps` — 인프라 투융자회사).
  - **리츠는 관문에서 든다** — 지금은 옛 규칙(「사업회사가 아니라 재무 지표가 성립하지 않는다」 · 실측 없음)대로 빠진다. 켜기 전 선행 둘이 실측으로 섰다: 미국 리츠 매출이 리스 매출(ASC 842) 태그 없이 계약매출 조각만 잡힌다(UDR FY 11M 대 순이익 378M · 매출 < max(영업현금흐름, 순이익) 23/212 · `docs/reload-gate.md` 「리츠」 행) · 국내 리츠는 재무 엔드포인트와 회계기간을 원장에 아직 안 물었다.
  - 사용자 문장(2026-10-31): 「종목에 대한 판단은 사용자에게 묻지말고, 정합성과 단순함을 중요시 한 대원칙을 세운 후 너 스스로 판단해.」 위 원칙과 리츠 판정은 내 해석이다.
- MUST: 상위 N을 채우지 못하면 `DataSourceException`을 던진다. 부분 목록은 대량 오탈락이 된다(ADR-0008과 동일한 규칙).
- MUST: 휴장일이면 직전 거래일로 거슬러 올라간다. 빈 응답을 "구성종목 없음"으로 반영하면 유니버스가 통째로 빈다.
- MUST NOT: **키가 없는 환경에서 시드 유니버스(`KOSPI200` 등)를 비활성으로 내리지 않는다.** 시총 어댑터가 `@ConditionalOnApiKey`라 등록되지 않으므로 활성 유니버스가 하나도 남지 않는다. 실질적으로 테스트 DB가 그 환경이고, 거기서는 시드가 활성·시총 유니버스가 비활성이다. **키가 있는 운영 DB는 정반대이며 그것이 정상이다** — 시총 어댑터가 활성 유니버스를 공급하므로 시드는 폴백으로 물러난다.
- MUST NOT: 시드 구현을 지우지 않는다(ADR-0008을 그대로 승계한다).

## 검증

```bash
./gradlew test --tests "*MarketCapUniverseAdapterTest*"
```
보통주 선별, 스팩·리츠 제외(리츠는 관문 전까지), 부분 목록 거부, 휴장일 소급을 확인한다.

```bash
./gradlew test --tests "*PipelineEndToEndTest*"
```
**키 없이도** 시드 유니버스로 파이프라인 전체가 도는지 확인한다. 이 테스트가 깨지면 시드 폴백이 무너진 것이다.

```bash
psql -d stock_screener -tAc "select code, is_active from universe order by code"
```
`KOSPI200`·`KOSDAQ150`·`SP500` 행이 남아 있어야 한다(폴백의 조건이다). **어느 쪽이 활성인가는 그 환경에 키가 있는가가 정한다** — 운영은 시총 둘이 활성, 테스트 DB는 시드가 활성이다. 판정 기준은 어느 이름이 켜져 있는가가 아니라 **활성 유니버스가 하나라도 있는가**이며, 0이면 스크리닝 대상이 통째로 비고 그 상태는 화면에 "조건에 맞는 종목 없음"으로만 보인다.

## 배경

ADR-0008이 "지수 구성종목을 주는 공식 무료 API가 없다"고 기록하며 시드 CSV를 기본으로 뒀다. 그런데 **정확한 CSV를 구할 경로가 실질적으로 없다**는 것이 확인됐다 — KRX 정보데이터시스템의 지수구성종목은 화면 조회이고 과거 구성종목은 유료 판매 항목이다. 시드가 15종목 표본에 머무르면 적재 자체가 불가능하다.

실측이 다른 길을 열었다(2026-08-06, 실제 키). 시세 API에 `basDt`만 주고 종목코드를 빼면 **그날 상장 전 종목이 온다** — 2,872건, 785KB, 0.73초. 응답에 `mrktTotAmt`(시가총액)·`itmsNm`(종목명)·`mrktCtg`(시장)가 전부 들어 있고, `mrktCls`로 시장 필터도 된다. 과거 시점도 재현된다(2020-01-02 기준 2,475종목).

**"시가총액 상위 200"은 그 자체로 정확한 정의**이며 API로 완전히 재현된다. spec §3의 "지수 편입 우량 종목" 취지도 충족한다 — 실측상 상위 10종목이 삼성전자·SK하이닉스·SK스퀘어·삼성전기·현대차·LG에너지솔루션·삼성바이오로직스·KB금융·삼성생명·삼성물산으로 실제 지수와 충분히 근사하다.

IMPORTANT — 지수명을 차용하지 않는 것이 이 결정에서 가장 중요하다. 시총 상위 200은 실제 코스피200과 80~90%만 겹친다(지수는 유동비율과 업종 안배를 반영한다). `KOSPI200`이라는 이름에 다른 내용을 담으면 화면에 "코스피200"이라 적히는데 실제로는 아닌 상태가 되고, **그 차이는 아무 에러도 내지 않으면서** 사용자에게 잘못 전달된다. 나중에 정확한 구성종목을 확보하면 그때 `KOSPI200`을 켜면 되고, 두 유니버스가 공존해도 충돌하지 않는다.

교체율도 확인했다. 시총 상위 200의 2개월간 교체는 7종목(3.5%)으로 `UniverseReconciler`의 30% 임계 안이다. 다만 200위와 201위의 시총 차이가 0.2%에 불과해 경계에서 순위가 진동한다 — 히스테리시스(유지 밴드 N×1.1)를 두면 교체가 2종목으로 준다. **그 밴드는 결국 반환값에 안 들어갔다** — `MarketCapUniverseAdapter.select()`는 순수 상위 N을 내고 `RETENTION_BAND`는 `log.debug` 한 줄에만 쓰인다. **이 가정법 문장이 연쇄의 출처였다**: 문서 일곱 곳이 그것을 「있다」로 읽어 「과거 유니버스는 경로 의존이라 복원 안 된다」의 근거로 인용했고, 그 위에서 복원이 막혀 있었다(ADR-0135가 걷었다).

## 버린 대안

- **정확한 CSV를 사람이 계속 갱신** — 연 2회 정기변경에 수시변경까지 사람이 따라가야 하고, 실제로 그 CSV를 얻을 안정적 경로가 없다. `data-pipeline.md`의 "수동 개입 없이 자동 반영" MUST와도 충돌한다.
- **`KOSPI200` 코드에 시총 상위를 담기** — 마이그레이션이 없어 가장 싸지만, 이름과 내용이 어긋난 상태가 영구히 남는다. 나중에 진짜 구성종목을 넣으려 할 때 기존 이력이 무엇이었는지 구별할 수 없다.
- **전 종목(2,872) 대상** — 유니버스 개념이 사라져 가장 단순하지만, 재무 수집이 34,000콜로 며칠 걸리고 스팩·관리종목까지 스크리닝에 올라온다. spec §3의 "우량 종목" 전제와 맞지 않는다.
- **시드 유니버스를 비활성으로 내리기** — 처음에 그렇게 했다가 되돌렸다. 시총 어댑터가 `@ConditionalOnApiKey`라 키 없는 환경에서 등록되지 않아, 시드까지 내리면 **활성 유니버스가 하나도 남지 않는다.** ADR-0008의 근거 (3)("키 없이도 파이프라인 전체를 검증할 수 있다")이 무너지며 실제로 테스트 7건이 깨졌다.
- **거래대금·유동주식수로 가중** — 실제 지수에 더 가까워지지만 계산 근거를 우리가 만들게 되고, 그 값이 맞는지 검증할 방법이 없다. 시가총액은 소스가 주는 실측값이다.

## 결과

- 쉬워지는 것: CSV 없이 유니버스가 자동으로 유지된다. 리밸런싱이 매주 돌며 사람 개입이 사라진다. 유니버스 응답에 종목명이 들어 있어 종목 등록의 마스터 API 350콜도 함께 없어졌다.
- 어려워지는 것: 실제 지수와 완전히 같지 않다. 그 차이를 사용자에게 설명해야 하고, 유니버스 이름을 "시총 상위"로 노출하는 것이 그 설명의 첫 번째 수단이다.
- 되돌리려면: `MarketCapUniverseAdapter`를 지우고 `universe`에서 두 행을 내리면 된다. 시드 구현이 그대로 살아 있으므로 폴백은 항상 가능하다 — 그것이 이 결정을 안전하게 만드는 조건이다.
