# ADR-0039. 중장기 스윙 명세를 국내로 옮기며 무엇을 치환하고 무엇을 버렸는가

## 결정

외부 명세([`docs/external/screener-spec-midterm-swing.md`](../external/screener-spec-midterm-swing.md)
v1.0, 미국시장 기준 26개 조건)를 `SWING_MIDTERM_KR`
프리셋으로 옮기되, **원자료가 없는 조건은 근사하지 않고 버린다.** 치환한 것은 근거와 함께
아래 표에 남기고, 버린 것은 **프리셋 설명에 명시해 화면에서도 보이게 한다.**

## 규칙

- MUST: 옮기지 못한 조건을 `ScreenPreset.description`에 적는다. 이 프리셋의 가장 큰 위험은
  틀린 값이 아니라 **없는 안전장치를 있다고 믿는 것**이며, 결핍은 어떤 에러도 내지 않고
  화면에도 흔적이 없다.
- MUST NOT: 뜻이 다른 값을 같은 이름으로 부르지 않는다. 금융비용을 이자비용으로, 유니버스
  백분위를 업종 순위로 쓰지 않는다. 값이 그럴듯해 화면으로는 드러나지 않는다.
- MUST: 규모(시가총액)를 **절대값**으로 건다. 백분위는 유니버스 안에서 매겨지므로(ADR-0036)
  "시총 상위 30%"가 코스닥150 안의 상위 30%를 포함해 **규모로 거르려는 의도와 정반대**가 된다.
- MUST NOT: 원본의 임계값을 국내에 그대로 쓰기 전에 분포를 재지 않고 넘어가지 않는다.
  아래 §임계값에 실측이 있다.
- MUST: 이 표를 원본 명세가 개정될 때 **먼저** 본다. 원본 §11의 매핑 검증표에 대응한다.

## 검증

프리셋 설명이 결핍을 실제로 말하는지 — 여섯 낱말이 모두 있어야 한다:

```bash
psql -d stock_screener -At -c "SELECT description FROM screen WHERE code='SWING_MIDTERM_KR'" \
  | grep -o '업종\|EBITDA\|이자보상\|베타\|피인수\|해자' | sort -u | wc -l
```

`6`이어야 한다. 줄면 결핍 고지가 빠진 것이다.

**낱말은 그대로인데 `업종`이 가리키는 결핍이 바뀌었다.** 예전에는 "업종 상대 비교를 못 옮겼다"였고
지금은 "업종 표본이 5종목에 못 미치면 판정할 수 없다"다(ADR-0044). 나머지 다섯은 그대로다.

```premise 스윙 프리셋이 규모를 절대값으로 건다
psql -d stock_screener -At -c "WITH c AS (SELECT c.indicator_code i, c.operator o FROM screen s JOIN condition_group g ON g.screen_id=s.id JOIN screen_condition c ON c.group_id=g.id WHERE s.code='SWING_MIDTERM_KR') SELECT CASE WHEN (SELECT count(*) FROM c) = 0 THEN 'SWING_MIDTERM_KR에 조건이 없다 — 프리셋이 투영되지 않았다' WHEN (SELECT count(*) FROM c WHERE i = 'MARKET_CAP_PCTL') > 0 THEN '시가총액을 백분위로 걸고 있다 — 유니버스 안에서 매겨져 코스닥 소형주가 통과한다' WHEN (SELECT count(*) FROM c WHERE i = 'MARKET_CAP') = 0 THEN '규모 조건이 사라졌다 — 원본 U-03이 통째로 빠진 상태다' ELSE 'OK 규모를 절대값으로 건다(조건 ' || (SELECT count(*) FROM c) || '개)' END"
```

**`count(*) = 0`을 따로 답하는 것이 요점이다.** 프리셋이 아직 투영되지 않은 상태와
"백분위를 쓰지 않는다"가 둘 다 조용히 참이 되기 때문이다.

**U-05의 이식이 근사인 것은 아래 포함 관계가 참인 동안만이다.** `TRADING_DAYS_750`은 러너의
읽기 창에 값이 묶여 있다. 그 창을 정하던 것은 `SharesGrowth3yCalculator.LOOKBACK`(751)이었고, **지금은 `ICHI_*`의 1,100이다**(P12).
둘 중 하나가 바뀌면 **U-05가 기존 게이트보다 강하게 자르기 시작하는데, 결과 종목 수는 그대로일
수 있어 화면에서 드러나지 않는다.**

```premise U-05가 SHARES_GROWTH_3Y보다 강하게 자르지 않는다
psql -d stock_screener -At -c "WITH d AS (SELECT max(trade_date) td FROM indicator_value), x AS (SELECT stock_id, max(value) FILTER (WHERE indicator_code='SHARES_GROWTH_3Y') sg, max(value) FILTER (WHERE indicator_code='TRADING_DAYS_750') days FROM indicator_value, d WHERE trade_date = d.td AND indicator_code IN ('SHARES_GROWTH_3Y','TRADING_DAYS_750') GROUP BY 1) SELECT CASE WHEN count(*) FILTER (WHERE days IS NOT NULL) = 0 THEN 'TRADING_DAYS_750이 최신 지표 일자에 하나도 없다 — 지표가 배포되지 않았거나 그날 백필이 돌지 않았다' WHEN count(*) FILTER (WHERE sg IS NOT NULL) = 0 THEN 'SHARES_GROWTH_3Y가 최신 지표 일자에 하나도 없다 — 포함 관계를 잴 대상이 없다' WHEN count(*) FILTER (WHERE sg IS NOT NULL AND (days IS NULL OR days < 750)) = 0 THEN 'OK SHARES_GROWTH_3Y 보유(' || count(*) FILTER (WHERE sg IS NOT NULL) || '종목)가 U-05 통과(' || count(*) FILTER (WHERE days >= 750) || '종목)의 부분집합이다' ELSE 'U-05가 SHARES_GROWTH_3Y보다 강하게 자른다: ' || count(*) FILTER (WHERE sg IS NOT NULL AND (days IS NULL OR days < 750)) || '종목 — 읽기 창이나 LOOKBACK이 바뀌었는지 본다' END FROM x"
```

**모집단이 비는 경우를 둘로 가르는 이유**는 "지표가 배포되지 않았다"와 "그날 백필이 안 돌았다"가
둘 다 흔하기 때문이다. 이 둘 중 **실행당 1일치만 채워지는 것은 이제 `TRADING_DAYS_750` 하나다**(위 §깔때기 · 창이 1,100이 되며 `SHARES_GROWTH_3Y`는 350일자를 낸다). 백필을 건너뛴
날짜에는 정상적으로 비어 있다.

**수정주가·업종 쪽 펜스는 여기 없다** — 둘 다 착수해 정본이 옮겨 갔다. 수정계수는 원장이
정본이고 판정은 ADR-0049·0051·0052의 premise가, 업종은 `stock.industry_code`와 ADR-0044의
premise가 한다. 여기에 사본을 두면 두 곳이 갈린다.

### 깔때기 — 어느 조건이 몇 종목을 떨어뜨렸는지 재는 법

SCORING은 탈락 종목의 판정을 응답에 남기지 않으므로(ADR-0038 §결과) 화면으로는 알 수 없다.
**`phase-criteria.md` Phase 7이 요구하는 "재는 방법"이 이것이다** — 숫자만 옮겨 두면 다음
세션이 재현하지 못해 0건의 원인을 조건·데이터·국면으로 가를 근거가 사라진다.

```bash
psql -d stock_screener -F'|' -c "
WITH d AS (SELECT max(trade_date) td FROM indicator_value),
p AS (SELECT stock_id,
    max(value) FILTER (WHERE indicator_code='MARKET_CAP')        mc,
    max(value) FILTER (WHERE indicator_code='TURNOVER_60')       tv,
    max(value) FILTER (WHERE indicator_code='TRADING_DAYS_750')  td,
    max(value) FILTER (WHERE indicator_code='ADJ_CLOSE')         ac,
    max(value) FILTER (WHERE indicator_code='SMA_200')           s200,
    max(value) FILTER (WHERE indicator_code='SMA_60')            s60,
    max(value) FILTER (WHERE indicator_code='SMA_200_MOM_21')    mom,
    max(value) FILTER (WHERE indicator_code='SMA_200_SLOPE_60')  slp,
    max(value) FILTER (WHERE indicator_code='PCT_FROM_52W_LOW')  plo,
    max(value) FILTER (WHERE indicator_code='PCT_FROM_52W_HIGH') phi,
    max(value) FILTER (WHERE indicator_code='ATR_PCT_14')        atr,
    max(value) FILTER (WHERE indicator_code='PROFITABLE_QUARTERS_4') pq,
    max(value) FILTER (WHERE indicator_code='DEBT_RATIO')        dr,
    max(value) FILTER (WHERE indicator_code='DEBT_RATIO_SECTOR_REL') drs,
    max(value) FILTER (WHERE indicator_code='SHARES_GROWTH_3Y')  sg,
    max(value) FILTER (WHERE indicator_code='ALTMAN_Z')          az
  FROM indicator_value, d WHERE trade_date = d.td GROUP BY stock_id)
SELECT count(*) AS s0_base,
 count(*) FILTER (WHERE mc>=1e12) AS s1_mcap,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10) AS s2_turnover,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750) AS s3_history,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750
                    AND ac>s200 AND s60>s200 AND mom>0 AND slp>0) AS s4_trend,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750 AND ac>s200 AND s60>s200 AND mom>0 AND slp>0
                    AND ac<=s200*1.25) AS s5_disparity,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750 AND ac>s200 AND s60>s200 AND mom>0 AND slp>0
                    AND ac<=s200*1.25 AND plo>=30 AND phi>=-25) AS s6_52w,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750 AND ac>s200 AND s60>s200 AND mom>0 AND slp>0
                    AND ac<=s200*1.25 AND plo>=30 AND phi>=-25 AND atr<=6) AS s7_atr,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750 AND ac>s200 AND s60>s200 AND mom>0 AND slp>0
                    AND ac<=s200*1.25 AND plo>=30 AND phi>=-25 AND atr<=6
                    AND pq>=3 AND dr<=150 AND sg<=5) AS s8_survival,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750 AND ac>s200 AND s60>s200 AND mom>0 AND slp>0
                    AND ac<=s200*1.25 AND plo>=30 AND phi>=-25 AND atr<=6
                    AND pq>=3 AND dr<=150 AND sg<=5 AND drs<=1.5) AS s8b_sector_debt,
 count(*) FILTER (WHERE mc>=1e12 AND tv>=1e10 AND td>=750 AND ac>s200 AND s60>s200 AND mom>0 AND slp>0
                    AND ac<=s200*1.25 AND plo>=30 AND phi>=-25 AND atr<=6
                    AND pq>=3 AND dr<=150 AND sg<=5 AND drs<=1.5 AND az>=2.6) AS s9_altman
FROM p"
```

**`s3_history`가 크게 깎는 것은 정상이다.** 2026-08-07 실측에서 221 → 206으로 15종목이 여기서
빠지는데, 그들은 **이 단계가 없을 때 뒤에서 걸리던 종목**이다(최종 수가 같다). 이 단계가
자기 몫보다 많이 자르는 것처럼 보이면 그것은 U-05가 아니라 **수집 결손**이다 — 아래 §단계 값이
0이면… 절과 `TradingDays750Calculator`의 javadoc을 함께 본다.

**MUST: 임계값을 고치면 이 SQL도 함께 고친다.** 정본은 `PresetCatalog.swingMidtermKr()`이고
이것은 사본이다 — 어긋나면 깔때기가 프리셋과 다른 것을 재면서 그럴듯한 숫자를 낸다.

**단계 값이 0이면 조건이 아니라 지표 부재를 먼저 의심한다.** 값이 없는 종목은 SQL에서도
비교가 NULL이 되어 조용히 빠지므로, 조건이 자른 것과 구분되지 않는다. 필수 지표별 종목 수를
먼저 센다:

```bash
psql -d stock_screener -At -F'|' -c "SELECT indicator_code, count(DISTINCT stock_id) FROM indicator_value WHERE trade_date=(SELECT max(trade_date) FROM indicator_value) AND indicator_code IN ('MARKET_CAP','TURNOVER_60','TRADING_DAYS_750','ADJ_CLOSE','SMA_200','SMA_60','SMA_200_MOM_21','SMA_200_SLOPE_60','PCT_FROM_52W_LOW','PCT_FROM_52W_HIGH','ATR_PCT_14','PROFITABLE_QUARTERS_4','DEBT_RATIO','SHARES_GROWTH_3Y','ALTMAN_Z') GROUP BY 1 ORDER BY 2"
```

**15개가 다 나와야 한다.** 하나라도 빠지면 그 지표가 원자료 결손으로 계산되지 않은 것이고,
필수 조건이면 그것만으로 결과가 0건이 된다 — 2026-08-10에 `ALTMAN_Z`가 실제로 그랬다(ADR-0040).

**`TRADING_DAYS_750`은 실행당 1일치만 채워진다**(`SHARES_GROWTH_3Y`는 창이 1,100이 되며 350일자를 낸다) — 유효 워밍업이 읽기 창과
같아 창의 마지막 봉에서만 값이 나온다. 그래서 **날짜별 백필을 돌리지 않은 날짜는 이 둘이 없고,
필수 조건이라 그날 결과가 통째로 0건이 된다.** 0건을 국면 탓으로 읽기 전에 그 둘을 먼저 센다.

## 배경

원본은 미국 상장주 4,000종목을 1,000~1,500 → 300~500 → 50~120 → 15~25로 좁히는 4단 깔때기다.
우리 유니버스는 이미 시총 상위 350(전체 2,872의 12%)이라 **원본의 Layer 0보다 2~3배 엄격한
지점에서 시작한다.** 그래서 U-03(시총 ≥ $5B)을 그대로 환산(≈6.9조)하면 350종목 중 70종목대만
남고 코스닥은 거의 전멸한다 — 원본의 의도(애널리스트 커버리지·유동성)와 다른 것을 자르게 된다.

더 근본적인 제약은 원자료다. `stock.sector`가 **356종목 전부 비어 있어** 업종 상대 비교가
원리적으로 불가능하고, 감가상각비·이자비용은 DART가 비금융 기업에 표준계정코드로 주지 않는다
(2026-08-10 실측, `docs/api-spec/dart-open-api.md` §7).

## 조건 대조표

원본 ID → 우리 구현. **원본이 개정되면 이 표를 먼저 본다.**

### Layer 0 — 유니버스 (6)

| 원본 | 우리 | 판정 |
|---|---|---|
| U-01 거래소 NYSE/NASDAQ | 유니버스가 KOSPI·KOSDAQ | 구조가 이미 충족 |
| U-02 보통주만(SPAC·우선주·ETF 제외) | ADR-0012가 종목코드 끝자리 0, 스팩·리츠·ETF 제외 | 구조가 이미 충족 |
| U-03 시총 ≥ $5B | `MARKET_CAP >= 1조원` | **치환** — 아래 §임계값 |
| U-04 60일 평균 거래대금 ≥ $30M | `TURNOVER_60 >= 100억원` | **치환** — 아래 §임계값 |
| U-05 상장 ≥ 3년(750거래일) | `TRADING_DAYS_750 >= 750` | **근사.** 세는 것이 상장 경과가 아니라 **저장된 봉의 수**다 — 신규 편입 종목의 수집 결손과 거래정지 구간이 똑같이 이 값을 줄이며, 이 값만으로 셋을 가를 수 없다. 값은 750에서 포화한다(`min(size, 750)`이라 창이 넓어져도 불변이다) |
| U-06 피인수 진행 제외 | — | **버림.** 코퍼레이트 액션 소스가 없다 |

### Layer 1 — 생존 게이트 (7)

| 원본 | 우리 | 판정 |
|---|---|---|
| H-01 최근 4분기 중 영업이익 흑자 ≥ 3 | `PROFITABLE_QUARTERS_4 >= 3` | 그대로 |
| H-02 D/E ÷ 업종 중앙값 ≤ 1.5 | `DEBT_RATIO_SECTOR_REL <= 1.5` + `DEBT_RATIO <= 150` | **모집단은 원본으로 돌아왔다. 뜻은 아직 다르다** — 원본 D/E가 차입금 기준인데 우리 부채비율은 부채총계/자기자본이다. 업종 표본 5 미만은 판정불가(ADR-0044). 절대 기준을 함께 남긴 것은 아래 H-03 자리를 부분적으로 메우기 위해서다 |
| H-03 순부채 ÷ EBITDA ≤ 3.0 | — | **버림.** 감가상각비가 비금융 기업에 표준계정코드로 오지 않아 EBITDA를 만들 수 없다. **원본 §의도가 "H-02는 상대 기준이라 업종 전체가 과부채인 경우를 잡지 못한다"며 이것을 절대 기준으로 병행하라고 적었으므로, 그 자리를 `DEBT_RATIO <= 150`이 부분 대체한다** — 상환능력이 아니라 레버리지라 같은 것은 아니다 |
| H-04 EBIT ÷ 이자비용 ≥ 3.0 | — | **버림.** 이자비용이 금융업에만 온다. `금융비용`은 외환손실·파생상품손실을 포함해 다른 값이다 |
| H-05 5년 누적 영업현금흐름 > 0 | — | **보류.** 전체 재무제표 API로 옮기면 얻을 수 있다(그 하나뿐이다) |
| H-06 3년 발행주식수 증가율 ≤ 5% | `SHARES_GROWTH_3Y <= 5` | 그대로. 단 액면분할을 희석과 구분하지 못한다(분할 이력이 없다) |
| H-07 Altman Z ≥ 2.6 | `ALTMAN_Z >= 2.6` | 그대로. 보험·금융서비스(KSIC 65·66)는 명시 제외한다(ADR-0044). **중분류 64는 지주회사를 함께 담아 코드로 가를 수 없어 남겼고, 그쪽은 여전히 부작용에 기댄다** — 아래 §부작용 |

### Layer 2 — 추세 국면 (8) — 가장 잘 맞은 층이다

| 원본 | 우리 | 판정 |
|---|---|---|
| T-01 종가 > SMA200 | `ADJ_CLOSE > SMA_200` | 그대로(지표 참조) |

## 임계값 — 국내 분포를 재고 정했다

원본 §12가 모든 임계값을 "캘리브레이션 초안"이라 밝혔으므로 그대로 가져오지 않았다.
아래는 2026-08-06 기준 활성 유니버스 350종목 실측이다.

| 조건 | 원본 | 우리 | 근거 |
|---|---|---|---|
| 시가총액 | $5B (≈6.9조) | **1조원** | KOSPI_TOP200 중앙값 4.62조·최소 1.29조, KOSDAQ_TOP150 중앙값 1.02조. 6.9조를 쓰면 350 → 70종목대이고 코스닥이 거의 전멸한다. 1조는 코스피 전부와 코스닥 절반을 남긴다 |
| 60일 평균 거래대금 | $30M (≈415억) | **100억원** | 실측 분위 p10=46억 p25=92억 p50=239억. 415억은 상위 35%만 남긴다 — 이미 시총 상위인 유니버스에 이중 필터가 된다 |
| ATR 비율 | 4% | **6%** | **국내가 구조적으로 더 흔들린다.** 유니버스 ATR 비율 중앙값이 7.91%, p10=4.64, p25=5.88이다. 4%를 그대로 쓰면 상위 10%만 남아 게이트가 아니라 저변동성 스크리너가 된다 — 실측으로 추세 게이트 통과 16종목이 **1종목**이 됐다. 6%는 p25 언저리이며 원본이 미국 표본에서 4%를 놓은 상대 위치에 대응한다 |

**게이트 깔때기(2026-08-06 실측, SQL 사전 측정):**
350 → 시총 277 → 거래대금 224 → 200일선 위 88 → 정배열 78 → 1개월 상승 75 → 이격도 53 →
52주 저점 +30% 52 → **52주 고점 −25% 이내 16.**

**저장된 지표값으로 다시 잰 것(2026-08-06, 백필 뒤):** 348 → 275 → 222 → 추세 4종 78 →
기울기 둘 75 → 이격도 53 → 52주 고저 16 → **ATR 6% 이하 + 재무 셋 3종목.**
ATR을 4%로 두면 1종목, 무제한이면 6종목이 상한이다.

**원본이 캘리브레이션 1순위로 든 T-04(이격도)는 국내에서 지배적이지 않다.** 실제로 크게 자르는
것은 둘이다 — T-06(52주 고점, 52 → 16)과 T-07(ATR, 16 → 1). 앞은 국내 표본의 고점 대비
중앙값이 −34.6%라서고, 뒤는 일간 변동성 자체가 미국 대형주보다 크기 때문이다. **둘 다 시장
구조의 차이이지 조건이 잘못된 것이 아니다.** T-07은 위 표대로 재보정했고, **T-06은 손대지
않았다** — 한 번에 두 손잡이를 풀면 무엇이 결과를 바꿨는지 귀속시킬 수 없다.

### 꼬리에서 실제로 자르는 것은 다르다 (2026-08-10 재측정)

**게이트 중간에서 크게 자르는 것과 꼬리에서 결과 수를 정하는 것이 같지 않다.** 아래는
필수 13개로 다시 잰 것이고(2026-08-06 종가 기준), 위 §깔때기의 SQL이 그대로 재현한다.

- **T-06을 −25 → −35로 풀면 3 → 4, 통째로 없애도(−100) 4에서 멈춘다.** 게이트 중간 구간에서는
  가장 크게 자르지만(53 → 16) **꼬리에서는 상한이 4다.** "1순위 손잡이"로 다루면 크게 풀고도
  결과가 거의 그대로인 채 게이트만 헐거워진다.
- **꼬리에서 실제로 자르는 것은 `DEBT_RATIO ≤ 150`이다(11 → 3).** `PROFITABLE_QUARTERS_4`와
  `SHARES_GROWTH_3Y`는 11개를 전부 통과시킨다.
- **MUST NOT: 그 사실을 `DEBT_RATIO`를 풀 근거로 읽지 않는다.** 이유가 둘이다.
  - **잘린 8개 중 6개가 금융지주·보험이다**(신한·KB·하나·우리·iM·삼성화재). `ALTMAN_Z`가
    복구되면 그 종목들은 유동자산 부재로 **어차피 판정불가가 되어 빠진다**(§부작용).
    순수하게 `DEBT_RATIO`만으로 잘리는 것은 BGF리테일·대한항공 둘이다.
  - **150은 손잡이가 아니다.** 통과한 것 중 최고가 57.59, 잘린 것 중 최저가 176.36이라
    **임계를 58~176 어디로 옮겨도 결과가 같다.** 100·150·180·200을 다 쓸어 봤고 3 또는 4였다.

**즉 이 프리셋의 결과 수는 임계값이 아니라 유니버스 규모와 시장 국면이 정한다.** 다음
캘리브레이션을 할 때는 손잡이를 고르기 전에 위 깔때기를 다시 재고 **어느 단계가 실제로
지배적인지부터 확인한다** — 그 순위는 국면에 따라 바뀐다.

**하루 만에 실증됐다(2026-08-07 종가 적재 후).** 결과가 **2종목 → 1종목**이 됐다.
씨젠이 빠졌는데 **14개 조건 중 딱 하나, `TURNOVER_60`이 103.6억 → 99.16억으로 임계(100억)에
0.8% 미달**한 것이 전부다. 나머지 13개는 전부 통과했고 Altman Z는 오히려 6.22 → 6.24로 올랐다.

**MUST NOT: 이것을 임계값이 과하다는 근거로 읽지 않는다.** 경계에 붙어 있던 종목이 경계를
넘나든 것이며, **결과 수가 하루 단위로 흔들린다는 사실 자체가 위 문단의 실증**이다.
0건이 나와도 마찬가지다 — `phase-criteria.md` Phase 7이 요구하는 대로 **① 조건 ② 데이터
③ 국면**으로 먼저 가른다. 이 사례는 ③이고, 가르는 데 든 것은 지표 14개를 두 날짜로 나란히
뽑는 쿼리 하나였다.

## 총량 판정 — 이 프리셋은 원본의 얼마인가

**개별 결손은 각각 정당했지만 누적은 다른 물건이 됐다.** 조건 하나가 막힐 때마다 빼는 판단을
반복하면, 각 단계는 합리적인데 결과는 원본과 성격이 다른 프리셋이 된다. 그 누적을 여기 적는다.

| 층 | 원본 | 그대로 | 치환 | 버림 | 구조가 흡수 |
|---|---|---|---|---|---|
| Layer 0 유니버스 | 6 | 1 | 2 | 1 | 2 |
| Layer 1 생존 | 7 | 3 | 1 | 3 | — |
| Layer 2 추세 | 8 | 5 | 2 | 1 | — |
| Layer 3 Soft | 5 | 1 | 2 | 1 | 1 |
| 모듈 B 플래그 | 40 | — | — | 40 | — |

**IMPORTANT — 가장 많이 깎인 것이 원본이 설계의 축으로 삼은 축이다.** 원본 §1-1 ③은
"상방보다 생존을 먼저 본다. 후보가 부족해지는 것보다 부실 종목이 통과하는 것이 훨씬 비싼
실수다"를 네 제약 중 하나로 두고 Layer 1에 7개를 배치했다. 우리에게 실제로 작동하는 것은
**H-01(흑자 분기)·H-02(업종 상대 + 절대 병행)·H-06(희석)·H-07(Altman Z) 넷**이다.
반대로 가장 온전히 옮겨진 것은 Layer 2 추세(8개 중 7개)다.

**업종 축이 붙어도 위 표의 숫자는 그대로다.** 모집단이 원본으로 돌아왔을 뿐 재는 대상이
같아지지는 않았기 때문이다 — H-02의 D/E 정의가 다르고, S-01은 원본의 OR 중 한쪽뿐이며,
S-02는 EBIT/EV가 아니라 영업이익률이다. **"치환"을 "그대로"로 옮기면 이 표가 거짓이 된다.**

즉 **이 프리셋은 원본보다 "추세는 그대로, 생존은 얇은" 쪽으로 기울어 있다.** 그것이 의도가
아니라 데이터 제약의 결과라는 사실이 이 문서의 존재 이유다.

- MUST NOT: 조건이 막힐 때마다 빼는 것으로 해결하지 않는다. 뺄 때마다 원본에서 멀어지고,
  **개별 결정이 전부 정당해도 누적은 정당해지지 않는다.** 막히면 먼저 원자료를 여는 길을 보고,
  그것이 불가능할 때만 빼되 이 표를 함께 갱신한다.
- MUST: 이 표의 "버림"이 하나 늘 때마다 **위 총량 판정 문단을 다시 읽는다.** 어느 축이 얼마나
  남았는지가 프리셋을 계속 "중장기 스윙"이라 부를 수 있는지를 정한다.

## 부작용 — Altman Z가 금융 종목을 가르는 방식

**절반은 명시 제외가 됐고 절반은 여전히 부작용이다.**

- **보험(65)·금융서비스(66)는 이제 계산기가 명시적으로 제외한다**(ADR-0044). 근거가 코드
  범위라 값이 나오든 안 나오든 성립한다.
- **중분류 64(금융업)는 제외하지 않았다.** 이름과 달리 그 자리가 **지주회사 버킷을 겸해**
  코드로 가를 수 없기 때문이다 — `64992`에 신한지주·KB금융과 LG·SK·GS가 함께 있고 3자리
  `649`에도 미래에셋벤처투자와 효성·HDC가 섞인다. 그 종목들이 결과에서 빠지는 것은 여전히
  유동/비유동 미구분 재무상태표 때문이며 **그쪽은 의도한 방어가 아니다.**

**이 비대칭을 정한 것은 실측이다** — 350종목 기준 64·65·66의 51종목 중 `ALTMAN_Z` 값이 나온
22종목이 **21개까지 비금융 사업지주**였고, 진짜 금융사 29종목은 이미 값이 없었다. 64를 통째로
자르면 얻는 것은 미래 방어뿐이고 잃는 것은 적용 가능한 21종목이다(2026-08-11 사용자 승인).

**MUST NOT: 64가 값을 내는 것을 보고 제외 범위를 넓히지 않는다.** 그 값의 대부분은 제조·유통
지주회사의 것이고, Altman Z가 원래 겨냥한 대상이다. 넓히려면 금융지주와 사업지주를 가를
근거를 먼저 찾아야 하며 `induty_code`에는 그것이 없다.

## 버린 대안

- **없는 조건을 근사로 메운다** — 금융비용을 이자비용으로, 유니버스 백분위를 업종 순위로,
  ROE 5년 평균을 해자 프록시로. 전부 값이 그럴듯해 화면으로는 드러나지 않고, 사용자는 검증된
  게이트를 통과했다고 믿는다. 원본 §1-1 ③이 "부실 종목이 통과하는 것이 훨씬 비싼 실수"라고
  적은 것이 이 유혹을 정확히 가리킨다.
- **원본 임계값을 그대로 쓴다** — 대조가 쉬워지지만 시총 조건 하나로 코스닥이 통째로 빠진다.
  원본이 스스로 캘리브레이션 초안이라 밝힌 값을 정본처럼 다루는 것이기도 하다.
- **50일선·ATR20 계산기를 새로 만든다** — 원본과 완전히 같아진다. 그러나 지표가 둘 늘고
  (60일선·ATR14와 뜻이 거의 같다) 러너의 계산량만 커진다. 정배열과 변동성의 판정이 달라지지
  않는 범위라 판단했다 — **달라진다는 증거가 나오면 이 판단부터 뒤집는다.**
- **모듈 B를 지표가 아니라 새 플래그 도메인으로 지금 만든다** — 원본의 의도에 가장 가깝다.
  그러나 40개 중 8개만 계산 가능해 "플래그 시스템이 있다"는 인상만 주고 실제로는 대부분
  비어 있게 된다. 없는 것을 있는 것처럼 보이게 하는 쪽이라 받아들이지 않았다.

## 결과

- **쉬워지는 것**: 원본이 개정되면 이 표만 보고 무엇이 영향받는지 알 수 있다. 결핍이 화면에도
  적혀 있어 사용자가 이 프리셋의 한계를 안 채로 쓴다.
- **어려워지는 것**: 원본과 결과가 다르며, 그 차이의 절반은 데이터 부재고 절반은 임계값이다.
  둘을 섞어 보면 "왜 이 종목이 안 나오나"에 답할 수 없다 — 그래서 깔때기 숫자를 함께 남겼다.
- **되돌리려면**: `PresetCatalog.swingMidtermKr()` 한 블록이다. 지표는 남아도 무해하다.
- **이 표를 다시 쓰게 만드는 사건 셋**: ① 업종 소스가 붙으면 H-02·S-01·S-02가 원본으로
  돌아간다 ② 전체 재무제표로 옮기면 H-05가 살아난다 ③ 시장 지수 시세가 생기면 T-08이 살아난다.
  **셋 중 ①의 소스가 2026-08-10에 확인됐다**(아래 §단계 C).

**원본에 없는 조건 후보 하나가 실측에서 나왔다 — 감사의견.** DART가 `adt_opinion`을 1콜에
3개년 준다(`docs/api-spec/dart-open-api.md` §10-D). 비적정(한정·부적정·의견거절)은 상장폐지
사유이고, 원본 §1-1 ③의 *"부실 종목이 통과하는 것이 훨씬 비싼 실수"*에 정확히 맞는
**유니버스 제외 조건**이다. **후보로만 적는다** — 원본 대조표에 없는 항목을 이 표에 조용히
더하면 표가 "원본 대비 무엇이 남았는가"를 답하지 못하게 된다. **채택하려면 원본을 개정하는
것이 먼저이며 그것은 사용자 결정이다**(CLAUDE.md — 기획 정본을 에이전트 판단으로 고치지 않는다).
표본 둘이 다 `적정의견`이라 **비적정의 표기는 아직 모른다.**

## 남은 결손을 여는 길 — 무엇이 있어야 무엇이 살아나는가

**"원자료가 없다"의 근거가 한 종류가 아니다.** 지난 세션이 부른 DART 엔드포인트는
`fnlttSinglAcnt`·`fnlttSinglAcntAll` **둘뿐**이고 공시·기업정보 계열은 한 번도 부르지 않았다
(`docs/api-spec/dart-open-api.md`의 목차가 그 사실을 드러낸다). 아래 다섯으로 갈린다.

| 단계 | 뜻 | 해당 |
|---|---|---|
| **A** | **추가 수집이 0이다.** 원자료가 이미 있고 계산기만 없다 | S-03을 TTM EPS YoY로(분기 순이익 + `price_daily.listed_shares`) · S-01의 자체 5년 P/E 중앙값(원자료는 전량 보관이다 — ADR-0011이 자르는 것은 *지표*뿐) |
| **B** | 실측으로 이미 열려 있는데 안 쓴다 | H-05(영업활동현금흐름 4/4) · S-02의 EV(현금성자산 4/4, 총차입금은 합성) · S-04 매출총이익(`CostOfSales` **미측정**) |
| **C** | DART의 **다른 엔드포인트**가 필요하다 | 업종 분류 → H-02·S-01·S-02 + §부작용 해소 · 주식분할 이력 → 수정주가·H-06 · 합병/주식교환 → U-06 |
| **D** | DART 밖의 소스가 필요하다 | 시장 지수 일별 시계열 → T-08 · 외국인·기관 수급 → 모듈 B의 F 계열 |
| **E** | 실측이 닫았다 | H-03(감가상각비) · H-04(이자비용) — **단 표본이 4개사다.** 같은 문서가 "계정명 일관성은 4개사에서만 확인"을 미검증 항목으로 스스로 적으므로, "비금융 3사에 없다"까지가 실측이고 "350종목에 없다"는 외삽이다 |

**MUST: 단계 A를 단계 E로 오분류하지 않는다.** 실제로 S-01을 "지표 보존 180거래일이 막는다"로
잘못 적어 두었었다. ADR-0011은 **원자료를 전량 보관**하며 막는 것은 계산기 부재다 — 그 오분류
하나가 열려 있는 길을 영구 폐쇄로 만든다.

**단계 C·D는 스키마가 이미 비어 있는 채로 준비되어 있다.** `stock.sector`·`stock.listed_on`이
활성 종목 전부 NULL이고, `CorporateAction.Type`에 `SPLIT`/`REVERSE_SPLIT`이 있으며
`PriceDataSource.fetchCorporateActions`의 default가 `List.of()`다.

### 단계 C — 실측이 답한 것

판정 근거는 카탈로그가 아니라 **실제 호출**이다(`docs/api-spec/dart-open-api.md` §10).

| 단계 C 항목 | 판정 | 근거 |
|---|---|---|
| **업종 분류** → H-02·S-01·S-02 + §부작용 | **닫혔다 — 붙였다(P8)** | 350종목 전수 적재 완료. 표본 임계 5로 **254종목이 소분류, 53종목이 중분류 폴백, 43종목이 판정불가**다. Altman Z 제외는 65·66만이다(§부작용) |
| **주식분할 이력** → 수정주가·H-06 | **닫혔다 — 붙였다(P9)** | 「증자(감자) 현황」 `주식분할`·`무상증자`. 350종목 전수 수집으로 원장 91행이 되고 **공시가 59건을 자동 승인**했다. **액면병합은 원리적으로 안 실려**(자본금을 안 바꾼다) 그쪽은 `listed_shares` 휴리스틱 + 사람 판정이 답한다(§10-B · ADR-0049) |
| **합병/주식교환** → U-06 | **절반 열렸다** | 이사회결의일·합병기일은 구조화되어 오는데 **존속/소멸은 자유 텍스트뿐이라 "피인수인가"는 파싱이 필요하다**(§10-D) |

**MUST NOT: "열렸다"를 "값이 다 들어온다"로 읽지 않는다.** 셋 다 함정이 딸려 있고, 그 함정은
전부 **조용히 틀린 값**을 만드는 종류다 — 하루 어긋난 수정계수, 분할이 없는 것으로 보이는
종목, 인수한 쪽까지 잘라내는 U-06. 각각의 상세는 §10에 있고 **착수 전에 그 절을 읽는다.**

**MUST: 결손을 소스 부재로 판정하기 전에 원본 명세의 *가공법*을 먼저 읽는다.** U-05가
그랬다 — 원본이 *"`ipoDate` 필드보다 실제 가격 시계열 길이로 판정할 것"*이라고 **상장일을
쓰지 말라고 명시한 자리에서 상장일 소스를 찾고 있었다.** 위 §단계 표의 *"단계 A를 단계 E로
오분류하지 않는다"*와 같은 병인데 층이 다르다 — **막힌 것이 원자료인지 계산기인지 요구
자체인지를 가른다.**

**아래 문단은 P8 착수 전에 적은 우려이고, 실측이 그것을 확인했다** — 판정불가 43종목(12%)이
그 결과다. 우려가 해소된 것이 아니라 **드러난 채로 다뤄지고 있다**(표본 수를 지표로 낸다).

**IMPORTANT — 업종은 "소스가 있다"와 "H-02·S-01·S-02가 원본으로 돌아간다"가 다르다.**
원본이 요구하는 것은 업종 코드가 아니라 **업종 중앙값·업종 내 순위**이고, 그것은 업종당
종목이 충분해야 성립한다. **우리 유니버스는 350종목뿐이라 업종당 2~3개로 흩어질 수 있고,
그러면 "업종 중앙값"은 사실상 그 종목 자신이 된다** — 값이 나오므로 화면에서는 드러나지
않는다. 이 ADR이 §S-01에서 *"뜻이 다른 값을 같은 이름으로 부르지 않는다"*고 적은 것과
같은 병이며, 이번에는 모집단 크기가 원인이다.

**그 분포는 이제 재어 놓았다**(위 표 · ADR-0044 §실측). 350콜을 쓴다.

**회사분할(인적분할)은 여전히 닫혀 있다.** 「회사분할 결정」 개발가이드를 아직 받지 않았고,
`CorporateAction.Type`에 표현할 자리도 없다. P9의 결정 하나가 그것이다.

### 별도 phase로 갈라야 하는 것

여기 적는 이유는 `progress.md`가 고정 예산이기 때문이다 — 그쪽에는 이름 한 줄만 둔다.
착수 시 완료 판정을 `phase-criteria.md`에 **먼저** 적는다.

- **P8 업종 축 — 끝났다**(2026-08-11). 결정과 실측은 ADR-0044가 정본이다. 여기 남기는 것은
  **이 표를 다시 읽게 만든 사건**이라는 사실뿐이다 — H-02·S-01·S-02와 §부작용이 그것으로 바뀌었다.
- **P9 수정주가 정상화 — 끝났다**(2026-08-13). 결정과 실측은 ADR-0049(원장)·ADR-0050(판정)·
  ADR-0051(유도)·ADR-0052(호출 자리)가 정본이다. **추세 게이트 6개가 전부 `adj_close`를 쓰므로
  이 표를 다시 읽게 만든 사건이다** — T-01~T-07의 값이 62종목에서 실제로 바뀌었다.
  **다만 보정 커버리지가 원장 커버리지와 같다**(ADR-0051 §결과) — `UNSUPPORTED`·`REJECTED`로 남은
  사건의 종목은 여전히 미보정이고, 그 목록은 `corporate_action`이 이름으로 답한다.
- **P10 전체 재무제표 전환** — `account_id` 우선 매칭 재작성 + `IS`/`CIS` 분기(표본 넷 중 셋이
  `CIS`뿐이다) + 재무 5년 적재.
  **근거가 하나 늘었다**: 주요계정은 회사에 따라 **계정 행 자체를 주지 않는다**(오리온·오리온홀딩스에
  이익잉여금이 CFS·OFS 양쪽에 없다). 계정명 후보군 보강으로도 CFS/OFS 폴백으로도 안 열리고,
  전체 재무제표의 자본변동표가 남은 길이다(`docs/api-spec/dart-open-api.md` §8).
  - **여는 것은 H-05와 그 3종목뿐이다.** `financial_statement`의 `eps`·`bps`·`shares_outstanding`도
    전 행 NULL이지만 **그것은 결손이 아니다** — 앞 둘은 `src/main`에 읽는 코드가 0개고(대조용이다,
    `.claude/rules/data-pipeline.md`), 셋째는 `price_daily.listed_shares`가 없을 때만 타는 폴백인데
    그 컬럼의 NULL이 0행이다(ADR-0013). **NULL 컬럼을 세어 phase 크기를 잡으면 절반이 헛것이다.**
  - **MUST: 어댑터 전환을 적재보다 먼저 한다.** `FinancialWriter.fillMissing()`은 어댑터가 준 값이
    `null`이면 그 컬럼을 후보에서 뺀다. 순서가 뒤집히면 수천 콜을 태우고 OCF가 한 칸도 안 채워진
    채 **잡이 SUCCESS로 끝나고**, 고쳐서 다시 돌리면 같은 엔드포인트에 누적이 쌓여 한도에 닿는다
    (한도는 API별이다 — `dart-open-api.md` §5).
  - **MUST: 적재 뒤 백필을 함께 계획한다.** 이 잡은 `indicator_value`를 건드리지 않으므로,
    백필이 없으면 `financial_statement`가 다 차도 **화면과 프리셋이 한 글자도 안 바뀌고 H-05도
    안 나온다.** 에러도 경고도 없다. 무효화를 생략해도 되는지는 ADR-0040이 "그때 다시 답하라"고
    표시해 둔 자리다. **백필 자체는 1거래일이면 된다** — 화면·프리셋·아래 §깔때기가 전부
    `max(trade_date)` 한 장만 읽는다(ADR-0045가 그 밖을 저장하지도 않는다).
  - **MUST: 착수 판정의 첫 질문을 "어느 보고서 코드가 필요한가"로 둔다. `fs_div` 폴백 비율이
    아니다.** 8,400콜은 350종목 × **6년** × **4보고서**이고(`FinancialRefillJob`의
    `estimatedCalls`), **H-05가 요구하는 것은 연간뿐이다** — 원본 §H-05의 가공법이
    `sum(operatingCashFlow, 최근 5개 회계연도)`다. 사업보고서(`11011`)만이면 **2,100콜**,
    폴백이 전량 붙어도 4,200으로 보수 예산의 42%다. **순서를 뒤집으면 존재하지도 않는 예산
    초과를 관리하느라 4배를 태운다.**
  - **MUST: H-05 계산기가 선언할 `financialYearsNeeded`의 전역 파급을 먼저 본다.** 러너는
    전역 최대 하나로 읽으므로(`IndicatorRunner.readRawData`) 현재 최대 2가 5로 오르면
    `IndicatorDataReader`의 `(years+1)*4`가 **12분기 → 24분기**가 되고 그 비용이 350종목 ×
    모든 지표에 걸린다. **"지표 추가 비용 1파일"이 이 파급을 가린다** —
    `IndicatorExtensibilityTest`는 파일 수를 세지 읽기 비용을 세지 않는다.
  - **`FinancialWriter`의 `FILL_MISSING`은 값이 다르면 덮지 않고 WARN만 낸다.** `account_id`
    매칭으로 **이미 값이 든 컬럼**이 교정될 수 있는데 그것이 저장되지 않는다. 덮을지는
    어댑터 전환 때 정한다 — 적재까지 가서 만나면 이미 콜을 태운 뒤다.
  - **쿼터 카운터(`TokenBucketRateLimiter.usedToday`)는 인메모리이고 `BootstrapRunner`는
    실행마다 새 JVM이다.** 재실행하면 0에서 다시 세므로 **실제 누적은 아무도 모른다.**
    소량 검증 → 전량 → 재실행이 이어지는 경로에서 실행 횟수 × 예상 콜을 손으로 적는다.
  - **라이브 표본에 오리온을 넣는다.** 기존 표본 넷(삼성전자·NAVER·카카오·KB금융)은 이미
    이익잉여금이 나오는 회사들이라, 그대로 두면 **이 phase가 여는 SCE 경로가 검증되지 않는다.**
  - **§11-E는 현금흐름표의 분기 금액 규칙을 적지 않았다.** `thstrm_amount`가 [3개월]이라고
    밝힌 것은 (포괄)손익계산서뿐이다. 연간만 쓰는 동안은 안 드러나고, 분기 OCF를 쓰는 조건이
    붙는 순간 4배나 1/4로 조용히 틀린다. **확인해서 그 절에 적거나 "미확인"으로 명시한다.**
- **T-08 시장 지수 — P10에 얹을 수 없다.** 원자료는 지수 2콜로 끝나지만(`data-go-kr-market-index.md`)
  **지표 계층에 시장 지수를 받을 자리가 없다**: `DataRequirement`의 필드가 `priceBarsNeeded`·
  `financialYearsNeeded`·`dependsOn` 셋뿐이고 `dependsOn`은 **같은 종목의 다른 지표** 시계열이다.
  즉 새 테이블·어댑터 위에 `DataRequirement`·`IndicatorContext`·`IndicatorDataReader`·`IndicatorRunner`
  **코어 넷을 고쳐야 한다.** 이것은 저장 구조가 아니라 **지표 계약**을 바꾸는 일이고, Phase 1·3·7이
  공유하는 *"지표 추가 비용이 1파일"* 기준(`IndicatorExtensibilityTest`가 단언한다)을 다시 여는
  결정이다. **외부 콜 수로 우선순위를 매기면 이 phase가 가장 싸 보인다 — 실제로는 가장 크다.**
  기준지수 선택도 미결이다(같은 문서가 "phase의 결정"으로 열어 두었다).
  - **P8이 그 넷 중 셋을 이미 열었다**(ADR-0044) — `IndicatorContext`가 종목 속성을 받고
    `IndicatorDataReader`·`IndicatorRunner`가 그것을 나른다. **그러나 T-08이 싸진 것은 아니다.**
    P8이 더한 것은 **종목 하나에 딸린 스칼라**이고 T-08이 필요로 하는 것은 **종목 밖의 시계열**이라
    `DataRequirement`가 그것을 선언할 자리가 여전히 없다. **열린 것은 문이지 길이 아니다.**
