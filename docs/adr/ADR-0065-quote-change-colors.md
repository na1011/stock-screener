# ADR-0065. 시세 등락은 앱의 값 색조를 그대로 쓴다 — 국내 증권앱 관례를 쓰지 않는다

## 결정

전일 대비 등락을 **상승 초록·하락 빨강**으로 그리고, 지표 카드가 쓰는 값 색조
(`--p-tone-favorable-text`/`--p-tone-unfavorable-text`)를 **그대로** 쓴다. 새 색도 새 토큰도
만들지 않는다. 국내 증권앱 관례(상승 빨강·하락 파랑)는 **검토했고 쓰지 않는다.**

## 규칙

- MUST NOT: 등락에 **`▲`/`▼`를 쓰지 않는다.** 이유가 둘이고 둘 다 이 저장소 안에 있다.
  ① ADR-0021 §형태로 가른다가 `MUST NOT: 유불리 방향 표식(▲/▼)에 색을 주지 않는다`를 못 박았다.
  ② 같은 화면의 `IndicatorCard`가 그 글리프를 이미 쓰는데 **극성이 반대다** — `lib/direction.ts`의
  `▼`는 「낮을수록 유리」라 PER 카드의 `▼`는 *좋다*는 뜻이다. 방향은 부호와 색이 진다.
- MUST NOT: 등락 전용 색 토큰을 만들지 않는다. 뜻이 값 색조와 같으므로 이름을 나누면 한 사실이
  두 곳에 생기고, `tokens.spec.ts`의 「값 색조는 판정 Tag가 없는 화면에만 있다」가 세는 소비처
  목록도 갈린다.
- MUST: 화면에 **「전일 대비」라고 적지 않는다.** 거래정지 구간은 봉 자체가 없어 직전 거래일이
  수 주 전일 수 있고(실측: 207940은 26거래일 전) 프론트에는 거래일 달력이 없어 인접 여부를
  판정할 수단도 없다. `quoteBasisLabel`이 **날짜를 그대로** 말한다.
- MUST: 등락률은 소수 **두 자리**다(`formatQuoteChange`). `formatSignedPercent`(한 자리)는 재무
  증감률용이므로 그대로 둔다.

## 검증

```bash
# 1. 등락이 값 색조를 그대로 쓰는가 (전용 토큰이 되살아나지 않았는가)
rg -n -- '--p-tone-(favorable|unfavorable)-text' frontend/src/components/stock/StockHeader.vue
#    → 잡혀야 한다
rg -l -- '--p-quote-' frontend/src
#    → 아무것도 나오지 않아야 한다

# 2. 등락에 방향 글리프가 없는가
#    마지막 필터가 블록 주석을 거른다 — 주석이 "왜 안 쓰는지"를 적으려고 그 글리프를 부르고,
#    그것까지 잡으면 이 검사가 늘 빨개져 아무도 안 보게 된다 — `lib/sourceScan.ts`의
#    `stripBlockComments`가 같은 판단을 코드로 적어 두었다.
rg -n '[▲▼]' frontend/src/lib/quote.ts frontend/src/components/stock/StockHeader.vue | rg -v ':\s*\*'
#    → 아무것도 나오지 않아야 한다

# 3. 그 색이 실제로 읽히는가 (지금까지 아무도 재지 않던 자리다)
cd frontend && npx vitest run src/theme/contrast.spec.ts
```

## 배경

사용자가 처음에는 국내 증권앱 관례(상승 빨강·하락 파랑)를 골랐고 그렇게 구현했다. 실제 화면에서
대가가 드러나 뒤집었다 — 종목 상세 한 화면에서

- **빨강이 두 가지를 말했다.** 헤더에서는 "상승", 바로 아래 지표 카드에서는 "불리".
- **파랑이 둘이 됐다.** `primary`가 cobalt(`#4d93ff`)이고 하락이 sky(`#38bdf8`)인데, 하락색과
  소속 배지 글자색(`{primary.300}` `#7faeff`)의 **명도 대비가 1.04**이고 색상각만 20°
  (198° ↔ 218°) 차이였다. 둘은 두 줄 간격으로 붙어 있다.

그리고 **형태로 가를 길이 없다** — 이 저장소가 ADR-0021에서 초록·빨강의 두 뜻을 가를 때 쓴
수법인데, 남은 형태 채널이 `▲`/`▼`이고 위 §규칙이 그것을 막는다.

## 버린 대안

- **국내 증권앱 관례(상승 빨강·하락 파랑)** — 위 §배경이 버린 이유다. 실측 대비비는
  상승 `#f87171` 6.03:1, 하락 `#38bdf8` 7.79:1로 **읽히기는 했다.** 문제는 대비가 아니라
  같은 화면에서 색이 뜻을 두 개씩 갖는 것이었다.
- **색 없이 부호만**(`FinancialsPanel`의 YoY와 같은 처리) — 충돌이 아예 없지만, 등락은 이
  카드에서 두 번째로 큰 값이라 무채색이면 오른 것과 내린 것을 훑어서 구별할 수 없다.

## 결과

색 계열이 늘지 않고, 종목 상세에서 초록·빨강이 각각 한 뜻만 갖는다. `--p-tone-*` 소비처가
셋으로 늘었고 `tokens.spec.ts`의 「값 색조는 판정 Tag가 없는 화면에만 있다」가 그것을 반영한다.

대가는 **국내 관례와 반대**라는 것이다. 국내 증권앱을 쓰던 사용자는 처음에 한 번 반대로 읽을
수 있다. 되돌리려면 `preset.ts`에 등락 전용 색을 다시 두고 `StockHeader`의 클래스 둘이 그것을
가리키게 한다 — 그때 §배경의 두 충돌이 함께 돌아온다.
