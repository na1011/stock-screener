# ADR-0003. 프리셋과 커스텀 필터가 하나의 조건 모델을 공유하고, 조건은 EXISTS로 번역한다

## 결정

조건을 "지표 - 연산자 - 피연산자"의 데이터로 다루고, 판정 방식(FILTER/SCORING)은 조건이 아니라 실행의 속성으로 둔다. 조건 하나는 상관 `EXISTS` 서브쿼리 하나로 번역한다. 저장 구조는 처음부터 트리이되 v1은 깊이 1만 만든다.

## 규칙

- MUST: 번역기와 판정기는 **연산자에만** 분기한다. 지표 코드에 분기하지 않는다.
- MUST: 조건의 판정 의미를 `ComparisonOperator.test()` 한 곳에만 둔다. SQL 번역, 화면의 선정 이유, 워치리스트 알림이 모두 이것을 따른다.
- MUST: `ConditionOutcome`의 3상태(충족/불충족/판정불가)를 유지한다. "지표 없음"을 "불충족"으로 합치지 않는다.
- MUST: SCORING은 좁히는 WHERE 없이 전체 종목을 대상으로 한다. 일부 조건만 만족한 종목도 결과에 남아야 한다.
- MUST: 번역과 판정을 재귀로 유지한다. v1이 깊이 1만 쓰더라도 일반형을 지운다면 v2에서 재작성해야 한다.
- MUST NOT: 조건 개수만큼 SELECT 절에 CASE 컬럼을 추가하지 않는다. 쿼리는 항상 2개다.
- MUST NOT: JOIN 기반 번역으로 바꾸지 않는다.

## 배경

`.claude/rules/backend.md`가 세 가지를 동시에 요구한다 — 두 판정 방식이 하나의 조건 모델을 공유할 것, 조건 목록이 향후 OR 트리의 최상위로 흡수될 것, 하드코딩 분기로 우회하지 말 것.

핵심 통찰은 **프리셋과 커스텀 필터가 두 종류의 조건이 아니라 같은 조건에 대한 두 개의 접기(fold)**라는 것이다. 가중치는 조건 자체가 아니라 조건-소속 관계의 속성이고, 판정 방식은 실행의 속성이다. 그래서 조건은 자신이 어디에 쓰이는지 모른다.

"판정 불가"를 별도 상태로 둔 이유: FILTER에서는 "지표 없음"과 "불충족"이 똑같이 제외지만, SCORING에서는 다르다. 5개 중 4개를 만족한 종목이 나머지 하나의 지표가 없다는 이유로 사라지면 순위를 매기는 목적이 무너진다. 화면에도 "조건 불충족"과 "데이터 없음"이 다르게 보여야 사용자가 이유를 이해한다.

## 버린 대안

- **프리셋용·커스텀용 조건 모델 분리** — 지표 하나 추가에 양쪽을 고쳐야 하고 시간이 지나며 어긋난다. `backend.md`가 명시적으로 금지한다.
- **JOIN 기반 번역** — AND만 있는 v1에서는 동등하지만, OR 그룹은 `(EXISTS OR EXISTS)`로 자연스럽게 확장되는 반면 JOIN은 OUTER JOIN + null 검사로 변형되어야 한다. 즉 트리로 확장할 수 없는 형태가 되어 spec §10과 충돌한다. 행 증식으로 DISTINCT가 필요해지는 문제도 있다.
- **평면 조건 목록으로 저장하고 나중에 트리로 마이그레이션** — 저장된 모든 조건과 모든 쿼리 경로를 다시 써야 한다. 지금 자기참조 FK 하나를 두는 비용이 압도적으로 싸다.
- **SELECT 절에 조건별 CASE 컬럼** — 조건 수만큼 컬럼이 늘고 요청마다 SQL 모양이 달라져 계획 캐시를 못 탄다.
- **점수 계산을 SQL에서** — 정렬·페이징 정합성 때문에 SQL이 유리하지만, v1 규모(850종목)에서는 2번 쿼리로 값을 가져와 Java에서 접는 편이 선정 이유 생성과 판정 로직 공유를 자연스럽게 만든다. **성능이 문제가 되면 재검토한다** — 그때는 `ORDER BY` 표현식을 SQL로 내리는 것이 답이다.

## 결과

- 쉬워지는 것: 새 지표가 번역기·판정기를 건드리지 않는다. 프리셋을 FILTER로 돌리거나 커스텀 화면에 가중치를 주는 것이 공짜다. v2의 OR 도입은 UI 변경만으로 끝난다(번역·판정은 이미 동작 확인).
- 어려워지는 것: 점수 정렬이 메모리에서 일어나므로 종목 수가 크게 늘면 `LIMIT` 푸시다운이 불가능해진다. 유니버스가 850종목으로 고정된 전제에서만 성립한다.
- 되돌리려면: `screening` 패키지 전체와 V3 마이그레이션을 함께 고쳐야 한다.
