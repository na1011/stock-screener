# 진행 상태

세션이 바뀌어도 남아야 하는 "지금 어디까지 왔는가". 세션 시작 시 훅이 이 파일을 주입한다.

- 요구사항은 [`spec`](./stock-screener-project-spec.md), **phase 완료 판정**은 [`phase-criteria.md`](./phase-criteria.md), 외부 API 실측은 [`api-spec/`](./api-spec/), 되돌리기 어려운 결정은 [`adr/`](./adr/)에 있다. **여기에 옮겨 적지 않는다.**
- 무엇을 했는지는 `git log`에 있다.
- MUST: 상태 주장은 확인 가능한 형태로 쓴다. 낡은 문서를 에이전트는 그대로 믿는다.
- **줄을 더할 때는 뺄 것을 함께 정한다.** 고정 예산이지 로그가 아니다. 경고선·절단선은 `check-doc-staleness.sh`가 알린다.
- **MUST: 한 줄을 여기 둘지는 중요도가 아니라 유도 가능성이 정한다.** 코드로 알 수 있으면 지우고, 특정 파일을 열어야 위반하면 `.claude/rules/`로, 명령을 실행해야 위반하면 hook·skill로 보낸다. 남는 것은 **코드에 흔적이 없어 물어볼 생각조차 못 하는 사실**과 **지금 할 일**뿐이다. 판단 기준 전문은 `.claude/rules/harness-core.md`에 있다.

## Phase 상태

**1~5·7·P8·P9·P10·P12 완료. 6은 미완료다.** 판정 기준은 `phase-criteria.md`, 근거는 `docs/adr/`가 답한다. 7(스윙 프리셋)이 **원본 대비 무엇을 못 옮겼는지는 ADR-0039의 대조표**다.

**6이 걸린 곳은 하나다** — Phase 6 기준이 **"두 채널 모두"**(spec §8)를 명시하는데 `MAIL_*`이 비어 알림이 메신저로만 나간다. **코드는 붙어 있고**(ADR-0025) 자격증명만 없다 — 사람이 넣으면 충족된다(`TODO.md`). **MUST NOT: 자격증명이 없는 채로 완료로 적지 않는다.**

**P12는 §P12 첫 축(TradingView 대조)을 면제받고 완료이며, 2026-08-14에 점수화 계층을 철회했다** — 경위는 **ADR-0046 §승인된 예외**와 **§2026-08-14 개정**이 정본이다. Tier·9등급·leaf가 사라지고 `ICHIMOKU_SP_KR`은 관측 조건 다섯을 쓴다. **여전히 `SWING_MIDTERM_KR`과 같은 테스트베드이고 원본 대조를 한 적이 없다** — 13 수식자는 전부 정수라 부등호 하나가 뒤집혀도 값이 그럴듯하다. **MUST NOT: 이 프리셋의 결과를 매매 판단의 근거로 쓰지 않는다.**

**아직 없는 것**: 미국 어댑터(v1.1, ADR-0010).

**실데이터가 들어 있다**(개수·최신 일자는 DB에 묻는다).

**허용목록의 지인 계정(비관리자) 하나가 spec §9의 "관리자 외 계정"이다** — 지우면 그 수용 기준이 다시 미충족이 된다.

## 다음에 할 일

**사람이 값을 채우는 일이 남았다** — 목록은 [`TODO.md`](../TODO.md), 발급 여부는 `./gradlew checkEnv`가 답한다(문서가 먼저 낡는다).

- **아무것도 저절로 돌지 않는다**(ADR-0043). 앱·터널은 `ops/start.sh`로만 뜨고 죽으면 죽은 채로 있다. 무엇이 도는지는 `ops/status.sh`가, 반영은 `ops/deploy.sh`가 답한다(ADR-0034).
- **MUST NOT: 결손이 생길 때마다 조건을 빼서 해결하지 않는다**(2026-08-10 사용자 판단). 개별 판단이 정당해도 **누적은 원본과 다른 물건**이 된다. 막히면 **원자료를 여는 길을 먼저 본다** — `ALTMAN_Z` 0건이 그렇게 풀렸다(ADR-0040).
- **남은 phase는 P11(모듈 B) 하나다** — 범위와 착수 전 함정은 ADR-0039 §별도 phase가 답한다. 착수 시 완료 판정을 `phase-criteria.md`에 **먼저** 적는다.
- **보정 못 한 사건이 창에 들면 그 지표는 이제 값을 내지 않는다**(ADR-0055). 남은 위험은 반대쪽이다 — **원장에 없는 사건은 여전히 통과한다.** "보정한다"를 "전량 보정됐다"로 읽지 않는다.
- **낱말 없이 증거만으로 판정한 무상증자가 있다**(표지: `HEURISTIC`+`APPLIED`+`BONUS_ISSUE`. 분할·병합은 비율의 정본이 `listed_shares`라 해당 없다). 다음 분기 공시가 와도 **`record`가 판정된 행을 덮지 않아 대조는 사람 몫이다.**
- **재무 정정공시를 정기적으로 발견하는 경로가 없다**(ADR-0056). 재무를 받는 잡 셋이 전부 수동이라, 정정이 나면 그때까지 그 종목의 지표가 **틀린 채로 있는다** — 실제로 고려아연이 그랬다. 찾는 값은 싸다(36콜, `batch-load` skill).
- **`SWING_MIDTERM_KR`은 지표를 늘리기 위한 테스트베드이지 종목을 추천받는 프리셋이 아니다.** 결과 수가 적은 것이 정상이며 **MUST NOT: 임계값을 풀어 해결하지 않는다**(경위는 ADR-0044 §승인된 예외).
- **훅의 빈자리 셋.** ① `/compact` 뒤 `SessionStart` 미발화(matcher) ② `guard-destructive.sh`에 `kill` 판정이 없다 ③ `progress.md` 갱신 상기 계층이 없다. 후보 `Stop`은 **배달이 미검정이다 — 재기 전에 세우지 않는다.**

## 어떤 파일을 열든 알아야 하는 것

파일별 함정은 `.claude/rules/*.md`가 glob으로, 작업별 절차는 skill이 스스로 로드한다. **무엇이 어디 있는지 여기 옮겨 적지 않는다** — 목록은 반드시 낡고, 낡은 목록은 "로드됐다"고 믿게 만든다.

- **phase별 브랜치를 만들지 않는다.** `main`에 직접 쌓는다 — Phase 2 브랜치가 `main`을 4개월 묶어둔 전례가 근거다(CLAUDE.md가 이 줄을 가리킨다). 브랜치는 **버릴 수 있는 탐색**에만 쓴다.

## 미룬 것 / 알려진 미완성

- **감춘 지표를 상세 화면에서 펼쳐 볼 길이 없다**(ADR-0058). 보는 경로가 "스크리너에서 조건에 추가"뿐인데 `screenDraft`가 영속되지 않아 **상세를 새로고침하거나 링크로 바로 열면 그 경로가 끊긴다.** 토글을 두면 「기본/전체」 상태를 어디 기억할지가 따라붙어 미뤘다.
- **업종 표본 수 3개(`*_SECTOR_N`)가 재무 구획에 카드로 뜬다.** `detail_default`로 감출 수 있게 됐지만 사용자가 지목하지 않았다.

- **`HEAD /`에 Spring Security 응답 헤더가 빠진다** — 영향은 감시 도구뿐이라 미뤘다.
- **Spring Batch를 쓰는 잡이 없다** — ADR-0005의 재시작성을 아무도 안 쓴다(`BATCH_*` 0행, `linkJobExecution()`은 죽은 코드). `BatchExecutionContext.abort()`도 같은 모양이다 — 프로덕션 호출자가 0인데 javadoc은 "일일 쿼터 소진이 대표적이다"라고 말한다. **걷을지 쓸지 정한다.**

## 되돌리지 말 것

**공통점: 지워도 컴파일되고 테스트도 통과하는데 나중에 조용히 망가진다.** 아래 셋만 여기 남기는 이유는 **그 파일을 건드리지 않아도 무너질 수 있어** 그 알림이 걸리지 않기 때문이다.

- **ADR-0005 — `JobRepository` 빈 직접 정의를 지우지 않는다.** 지우면 인메모리로 돌아가 아무것도 기록되지 않고 재시작이 불가능해지는데 **아무 증상이 없다.**
- **ADR-0007 — `rollbackFor = Exception.class`와 `StockTaskRunner` 분리를 유지한다.** Spring 기본은 checked 예외에 커밋하고, 자기 호출은 프록시를 안 거쳐 `REQUIRES_NEW`가 무시된다.
- **ADR-0012 — 활성 유니버스를 0개로 만들지 않는다.** 시총 어댑터가 `@ConditionalOnApiKey`라 **키 없는 환경에서** 시드까지 내리면 하나도 안 남는다(실제로 테스트 7건이 깨졌다). 운영은 시총 둘이 활성이고 시드가 비활성인 것이 정상이며, 테스트 DB는 정반대다.
