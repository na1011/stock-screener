# 진행 상태

세션이 바뀌어도 남아야 하는 "지금 어디까지 왔는가". 세션 시작 시 훅이 이 파일을 주입한다.

- 요구사항은 [`spec`](./stock-screener-project-spec.md), **phase 완료 판정**은 [`phase-criteria.md`](./phase-criteria.md), 외부 API 실측은 [`api-spec/`](./api-spec/), 되돌리기 어려운 결정은 [`adr/`](./adr/)에 있다. **여기에 옮겨 적지 않는다.**
- 무엇을 했는지는 `git log`에 있다.
- MUST: 상태 주장은 확인 가능한 형태로 쓴다. 낡은 문서를 에이전트는 그대로 믿는다.
- **줄을 더할 때는 뺄 것을 함께 정한다.** 고정 예산이지 로그가 아니다. 경고선·절단선은 `check-doc-staleness.sh`가 알린다.
- **MUST: 한 줄을 여기 둘지는 중요도가 아니라 유도 가능성이 정한다.** 코드로 알 수 있으면 지우고, 특정 파일을 열어야 위반하면 `.claude/rules/`로, 명령을 실행해야 위반하면 hook·skill로 보낸다. 남는 것은 **코드에 흔적이 없어 물어볼 생각조차 못 하는 사실**과 **지금 할 일**뿐이다. 판단 기준 전문은 `.claude/rules/harness-core.md`에 있다.

## 다음에 할 일

**v1 구현은 끝났다. 사람이 값을 채우는 일이 남았고** 목록은 [`TODO.md`](../TODO.md)에 있다. 발급 상태는 문서가 아니라 `./gradlew checkEnv`에 묻는다 — 발급은 문서 밖에서 일어나 문서가 먼저 낡는다.

- **도는 것은 `build/libs`가 아니라 `~/Library/Application Support/stock-screener/app.jar`이다.** 코드나 `.env`를 고쳤으면 `ops/deploy.sh`를 돌려야 반영된다 — `build`만 하면 옛것이 돌고 화면에 단서가 없다(ADR-0034).
- **`indicator_value` 세 인덱스에 `REINDEX INDEX CONCURRENTLY`가 남았다**(인덱스가 힙의 2.4배). **20시 배치의 purge가 한 번 돈 뒤** 한다 — 뒤집으면 곧 지워질 행까지 인덱싱한다. purge는 `DailyUpdateJob`에만 있어 따로 못 돌린다. **돌았는지는 세션 시작의 ADR-0011 전제가 답한다**(깨져 있으면 아직이다).
- **MUST NOT: 결손이 생길 때마다 조건을 빼서 해결하지 않는다**(2026-08-10 사용자 판단). 개별 판단이 전부 정당해도 **누적은 원본과 다른 물건**이 된다. 막히면 **원자료를 여는 길을 먼저 본다** — `ALTMAN_Z` 0건이 실제로 그렇게 풀렸다(ADR-0040). 총량 판정과 남은 결손의 단계별 분류는 ADR-0039에 있다.
- **다음 phase 후보 넷은 ADR-0039 §남은 결손을 여는 길에 있다**(P8 업종 · P9 수정주가 · P10 전체 재무제표 · P11 모듈 B). **착수 전 완료 판정을 `phase-criteria.md`에 먼저 적는다.**
- **사용자 답을 기다리는 것**: DART API의 **개발가이드**(경로·파라미터·응답 필드). 어떤 API가 있는지는 받아 `api-spec` §9에 정리했다 — **액면분할 전용 API가 없다는 것이 거기서 확정됐다(P9가 커진다).** 남은 질문은 [`TODO.md`](../TODO.md) §1.
- **훅이 조용히 안 도는 자리 셋**(2026-08-10 확인). ① `/compact` 뒤 `SessionStart` 셋이 안 뜬다(matcher). ② `SessionEnd` 배달 0건. ③ `guard-destructive.sh`에 `kill` 판정이 없어 `pkill -f java`가 운영 앱을 죽여도 안 막힌다.
- **20시 배치가 당일 종가를 받아오는가**(2026-08-10 첫 관측) — `SELECT max(trade_date) FROM price_daily`가 그날이면 그렇다. 아니면 시각을 늦춘다(ADR-0033). 0건 WARNING은 `stdout.log`로만 간다.

## 어떤 파일을 열든 알아야 하는 것

파일별 함정은 `.claude/rules/*.md`가 glob으로, 작업별 절차는 skill이 스스로 로드한다. **무엇이 어디 있는지 여기 옮겨 적지 않는다** — 목록은 반드시 낡고, 낡은 목록은 "로드됐다"고 믿게 만든다.

- **저장소는 `/Users/na1011/dev/stock-screener`에 있다**(2026-08-09에 `~/Desktop`에서 옮겼다, ADR-0034).

## 미룬 것 / 알려진 미완성

- **알림이 아직 로그로만 나간다.** 채널 구현은 붙어 있고 자격증명이 없어 비활성이다 — 기동 로그의 `알림 채널이 하나도 구성되지 않아…`가 그 상태의 표시다(ADR-0025).
- **`HEAD /`에 Spring Security 응답 헤더가 빠진다.** 영향은 HEAD로 찌르는 감시 도구뿐이라 미뤘다.
- **인터랙션 로그에 리텐션이 없다.** 지인 몇 명 규모에서 수년간 문제가 없어 미뤘다. 필요해지면 `DailyUpdateJob`의 정리 단계에 붙인다.
- **프론트 스택트레이스가 minify된 채다.** 배선은 다 됐고 Sentry 슬러그만 비었다 — 값을 채우면 코드 변경 없이 올라간다.
- **Spring Batch를 쓰는 잡이 없다.** `Job`·`Step`이 없어 `BATCH_*`가 0행이고 `linkJobExecution()`은 죽은 코드다 — ADR-0005의 재시작성을 아무도 안 쓴다. **걷을지 쓸지 정한다.**

## 되돌리지 말 것

**공통점: 지워도 컴파일되고 테스트도 통과하는데 나중에 조용히 망가진다.** 아래 셋만 여기 남기는 이유는 **그 파일을 건드리지 않아도 무너질 수 있어** 그 알림이 걸리지 않기 때문이다.

- **ADR-0005 — `JobRepository` 빈 직접 정의를 지우지 않는다.** 지우면 인메모리로 돌아가 아무것도 기록되지 않고 재시작이 불가능해지는데 **아무 증상이 없다.**
- **ADR-0007 — `rollbackFor = Exception.class`와 `StockTaskRunner` 분리를 유지한다.** Spring 기본은 checked 예외에 커밋하고, 자기 호출은 프록시를 안 거쳐 `REQUIRES_NEW`가 무시된다.
- **ADR-0012 — 활성 유니버스를 0개로 만들지 않는다.** 시총 어댑터가 `@ConditionalOnApiKey`라 **키 없는 환경에서** 시드까지 내리면 하나도 안 남는다(실제로 테스트 7건이 깨졌다). 운영은 시총 둘이 활성이고 시드가 비활성인 것이 정상이며, 테스트 DB는 정반대다.
