# 진행 상태

세션이 바뀌어도 남아야 하는 "지금 어디까지 왔는가". 세션 시작 시 훅이 이 파일을 주입한다.

- 요구사항은 [`spec`](./stock-screener-project-spec.md), **phase 완료 판정**은 [`phase-criteria.md`](./phase-criteria.md), 외부 API 실측은 [`api-spec/`](./api-spec/), 되돌리기 어려운 결정은 [`adr/`](./adr/)에 있다. **여기에 옮겨 적지 않는다.**
- 무엇을 했는지는 `git log`에 있다.
- MUST: 상태 주장은 확인 가능한 형태로 쓴다. 낡은 문서를 에이전트는 그대로 믿는다.
- **줄을 더할 때는 뺄 것을 함께 정한다.** 고정 예산이지 로그가 아니다. 경고선·절단선은 `check-doc-staleness.sh`가 알린다.
- **MUST: 한 줄을 여기 둘지는 중요도가 아니라 유도 가능성이 정한다.** 코드로 알 수 있으면 지우고, 특정 파일을 열어야 위반하면 `.claude/rules/`로, 명령을 실행해야 위반하면 hook·skill로 보낸다. 남는 것은 **코드에 흔적이 없어 물어볼 생각조차 못 하는 사실**과 **지금 할 일**뿐이다. 판단 기준 전문은 `.claude/rules/harness-core.md`에 있다.

## Phase 상태

**1~6 전부 완료.** 판정 기준은 `phase-criteria.md`, 근거는 `docs/adr/`, 무엇을 봤는지는 `git log`가 답한다. 2·3·4는 실데이터로, 5·6은 관통 검증까지 마쳤다(2026-08-08·09).

**아직 없는 것**: 미국 어댑터(v1.1, ADR-0010). *있는* 것은 `./gradlew build`와 `git log`가 답한다.

**실데이터가 들어 있다.** 코드에 흔적이 없는 사실이라 여기 남긴다 — 개수와 최신 일자는 DB에 묻는다.

**허용목록에 지인 계정 하나가 비관리자로 등록돼 있다**(2026-08-09). spec §9가 요구하는 "관리자 외 계정"이 이것이고, 지우면 그 수용 기준이 다시 미충족이 된다.

## 다음에 할 일

**v1 구현은 끝났다. 남은 것은 사람이 값을 채우는 일과 그 뒤의 확인뿐이다** — 목록은 [`TODO.md`](../TODO.md)에 있다(알림 채널 자격증명, Sentry org·project 슬러그, ICANN 인증). 발급 상태는 문서가 아니라 `./gradlew checkEnv`에 묻는다 — 발급은 문서 밖에서 일어나 문서가 먼저 낡는다.

- **도는 것은 저장소의 `build/libs`가 아니라 `~/Library/Application Support/stock-screener/app.jar`이다.** 코드나 `.env`를 고쳤으면 `ops/deploy.sh`를 돌려야 반영된다 — `./gradlew build`만 하면 옛것이 돌고 화면에는 아무 단서가 없다(ADR-0034).
- **`indicator_value` 세 인덱스에 `REINDEX INDEX CONCURRENTLY`가 남았다**(인덱스가 힙의 2.4배). **오늘 20시 배치의 purge 뒤**에 한다 — 뒤집으면 곧 지워질 행까지 인덱싱한다. purge는 `DailyUpdateJob`에만 있어 따로 못 돌린다. **그때까지 ADR-0011 전제(445 > 180)가 깨진 채 뜨는 것은 정상이다.**
- **Phase 7(중장기 스윙 프리셋)이 커밋됐지만 배포되지 않았다.** `ops/deploy.sh`가 자동 승인 분류기에 막혀 사람이 돌려야 한다. 배포하면 V15·V16과 신규 지표 11개, `SWING_MIDTERM_KR`이 함께 반영되고 **최신 거래일 하나만 백필하면 프리셋이 돈다**(스크리닝은 최신 일자 한 장만 읽는다). 가격 게이트 깔때기를 SQL로 미리 쟀다(최신일): 350 → 시총1조 277 → 거래대금100억 224 → 200일선위 88 → 정배열 78 → 1개월상승 75 → 이격도1.25 53 → 52주저점+30% 52 → **52주고점−25% 16**. 마지막이 가장 크게 자른다(고점 대비 중앙값 −34.6%). 여기에 ATR·재무 다섯이 더 걸리므로 **0건이 나올 수 있다 — 이 숫자와 대조해 범인을 가르고, 이격도 상한을 1.25 → 1.30으로 푸는 것이 첫 손잡이다.**
- **훅이 조용히 안 도는 자리 셋**(2026-08-10 전수 확인). ① `/compact` 뒤엔 `SessionStart` 훅 셋이 안 뜬다(matcher가 `startup|resume|clear`). ② `SessionEnd` 배달 0건이라 `remind-progress.sh`가 죽어 있었을 수 있다. ③ `guard-destructive.sh`에 `kill` 판정이 없어 `pkill -f java`가 운영 앱을 죽여도 안 막힌다.
- **20시 배치가 당일 종가를 받아오는지는 오늘(2026-08-10) 20시 실행이 답한다** — 소급 조회로는 알 수 없다. 0건이면 WARNING이 `stdout.log`로만 간다(채널이 비었다). **거래일마다 오면 시각을 늦춘다**(ADR-0033). **2026-08-07이 빈 것은 휴장이다**(실측, `api-spec/`).
- **`HEAD /`에만 Spring Security 응답 헤더가 빠진다**(앱 쪽). 영향은 HEAD로 찌르는 감시 도구뿐. **정하면 이 줄을 지운다.**
- **재귀 지표 넷이 백필마다 값이 바뀐다**(2026-08-10 실측). 같은 구간을 두 번 돌렸더니 두 번 다 242,589행이 갱신됐고 전부 `ATR_14`·`RSI_14`·`MACD`·`MACD_V`(각 43~44%)였다. `SMA_20`·`PER`은 0%다 — 씨앗이 `maxEffectiveLookback`에서 잘리는 탓으로 보인다. **`SHARES_GROWTH_3Y`가 그 창을 200 → 750으로 늘렸으므로, 배포 뒤 같은 구간을 두 번 백필해 이 숫자가 줄었는지 먼저 잰다.** 안 줄면 그 지표를 빼는 것이 첫 선택지다(계산기 주석에 근거가 있다).

## 어떤 파일을 열든 알아야 하는 것

파일별 함정은 `.claude/rules/*.md`가 glob으로, 작업별 절차는 skill이 스스로 로드한다. **무엇이 어디 있는지 여기 옮겨 적지 않는다** — 목록은 반드시 낡고, 낡은 목록은 "로드됐다"고 믿게 만든다.

- **phase별 브랜치를 만들지 않는다.** `main`에 직접 쌓는다(2026-08-06). Phase 2 브랜치가 `main`을 4개월 묶어둔 전례가 근거다 — CLAUDE.md가 이 줄을 가리킨다. 브랜치는 **버릴 수 있는 탐색**에만 쓴다.
- **저장소는 `/Users/na1011/dev/stock-screener`에 있다**(2026-08-09에 `~/Desktop`에서 옮겼다, ADR-0034). iCloud 복제와 TCC 차단이 둘 다 원인 단에서 사라졌다.

## 미룬 것 / 알려진 미완성

- **재무 수집이 일일 배치에 없다.** 분기 공시라 매일 조회하면 쿼터만 태운다. 공시 시즌 갱신은 수동 실행 전제다.
- **알림이 아직 로그로만 나간다.** 채널 구현은 붙어 있고 자격증명이 없어 비활성이다 — 기동 로그의 `알림 채널이 하나도 구성되지 않아…`가 그 상태의 표시다(ADR-0025).
- **인터랙션 로그에 리텐션이 없다.** 지인 몇 명 규모에서 수년간 문제가 없어 미뤘다. 필요해지면 `DailyUpdateJob`의 정리 단계에 붙인다.
- **프론트 스택트레이스가 아직 minify된 채다.** SDK와 업로드 배선은 다 되어 있고 org·project 슬러그만 비어 있다(`TODO.md`). 값을 채우면 코드 변경 없이 올라간다.
- **Spring Batch를 쓰는 잡이 없다.** `Job`·`Step`이 없어 `BATCH_*`가 0행이고 `linkJobExecution()`은 죽은 코드다 — ADR-0005의 재시작성을 아무도 안 쓴다. **걷을지 쓸지 정한다.**

## 되돌리지 말 것

**공통점: 지워도 컴파일되고 테스트도 통과하는데 나중에 조용히 망가진다.** 아래 셋만 여기 남기는 이유는 **그 파일을 건드리지 않아도 무너질 수 있어** 그 알림이 걸리지 않기 때문이다.

- **ADR-0005 — `JobRepository` 빈 직접 정의를 지우지 않는다.** 지우면 인메모리로 돌아가 아무것도 기록되지 않고 재시작이 불가능해지는데 **아무 증상이 없다.**
- **ADR-0007 — `rollbackFor = Exception.class`와 `StockTaskRunner` 분리를 유지한다.** Spring 기본은 checked 예외에 커밋하고, 자기 호출은 프록시를 안 거쳐 `REQUIRES_NEW`가 무시된다.
- **ADR-0012 — 활성 유니버스를 0개로 만들지 않는다.** 시총 어댑터가 `@ConditionalOnApiKey`라 **키 없는 환경에서** 시드까지 내리면 하나도 안 남는다(실제로 테스트 7건이 깨졌다). 운영은 시총 둘이 활성이고 시드가 비활성인 것이 정상이며, 테스트 DB는 정반대다.
