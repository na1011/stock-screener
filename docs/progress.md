# 진행 상태

세션이 바뀌어도 남아야 하는 "지금 어디까지 왔는가". 세션 시작 시 훅이 이 파일을 주입한다.

- 요구사항은 [`spec`](./stock-screener-project-spec.md), **phase 완료 판정**은 [`phase-criteria.md`](./phase-criteria.md), 외부 API 실측은 [`api-spec/`](./api-spec/), 되돌리기 어려운 결정은 [`adr/`](./adr/)에 있다. **여기에 옮겨 적지 않는다.**
- 무엇을 했는지는 `git log`에 있다.
- MUST: 상태 주장은 확인 가능한 형태로 쓴다. 낡은 문서를 에이전트는 그대로 믿는다.
- **줄을 더할 때는 뺄 것을 함께 정한다.** 고정 예산이지 로그가 아니다. 경고선·절단선은 `check-doc-staleness.sh`가 알린다.
- **MUST: 한 줄을 여기 둘지는 중요도가 아니라 유도 가능성이 정한다.** 코드로 알 수 있으면 지우고, 특정 파일을 열어야 위반하면 `.claude/rules/`로, 명령을 실행해야 위반하면 hook·skill로 보낸다. 남는 것은 **코드에 흔적이 없어 물어볼 생각조차 못 하는 사실**과 **지금 할 일**뿐이다. 판단 기준 전문은 `.claude/rules/harness.md`에 있다.

## Phase 상태

**1~6 전부 완료.** 판정 기준은 `phase-criteria.md`, 근거는 `docs/adr/`, 무엇을 봤는지는 `git log`가 답한다. 2·3·4는 실데이터로, 5·6은 관통 검증까지 마쳤다(2026-08-08·09).

**아직 없는 것**: 미국 어댑터(v1.1, ADR-0010). *있는* 것과 테스트 개수는 `./gradlew build`와 `git log`가 답한다.

**Phase 6 판정의 "재부팅 후 사람 개입 없이"는 문자 그대로는 미충족이고, 그것이 의도된 상태다.** FileVault가 켜져 있어 콜드 부팅에는 암호 한 번이 필요하다 — LaunchAgent든 LaunchDaemon이든 볼륨이 잠긴 동안에는 못 뜬다(cloudflared도 마찬가지다). 사용자가 암호화를 유지하기로 정했다(2026-08-09). 나머지(잠자기→깨어남·프로세스 죽음·로그아웃→로그인)는 자동이다. 근거와 절차는 ADR-0033에 있다.

**실데이터가 들어 있다** (최신 시세일 2026-08-06). 코드에 흔적이 없는 사실이라 여기 남긴다 — 스크리닝·백필이 실제로 돌아가는 전제이고, 개수는 DB에 물으면 된다.

**허용목록에 지인 계정 하나가 비관리자로 등록돼 있다**(2026-08-09). spec §9가 요구하는 "관리자 외 계정"이 이것이고, 지우면 그 수용 기준이 다시 미충족이 된다.

- **지표 값이 일부 종목에만 있거나 극단값인 것은 대개 정상이다.** PER은 적자 기업에 값을 내지 않고, 4분기 합이 0에 가까우면 수만 배가 나온다. 버그로 단정하기 전에 분기 내역을 본다.

## 다음에 할 일

**v1 구현은 끝났다. 남은 것은 사람이 값을 채우는 일과 그 뒤의 확인뿐이다** — 목록은 [`TODO.md`](../TODO.md)에 있다(알림 채널 자격증명, Sentry org·project 슬러그, ICANN 인증). 발급 상태는 문서가 아니라 `./gradlew checkEnv`에 묻는다 — 발급은 문서 밖에서 일어나 문서가 먼저 낡는다.

- **앱은 떠 있다**(2026-08-09 11:46 재등록, 밖에서 `UP` 실측). 도는 것은 저장소의 `build/libs`가 아니라 `~/Library/Application Support/stock-screener/app.jar`이므로 **코드나 `.env`를 고쳤으면 `ops/deploy.sh`를 돌려야 반영된다** — `./gradlew build`만 하면 옛것이 돌고 화면에는 아무 단서가 없다(ADR-0034). 등록이 풀린 상태에서는 `deploy.sh`가 거부하므로 그때만 `ops/install-agent.sh`다.
- **20시 배치가 실제로 당일 종가를 받아오는지는 아직 못 봤다.** data.go.kr의 공개 시각을 실측하지 않았다. 이르면 수집이 0건으로 끝나고 그 경우 알림이 온다 — **거래일마다 오면 시각을 늦춘다**(ADR-0033).
- **`harness-*.md` 넷의 발화 확인이 2단계 중 1단계만 끝났다**(glob 매칭은 확인, `/clear` 후 발화는 미확인). `core`의 `paths`가 나머지 셋의 합집합이라 단독으로 뜨는 파일이 없다 — **`/clear` 후 Read 3회**로 넷을 다 본다: `docs/progress.md`(core+docs) → `.claude/hooks/guard-spec.sh`(hooks) → `.claude/rules/test.md`(rules). 이미 뜬 규칙은 다시 안 뜨므로 순서를 지킨다.

## 어떤 파일을 열든 알아야 하는 것

파일별 함정은 `.claude/rules/*.md`가 glob으로, 작업별 절차는 skill이 스스로 로드한다. **무엇이 어디 있는지 여기 옮겨 적지 않는다** — 목록은 반드시 낡고, 낡은 목록은 "로드됐다"고 믿게 만든다.

- **phase별 브랜치를 만들지 않는다.** `main`에 직접 쌓는다(2026-08-06). Phase 2 브랜치가 `main`을 4개월 묶어둔 전례가 근거다 — CLAUDE.md가 이 줄을 가리킨다. 브랜치는 **버릴 수 있는 탐색**에만 쓴다.
- **저장소는 `/Users/na1011/dev/stock-screener`에 있다**(2026-08-09에 `~/Desktop`에서 옮겼다, ADR-0034). iCloud 복제와 TCC 차단이 둘 다 원인 단에서 사라졌다.

## 미룬 것 / 알려진 미완성

- **재무 수집이 일일 배치에 없다.** 분기 공시라 매일 조회하면 쿼터만 태운다. 공시 시즌 갱신은 수동 실행 전제다.
- **알림이 아직 로그로만 나간다.** 채널 구현은 붙어 있고 자격증명이 없어 비활성이다 — 기동 로그의 `알림 채널이 하나도 구성되지 않아…`가 그 상태의 표시다(ADR-0025).
- **인터랙션 로그에 리텐션이 없다.** 지인 몇 명 규모에서 수년간 문제가 없어 미뤘다. 필요해지면 `DailyUpdateJob`의 정리 단계에 붙인다.
- **프론트 스택트레이스가 아직 minify된 채다.** SDK와 업로드 배선은 다 되어 있고 org·project 슬러그만 비어 있다(`TODO.md`). 값을 채우면 코드 변경 없이 올라간다.

## 되돌리지 말 것

**공통점: 지워도 컴파일되고 테스트도 통과하는데 나중에 조용히 망가진다.** 지배 ADR은 `remind-adr.sh`가 편집 직후 포인터로 알린다. 아래 셋만 여기 남기는 이유는 **그 파일을 건드리지 않아도 무너질 수 있어** 그 알림이 걸리지 않기 때문이다.

- **ADR-0005 — `JobRepository` 빈 직접 정의를 지우지 않는다.** 지우면 인메모리로 돌아가 아무것도 기록되지 않고 재시작이 불가능해지는데 **아무 증상이 없다.**
- **ADR-0007 — `rollbackFor = Exception.class`와 `StockTaskRunner` 분리를 유지한다.** Spring 기본은 checked 예외에 커밋하고, 자기 호출은 프록시를 안 거쳐 `REQUIRES_NEW`가 무시된다.
- **ADR-0012 — 시드 유니버스(`KOSPI200` 등)를 비활성으로 내리지 않는다.** 시총 어댑터가 `@ConditionalOnApiKey`라 키 없는 환경에서 활성 유니버스가 하나도 남지 않는다(실제로 테스트 7건이 깨졌다).
