# 진행 상태

세션이 바뀌어도 남아야 하는 "지금 어디까지 왔는가". 세션 시작 시 훅이 이 파일을 주입한다.

- 요구사항은 [`spec`](./stock-screener-project-spec.md), **phase 완료 판정**은 [`phase-criteria.md`](./phase-criteria.md), 외부 API 실측은 [`api-spec/`](./api-spec/), 되돌리기 어려운 결정은 [`adr/`](./adr/)에 있다. **여기에 옮겨 적지 않는다.**
- 무엇을 했는지는 `git log`에 있다.
- MUST: 상태 주장은 확인 가능한 형태로 쓴다. 낡은 문서를 에이전트는 그대로 믿는다.
- **줄을 더할 때는 뺄 것을 함께 정한다.** 고정 예산이지 로그가 아니다. 경고선·절단선은 `check-doc-staleness.sh`가 알린다.
- **MUST: 한 줄을 여기 둘지는 중요도가 아니라 유도 가능성이 정한다.** 코드로 알 수 있으면 지우고, 특정 파일을 열어야 위반하면 `.claude/rules/`로, 명령을 실행해야 위반하면 hook·skill로 보낸다. 남는 것은 **코드에 흔적이 없어 물어볼 생각조차 못 하는 사실**과 **지금 할 일**뿐이다. 판단 기준 전문은 `.claude/rules/harness-core.md`에 있다.

- **도는 것은 `build/libs`가 아니다.** 코드·`.env`를 고쳤으면 `ops/deploy.sh`를 돌려야 반영된다 — `build`만 하면 옛것이 돌고 화면에 단서가 없다(ADR-0034).
- **🔴 2026-08-11(화) 20시 배치 뒤에 잰다** — `SELECT max(trade_date) FROM price_daily`. **2026-08-10(월) 실측에서 20시 배치도 20:13 직접 조회도 당일 0건이었다**(api-spec §공개 지연) — **시각을 늦춰도 같다.** 판정은 **그 값이 조회 시점의 전 영업일인가**다. 맞으면 **D+1 확정** → 대상 일자를 전 영업일로 바꾸고 ADR-0033을 개정한다. `2026-08-07`에 멈춰 있으면 D+2 이상이라 다시 잰다. **그 전에 상수를 박지 않는다.**
- **시세 결손은 물어야 보인다.** 0건이어도 배치는 SUCCESS고 이력도 초록이다. 평일인데 빈 날을 찾는다 — `SELECT d::date FROM generate_series(current_date-30,current_date-1,'1d') d WHERE extract(isodow FROM d)<6 AND NOT EXISTS(SELECT 1 FROM price_daily WHERE trade_date=d::date)`. **나온 날은 후보일 뿐이다** — 휴장·미공개와 가르려면 `basDt`로 소스에 직접 묻는다(api-spec §공개 지연). 실측: 08-07은 결손(사흘 방치), 07-17은 휴장이었다. 메우는 길은 **`/admin` 일일 갱신에 대상 일자를 넣는 것뿐**이고 `ROLE_ADMIN` 세션 인증이라 **사람이 한 번 로그인해야 한다.**
- **MUST NOT: 결손이 생길 때마다 조건을 빼서 해결하지 않는다**(2026-08-10 사용자 판단). 개별 판단이 정당해도 **누적은 원본과 다른 물건**이 된다. 막히면 **원자료를 여는 길을 먼저 본다** — `ALTMAN_Z` 0건이 그렇게 풀렸다(ADR-0040).
- **위 관측을 기다리는 동안 할 것은 phase 착수다.** 후보 넷은 ADR-0039 §남은 결손을 여는 길(P8 업종 · P9 수정주가 · P10 전체 재무제표 · P11 모듈 B). **P8이 가장 싸다** — 350콜 1회에 함정 하나(KSIC 자릿수가 3·5로 섞여 앞 2자리로 판정해야 한다)이고, ADR-0039가 가장 얇다고 지목한 Layer 1의 H-02를 되살린다. **착수 전 ① 완료 판정을 `phase-criteria.md`에 적고 ② 업종당 종목 수부터 잰다** — 그 분포가 P8의 성립을 정한다(api-spec §미검증).
- **DART 확장 실측이 끝났다** — 업종·액면분할·합병이 열렸고 상장일은 닫혔다(ADR-0039 §단계 C). **셋 다 조용히 틀리는 함정이 딸려 있어 착수 전 `api-spec` §10을 읽는다.**
- **훅이 조용히 안 도는 자리 셋**(2026-08-10). ① `/compact` 뒤 `SessionStart` 미발화(matcher) ② `SessionEnd` 배달 0건 ③ `guard-destructive.sh`에 `kill` 판정이 없어 `pkill -f java`가 운영 앱을 죽여도 안 막힌다.

## 미룬 것 / 알려진 미완성

- **알림이 메신저 한 채널로만 나간다** — spec §8은 **두 채널 모두**를 요구하는데 `MAIL_*`이 비어 있다. 실린 채널은 기동 로그의 `알림 채널 N개를 구성했다`가 답한다(ADR-0025).
- **`HEAD /`에 Spring Security 응답 헤더가 빠진다** — 영향은 감시 도구뿐이라 미뤘다.
- **Spring Batch를 쓰는 잡이 없다** — ADR-0005의 재시작성을 아무도 안 쓴다(`BATCH_*` 0행, `linkJobExecution()`은 죽은 코드). **걷을지 쓸지 정한다.**

## 되돌리지 말 것

**공통점: 지워도 컴파일되고 테스트도 통과하는데 나중에 조용히 망가진다.** 아래 셋만 여기 남기는 이유는 **그 파일을 건드리지 않아도 무너질 수 있어** 그 알림이 걸리지 않기 때문이다.

- **ADR-0005 — `JobRepository` 빈 직접 정의를 지우지 않는다.** 지우면 인메모리로 돌아가 아무것도 기록되지 않고 재시작이 불가능해지는데 **아무 증상이 없다.**
- **ADR-0007 — `rollbackFor = Exception.class`와 `StockTaskRunner` 분리를 유지한다.** Spring 기본은 checked 예외에 커밋하고, 자기 호출은 프록시를 안 거쳐 `REQUIRES_NEW`가 무시된다.
- **ADR-0012 — 활성 유니버스를 0개로 만들지 않는다.** 시총 어댑터가 `@ConditionalOnApiKey`라 **키 없는 환경에서** 시드까지 내리면 하나도 안 남는다(실제로 테스트 7건이 깨졌다). 운영은 시총 둘이 활성이고 시드가 비활성인 것이 정상이며, 테스트 DB는 정반대다.
