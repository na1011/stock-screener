# 진행 상태

세션이 바뀌어도 남아야 하는 "지금 어디까지 왔는가". 세션 시작 시 훅이 이 파일을 주입한다.

- 요구사항은 [`spec`](./stock-screener-project-spec.md), 설계와 **phase 완료 판정**은 [`design/v1-architecture.md`](./design/v1-architecture.md), 외부 API 실측은 [`api-spec/`](./api-spec/), 되돌리기 어려운 결정은 [`adr/`](./adr/)에 있다. **여기에 옮겨 적지 않는다.**
- 무엇을 했는지는 `git log`에 있다.
- MUST: 상태 주장은 확인 가능한 형태로 쓴다. 낡은 문서를 에이전트는 그대로 믿는다.
- **줄을 더할 때는 뺄 것을 함께 정한다.** 고정 예산이지 로그가 아니다. 경고선·절단선은 `check-doc-staleness.sh`가 알린다.
- **MUST: 한 줄을 여기 둘지는 중요도가 아니라 유도 가능성이 정한다.** 코드로 알 수 있으면 지우고, 특정 파일을 열어야 위반하면 `.claude/rules/`로, 명령을 실행해야 위반하면 hook·skill로 보낸다. 남는 것은 **코드에 흔적이 없어 물어볼 생각조차 못 하는 사실**과 **지금 할 일**뿐이다. 판단 기준 전문은 `.claude/rules/harness.md`에 있다.

## 어떤 파일을 열든 알아야 하는 것

파일별 함정은 `.claude/rules/*.md`가 glob으로, 작업별 절차는 skill이 스스로 로드한다. **무엇이 어디 있는지 여기 옮겨 적지 않는다** — 목록은 반드시 낡고, 낡은 목록은 "로드됐다"고 믿게 만든다.

- **phase별 브랜치를 만들지 않는다.** `main`에 직접 쌓는다(2026-08-06). Phase 2 브랜치가 `main`을 4개월 묶어둔 전례가 근거다. 브랜치는 **버릴 수 있는 탐색**에만 쓴다.
- **`git add -A`를 쓰지 않는다.** `1873cf3`이 macOS 복제본 42개를 담아 컴파일이 멈췄다.
- **IMPORTANT — iCloud가 `build/` 산출물도 복제한다.** 증상은 테스트의 `Could not execute test class 'X 2' (wrong name: X)`와 **수 분간의 멈춤**(Gradle이 파일 해싱에서 대기한다). 처방은 `./gradlew clean`이고, `checkDuplicateFiles`가 `src`(삭제)와 `build`(clean)를 나눠 먼저 잡는다. **원격 편집 파일이 즉시 안 보이는 것도 같은 원인이다 — 없다고 단정하기 전에 몇 분 뒤 다시 본다.**

## 미룬 것 / 알려진 미완성

- **`https://screener.na1011.net`이 살아 있다** (2026-08-07, `curl -I` → 200). 도메인·Tunnel 완료. 정본은 [`external-credentials.md`](./external-credentials.md).
- **IMPORTANT — 그런데 도메인 로그인은 안 된다. OAuth 클라이언트가 `데스크톱` 유형으로 발급됐다.** 그 유형에는 리디렉션 URI 칸이 없고 유형은 변경 불가라 **`웹 애플리케이션`으로 새로 만들어야 한다**([`TODO.md`](../TODO.md) §3 ③ 3-1). **loopback은 등록 없이 통과해 `localhost:8080` 로그인은 멀쩡하다** — 그래서 이 결함은 도메인을 붙이기 전까지 어떤 테스트에도 잡히지 않았다.
- **재무 수집이 일일 배치에 없다.** 분기 공시라 매일 조회하면 쿼터만 태운다. 공시 시즌 갱신은 수동 실행 전제다.
- **워치리스트가 통째로 Phase 6이다.** 이음매는 이미 있다.
- **배치 잡의 HTTP 진입점이 없다 — Phase 6.** `SecurityConfigTest`가 그 404를 단언하고 있어 **함께** 고쳐야 한다.
- **actuator 미도입**: Phase 6.
- **IMPORTANT — 프론트 Sentry는 키 이름만 준비됐다.** `.env.example`에 `VITE_SENTRY_DSN`이 있고 `checkEnv`가 누락을 잡지만, **Vite의 `envDir`이 `frontend/`라 루트 `.env`를 읽지 않는다.** `applyDotEnv`를 `frontendBuild`에도 걸어야 값이 번들에 들어간다(TODO §3 ④ 4-6). 지금 프론트 오류는 `console.error`에만 남는다.

## 되돌리지 말 것

**공통점: 지워도 컴파일되고 테스트도 통과하는데 나중에 조용히 망가진다.** 지배 ADR은 `remind-adr.sh`가 편집 직후 포인터로 알린다. 아래 셋만 여기 남기는 이유는 **그 파일을 건드리지 않아도 무너질 수 있어** 그 알림이 걸리지 않기 때문이다.

- **ADR-0005 — `JobRepository` 빈 직접 정의를 지우지 않는다.** 지우면 인메모리로 돌아가 아무것도 기록되지 않고 재시작이 불가능해지는데 **아무 증상이 없다.**
- **ADR-0007 — `rollbackFor = Exception.class`와 `StockTaskRunner` 분리를 유지한다.** Spring 기본은 checked 예외에 커밋하고, 자기 호출은 프록시를 안 거쳐 `REQUIRES_NEW`가 무시된다.
- **ADR-0012 — 시드 유니버스(`KOSPI200` 등)를 비활성으로 내리지 않는다.** 시총 어댑터가 `@ConditionalOnApiKey`라 키 없는 환경에서 활성 유니버스가 하나도 남지 않는다(실제로 테스트 7건이 깨졌다).
