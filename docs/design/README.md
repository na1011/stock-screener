# 설계 문서

이 디렉터리는 phase별 설계 방향을 담는다. 기획 정본(`../stock-screener-project-spec.md`)이 "무엇을 만드는가"를 정하고, 여기서는 "무엇을 향해 설계하는가"를 다룬다.

## 이 문서들이 하지 않는 것

**구현 명세가 아니다.** 클래스명·필드 목록·DDL·메서드 시그니처를 지정하지 않는다. `.claude/rules/harness.md`의 원칙 — 자율성은 규칙의 부재로 구현하고, 아키텍처와 구현 방식은 작업 시점 에이전트가 판단한다 — 이 여기에도 적용된다.

고정하는 것은 두 가지뿐이다.

1. **검증된 외부 사실** — 틀리면 런타임에 깨지거나 시간을 잃는 것. 판단의 여지가 없다.
2. **spec에서 유도된 방향** — spec과 `.claude/rules/`가 이미 요구하는 것. 협상 대상이 아니다.

그 사이의 설계 판단은 실행 에이전트가 내린다. "고려할 사항" 절은 **이미 검토된 논점과 인과관계**를 전달하는 것이지 결론을 강제하는 것이 아니다. 같은 논점을 다시 발견하느라 시간을 쓰지 않도록 남기되, 다르게 판단할 근거가 있으면 다르게 판단하고 ADR에 남기면 된다.

## 로드 방식

이 문서들은 자동 로드되지 않는다. `../progress.md`가 현재 phase의 설계 문서를 가리키고, 필요할 때 읽는다.

무조건 로드하지 않는 이유는 컨텍스트 비용이다. 항상 로드되는 문서가 길어지면 그 자체로 비용이고 주변 규칙의 준수율까지 떨어진다. 반면 결정의 근거는 `../adr/`에 `applies_to` 조건부 로드로 남으므로, 정말 필요한 순간에는 그쪽이 걸린다.

## 목록

`ls docs/design/`으로 확인한다. 수동 목록은 반드시 낡으므로 두지 않는다.
